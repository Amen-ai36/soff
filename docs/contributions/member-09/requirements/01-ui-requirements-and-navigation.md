# 用户界面需求与导航需求（成员 9，方案 B）

状态：成员 9 方案 B 贡献草案。`UI9-*` 是局部追踪编号，待成员 1/6 汇编后映射到统一 SRS。本文基于问卷数据（50 份，证据编号 E-B-Q-001）和用户旅程材料编写。

## 1. 方案 B 的设计取向

方案 B 采用"场景平衡"取向：既重视检索效率，也强调领域浏览、统计分析和学者门户的平等入口地位。该取向基于问卷发现：

- **证据 B-E01**：68% 用户使用检索作为主要入口，但 52% 同时使用领域浏览（Q2）
- **证据 B-E02**：74% 用户关注机构排名和领域分布统计（Q6）
- **证据 B-E03**：82% 用户期望学者门户提供研究网络和合作关系（Q8）

方案 B 与方案 A 的主要差异：

| 维度 | 方案 A（成员 4） | 方案 B（成员 9） |
|------|----------------|----------------|
| 首页入口 | 检索优先，领域浏览为次级 | 检索、领域、统计并列 |
| 学者门户 | 成果列表优先 | 研究网络与成果并重 |
| 统计分析 | 次要展示入口 | 主导航一级入口 |
| 信息密度 | 简洁优先 | 上下文丰富优先 |

## 2. 角色与权限边界

沿用成员 4 的角色定义，不重复列举。补充方案 B 的权限展示建议：

| 角色 | 方案 B 额外强调 |
|------|----------------|
| 访客 | 统计页面应显示数据口径和更新时间，避免误读 |
| 登录用户 | 认领入口在详情页和门户页均可见（90% 用户期望，Q10） |
| 已认领学者 | 门户维护应支持合作者关联（如纳入创新功能） |

## 5. 导航需求

| 编号 | 要求 | 验证方式 | 证据来源 |
|------|------|---------|---------|
| UI9-FR-01 | 全局导航应平等展示成果、学者、领域和统计入口；当前栏目高亮 | 页面走查 | 问卷 Q2、Q6 |
| UI9-FR-02 | 首页应提供检索、领域浏览、统计分析三个平等入口，不隐藏次级入口 | 原型任务测试 | 问卷 Q2（52% 使用领域浏览） |
| UI9-FR-03 | 面包屑导航应显示完整路径（领域层级、检索条件、门户关联） | 页面走查 | 用户旅程 J-B-03 |
| UI9-FR-04 | 学者门户应提供"研究方向""成果列表""合作网络"Tab 切换 | 原型任务测试 | 问卷 Q8（82% 关注合作关系） |
| UI9-FR-05 | 统计页面应在主导航一级可见，不作为隐藏入口 | 页面走查 | 问卷 Q6（74% 关注统计） |
| UI9-FR-06 | 移动端应保留核心导航，可折叠次级菜单 | 360x800 视口测试 | 问卷 Q13（56% 使用移动端） |

## 6. 首页布局（方案 B 特色）

### 6.1 布局结构

```text
[Logo]          [导航：成果 | 学者 | 领域 | 统计]     [登录/个人]

+----------------------------------------------------------+
|                      检索入口                              |
|   [成果 / 学者]  [_______________搜索框_______________] [搜索]  |
|   [高级检索]                                              |
+----------------------------------------------------------+

+------------------------+  +---------------------------+
|     领域浏览入口        |  |      统计概览入口           |
|  [计算机科学]           |  |  机构排名 Top 10           |
|  [生物医学]             |  |  领域分布图表              |
|  [工程技术]             |  |  年度成果趋势              |
|  ...                   |  |  [查看完整统计 →]          |
+------------------------+  +---------------------------+

+----------------------------------------------------------+
|                    最新成果 / 热门学者                      |
+----------------------------------------------------------+
```

### 6.2 首页交互

- **证据 B-E04**：68% 用户任务起点是关键词检索（Q2），因此搜索框保持首屏核心位置
- **证据 B-E05**：52% 用户使用领域浏览（Q2），因此领域入口不能作为三级菜单
- **证据 B-E06**：74% 用户关注统计（Q6），因此首页展示统计概览卡片

## 7. 全局页面状态

沿用成员 4 的状态定义。方案 B 补充：

| 状态 | 方案 B 额外要求 |
|------|---------------|
| 初始 | 首页应展示三入口示例，不只展示检索示例 |
| 业务空结果 | 除修改关键词外，应推荐相关领域或统计入口 |
| 部分数据缺失 | 统计页面应明确标注"未知类"占比（如 Q6 关注数据完整性） |

## 8. 响应式设计

| 视口 | 布局调整 | 优先级 |
|------|---------|-------|
| 桌面（≥1366px） | 三入口并列，统计卡片展开 | P0 |
| 平板（768-1365px） | 三入口垂直堆叠，统计卡片简化 | P1 |
| 移动端（<768px） | 检索优先，领域和统计折叠到汉堡菜单 | P1，问卷显示 56% 使用移动端 |

**证据 B-E07**：56% 用户使用移动端访问（Q13），但桌面仍是主要场景（68%），因此移动端作为 P1。

## 9. 可访问性基线

| 编号 | 要求 | WCAG 2.1 等级 |
|------|------|--------------|
| UI9-A11Y-01 | 所有交互控件支持键盘操作 | A |
| UI9-A11Y-02 | 焦点顺序与视觉顺序一致 | A |
| UI9-A11Y-03 | 图表提供文本替代（数据表格） | A |
| UI9-A11Y-04 | 普通文字对比度 ≥ 4.5:1 | AA |
| UI9-A11Y-05 | 表单字段有可读标签 | A |

## 11. 与成员 4 的协同

- **共同基线**：角色权限、页面状态、可访问性要求
