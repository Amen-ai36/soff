# SPEC-M9-PORTAL-CLAIM-UI：门户、认领申请与门户维护界面 v0.1

关联：UI9-FR-31～38；IA9-SEQ-05～08；IA9-RULE-10～12；FS9-A-*、FS9-B-*、FS9-BR-01～04；EX9-C3、C4；SPEC-M8-CLAIM、SPEC-M8-AUTH；契约假设 A-09、A-10、A-12、A-16～18。状态：候选规范。

认领规则、状态枚举与授权由成员 3、8 定义；本规范只规定界面行为。真实问卷样本中没有教师和科研人员（Q1：本科生 32/35、硕士 3/35），本规范不引用问卷数据。

## 1. 目标与范围

| 在范围内 | 不在范围内 |
| --- | --- |
| 学者门户公开页及其认领入口 | 身份核验标准（待成员 1、6 与老师确认） |
| 三步认领申请表单 | 证明材料文件上传与存储（成员 8 提案第 5 节待定） |
| "我的认领"列表 | 撤回申请（成员 8：不默认具有） |
| 门户维护：个人公开字段、成果展示的隐藏与恢复（支持批量） | 修改成果题名、作者等共享元数据（走治理流程） |

## 2. 门户入口判定

`domain/portalEntry.ts` 根据四个输入给出唯一入口：

| 登录 | 本人已获该门户维护授权 | 本人对该门户有审核中申请 | 门户状态 | 入口 |
| --- | --- | --- | --- | --- |
| 否 | — | — | 未认领 | 登录后申请认领 |
| 否 | — | — | 已认领 | 无入口，显示"该门户已被认领" |
| 是 | 是 | — | — | 维护门户 |
| 是 | 否 | 是 | 任意 | 查看申请进度 |
| 是 | 否 | 否 | 未认领 | 申请认领 |
| 是 | 否 | 否 | 已认领 | 无入口，显示"该门户已被认领" |

门户状态文字：

| 状态 | 文字 | 依据 |
| --- | --- | --- |
| 未认领 | "未认领：门户信息由平台整理，未经本人确认" | IA9-RULE-10 |
| 已认领 | "已认领：认领关系已审核通过，不代表平台为全部成果背书" | IA9-RULE-11 |

门户成果按四类分标签显示，标签写入 URL（`?type=paper`）；某类为空时显示"暂无论文"等，不显示加载失败。

## 3. 认领申请表单

### 3.1 进入条件

| 条件 | 界面 |
| --- | --- |
| 未登录 | 路由守卫跳转登录页，登录后回到本页（回跳地址只接受站内路径） |
| 门户已认领 | "该门户已被认领，无法申请"，不显示表单 |
| 本人已有该门户的审核中申请 | "你已提交过申请"并链接到"我的认领"，不显示表单 |

### 3.2 三步与校验

| 步骤 | 字段 | 规则 | 错误文案 |
| --- | --- | --- | --- |
| 1 关系说明 | `statement` | 去首尾空白后 1～500 字 | 请填写你与该学者的关系；关系说明不能超过 500 字 |
| 2 证明材料 | `homepageUrl` | 可空；非空时须为 `http://` 或 `https://` 开头且无空白 | 请输入以 http:// 或 https:// 开头的链接 |
| 2 证明材料 | `institutionEmail` | 可空；非空时须为邮箱格式 | 请输入有效的邮箱地址 |
| 2 证明材料 | 两者 | 至少填写一项 | 请至少提供一项证明材料（错误挂在 `homepageUrl`） |
| 3 确认 | `consent` | 必须勾选 | 请确认信息真实并同意用于审核 |

- "下一步"只校验当前步；不通过时焦点移到本步第一个出错字段。
- "上一步"保留已填内容。
- 草稿不写入浏览器存储（FS9-Q01 未确认，且含证明材料）。
- 邮箱不限制域名：机构邮箱白名单待成员 3、8 确认。
- 提交时 `evidence_refs` 为 `url:<链接>`、`email:<邮箱>`（假设 A-17）。

### 3.3 幂等键

同一表单实例、同一份内容使用同一个 `request_key`；内容变化后生成新键。因此网络中断后不改内容直接重试，服务端返回已有申请，不会出现两个申请（成员 8 提案第 3 节）。

### 3.4 提交结果

| 结果 | 界面 |
| --- | --- |
| 成功 | 显示申请编号、提交时间、"审核中"，并写明"审核通过前你还不能维护该门户"（IA9-RULE-12） |
| `INVALID_INPUT` | 字段错误回到对应步骤（`statement` 回步骤 1，`evidence_refs` 回步骤 2） |
| `CONFLICT` | "已有审核中的申请，或该门户已被认领"；重新读取"我的认领"与门户状态 |
| `UNAUTHENTICATED` | 跳转登录 |
| `NETWORK`、`TIMEOUT` | "提交是否成功尚未确认。可以直接重试，不会重复创建申请；也可以先到“我的认领”查看。"（EX9-R-06） |
| 其他 | 按错误种类显示文案与追踪编号 |

## 4. 我的认领

| 状态 | 文字 | 说明 | 操作 |
| --- | --- | --- | --- |
| `PENDING` | 审核中 | 审核通过前不能维护门户 | 无 |
| `APPROVED` | 已通过 | 可维护该门户允许修改的内容 | 维护门户 |
| `REJECTED` | 已驳回 | 显示驳回理由；理由缺失时写"驳回理由未提供" | 重新申请（新申请，旧记录保留） |

状态同时用文字表达，不只靠颜色。列表按提交时间倒序；有前序申请时显示其编号。

## 5. 门户维护

| 项 | 规则 |
| --- | --- |
| 访问 | 服务端返回 403 或 404 时显示"无访问权限"，二者文案相同（EX9-R-03） |
| 个人公开字段 | `bio` 不超过 1000 字；`homepage` 可空，非空时规则同 3.2 |
| 并发 | 保存携带 `expected_version`；409 时提示"记录已被更新"，重新读取最新版本，**保留用户未保存的输入**，由用户确认后再保存，不自动重试 |
| 批量隐藏/恢复 | 勾选后先显示确认："将隐藏 N 项。隐藏只影响你的门户展示，不删除成果，也不影响其他作者。"；完成后显示实际变化条数 |
| 共享元数据 | 不提供编辑；说明纠错流程待团队确认 |
