## 4. 视觉规范

### 4.1 颜色

颜色定义在 `frontend/src/styles/tokens.ts`，并与 `main.css` 中的 CSS 变量一一对应（测试检查两者一致）。

| 用途 | 颜色 | 与背景的对比度 |
| --- | --- | --- |
| 正文 | `#1f2933` | 14.76（白底）/ 13.75（浅灰底） |
| 次要文字 | `#52606d` | 6.46 / 6.02 |
| 主色（链接、主按钮） | `#1d4ed8` | 6.70；主按钮白字 6.70 |
| 错误 | `#b42318` | 6.57 |
| 警告文字 / 底 | `#8a4b00` / `#fff7e6` | 6.38 |
| 模拟数据标记 文字 / 底 | `#5b21b6` / `#ede9fe` | 7.57 |
| 成功文字 / 底 | `#166534` / `#dcfce7` | 6.49 |
| 输入框边框 | `#7b8794` | 3.66 / 3.41 |

正文组合最低 6.02，超过 WCAG AA 的 4.5；边框最低 3.41，超过非文字元素的 3。数值由 `npm test` 中的对比度测试按 WCAG 2.x 相对亮度公式计算。

### 4.2 排版与间距

| 项 | 规范 |
| --- | --- |
| 字体 | Microsoft YaHei、PingFang SC、Noto Sans CJK SC，回退系统字体 |
| 字号 | 正文 16px；标题 1.6rem / 1.25rem / 1.05rem；辅助文字 0.875rem |
| 间距 | 4、8、16、24、32px 五档（`--space-1`～`--space-5`） |
| 内容宽度 | 最大 1080px，居中 |
| 控件高度 | 最小 40px；窄屏 44px |
| 圆角 | 6px |

### 4.3 状态表达

状态一律同时用文字表达，颜色只作辅助：

| 状态 | 表达 |
| --- | --- |
| 模拟数据 | 紫底标签"模拟数据" |
| 认领状态 | 标签文字"审核中 / 已通过 / 已驳回"，并附一句说明 |
| 错误 | 红色左边框 + 粗体错误文案 + 追踪编号 |
| 字段错误 | 字段下方红字，字段设置 `aria-invalid` 并用 `aria-describedby` 关联 |
| 焦点 | 3px 主色外框 |

### 4.4 窄屏

断点 767px。窄屏时筛选面板与结果单列排列，筛选项横向排列以缩短面板；不改变元素顺序，保证视觉顺序与键盘顺序一致。

## 5. 关键交互设计

以下交互在 SPEC 中有完整规则，这里列出设计取舍：

| 交互 | 设计 | 取舍 |
| --- | --- | --- |
| 改筛选 | 勾选即生效，年份需点"应用" | 复选框即时生效减少操作；年份是自由输入，即时生效会在输入中途触发校验错误 |
| 无匹配与失败 | 两种文案、两种样式，互不出现 | 把失败显示成"0 条"会让用户误以为确实没有数据（EX9-R-01） |
| 翻页时数据更新 | 提示"翻页结果可能重复或遗漏"，不自动跳回第 1 页 | 不打断用户正在看的内容，由用户决定 |
| 认领提交中断 | 提示"提交是否成功尚未确认，可以直接重试" | 同一内容复用同一幂等键，重试不会产生第二个申请 |
| 维护冲突 | 保留未保存的输入，载入最新版本，由用户确认后再保存 | 自动重试会覆盖他人修改 |
| 审核决定 | 二次确认；通过时说明"申请人将获得维护权限" | 审核结果不可撤销 |
| 批量隐藏 | 确认文字说明"不删除成果，也不影响其他作者"；完成后显示实际变化条数 | 防止误以为删除了成果 |
