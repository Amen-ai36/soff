## 1. 本文范围

### 1.1 前端状态与业务状态的区别

这是本文最重要的边界声明：

| 维度 | 前端状态 | 业务状态 |
| --- | --- | --- |
| 定义者 | 成员 4、9 | 成员 3、8 |
| 存在位置 | 浏览器内存、URL、本地存储 | 服务端数据库 |
| 示例 | 加载中、已展开、焦点所在、草稿未提交 | `PENDING`、`APPROVED`、`REJECTED` |
| 权威性 | 不具权威性，刷新可重建 | 权威，界面须以其为准 |
| 本文范围 | 是 | 否，仅引用 |

**核心规则**：前端状态不得覆盖或推测业务状态。当两者不一致时，以服务端返回为准并提示用户。

## 2. 全局状态分类

### 2.1 五类前端状态

| 类别 | 编号前缀 | 含义 | 持久性 |
| --- | --- | --- | --- |
| 数据加载状态 | `FS9-L-*` | 数据请求的生命周期 | 会话内，刷新重建 |
| 用户输入状态 | `FS9-I-*` | 表单与控件的输入过程 | 可本地暂存 |
| 视图呈现状态 | `FS9-V-*` | 展开/折叠、标签切换、布局模式 | 可本地记忆 |
| 会话权限状态 | `FS9-A-*` | 登录态与可见能力 | 由服务端会话决定 |
| 业务映射状态 | `FS9-B-*` | 业务状态在界面上的呈现 | 只读映射，不本地推断 |

### 2.2 状态优先级

同一区域出现多个状态时，按以下优先级呈现，避免矛盾反馈：

```text
会话权限状态（无权限）
  > 数据加载状态（失败）
  > 数据加载状态（加载中）
  > 业务映射状态
  > 视图呈现状态
  > 用户输入状态
```

**例**：用户无权访问某申请详情时，显示无权限提示，不显示加载动画，也不显示任何业务状态。

## 3. 数据加载状态模型

### 3.1 状态机

```text
                    ┌──────────┐
                    │  空闲    │ FS9-L-IDLE
                    └────┬─────┘
                         │ 触发请求
                         ▼
                    ┌──────────┐
            ┌───────│  加载中  │ FS9-L-LOADING
            │       └────┬─────┘
            │            │
            │    ┌───────┼───────┬──────────┐
            │    ▼       ▼       ▼          ▼
            │ ┌──────┐┌──────┐┌──────┐┌────────┐
            │ │有数据││业务空││依赖失││无权限  │
            │ └──┬───┘└──┬───┘│  败  ││        │
            │    │       │    └──┬───┘└───┬────┘
            │ FS9-L-   FS9-L-  FS9-L-   FS9-A-
            │ SUCCESS  EMPTY   ERROR    DENIED
            │    │       │       │         │
            │    │       │       │ 重试    │
            └────┴───────┴───────┘         │
                 │                          │
                 ▼ 条件变化                 ▼ 登录
            重新进入加载中              重新进入加载中
```

### 3.2 状态定义

| 编号 | 状态 | 触发条件 | 界面表现 | 禁止 |
| --- | --- | --- | --- | --- |
| `FS9-L-IDLE` | 空闲 | 页面初次进入，未发起请求 | 显示任务入口与必要示例 | 不显示"0 条结果" |
| `FS9-L-LOADING` | 加载中 | 请求已发出未返回 | 保持框架稳定，标识处理中 | 不允许同一提交重复触发 |
| `FS9-L-SUCCESS` | 有数据 | 返回非空结果 | 显示结果、条件、数据版本 | 不隐藏当前筛选条件 |
| `FS9-L-EMPTY` | 业务空 | 返回成功但无匹配 | 明确无匹配，提供改词与清筛选 | 不写成服务异常 |
| `FS9-L-ERROR` | 依赖失败 | 请求失败或超时 | 可识别错误、重试入口、追踪标识 | 不伪装成 `total=0` |
| `FS9-L-STALE` | 版本失效 | 分页时数据已更新 | 提示重新查询 | 不混用旧分页结果 |

### 3.3 关键转换规则

| 编号 | 规则 | 依据 |
| --- | --- | --- |
| `FS9-LR-01` | `LOADING` 超过 300ms 才显示加载指示，避免闪烁 | `UI9-NFR-08` |
| `FS9-LR-02` | `LOADING` 超过 10 秒转入 `ERROR`，提示超时 | `UI9-NFR-03` |
| `FS9-LR-03` | `EMPTY` 与 `ERROR` 必须使用不同视觉与文案，不可互相替代 | `UI9-FR-15`、`UI9-AC-04`、`UI9-AC-05` |
| `FS9-LR-04` | 从 `ERROR` 重试时保留原请求条件，不清空用户输入 | `UI9-NFR-07` |
| `FS9-LR-05` | `STALE` 时保留用户已见内容，提供"用原条件重新查询"，不自动跳转 | `UI9-NFR-10` |

### 3.4 并发请求处理

| 场景 | 处理规则 |
| --- | --- |
| 用户连续改变筛选条件 | 取消前序请求，只渲染最后一次结果 |
| 用户在加载中切换排序 | 取消前序请求，新请求回到第 1 页 |
| 用户在加载中重复提交同一表单 | 忽略重复提交，不产生第二次请求 |
| 两个独立区域同时加载 | 各自独立显示加载态，不互相阻塞 |

## 4. 用户输入状态模型

### 4.1 字段级状态机

```text
    ┌──────────┐
    │  未触碰  │ FS9-I-PRISTINE
    └────┬─────┘
         │ 聚焦
         ▼
    ┌──────────┐
    │  编辑中  │ FS9-I-EDITING
    └────┬─────┘
         │ 失焦
         ▼
    ┌──────────┐      ┌──────────┐
    │  校验中  │─────▶│  有效    │ FS9-I-VALID
    └────┬─────┘      └──────────┘
         │
         ▼
    ┌──────────┐
    │  无效    │ FS9-I-INVALID
    └────┬─────┘
         │ 修改
         ▼
      回到编辑中
```

### 4.2 状态定义

| 编号 | 状态 | 界面表现 | 校验时机 |
| --- | --- | --- | --- |
| `FS9-I-PRISTINE` | 未触碰 | 默认样式，不显示错误 | 不校验 |
| `FS9-I-EDITING` | 编辑中 | 边框高亮 | 不实时报错，避免打断输入 |
| `FS9-I-VALIDATING` | 校验中 | 显示校验进行标识 | 异步校验（如唯一性） |
| `FS9-I-VALID` | 有效 | 可显示通过标识 | 失焦后 |
| `FS9-I-INVALID` | 无效 | 字段级错误信息 | 失焦后或提交时 |

### 4.3 表单级状态机

```text
    ┌──────────┐
    │  空表单  │ FS9-I-FORM-EMPTY
    └────┬─────┘
         │ 开始填写
         ▼
    ┌──────────┐
    │  草稿    │ FS9-I-FORM-DRAFT ──┐
    └────┬─────┘                    │ 本地暂存
         │ 全部字段有效              │
         ▼                          ▼
    ┌──────────┐              ┌──────────┐
    │  可提交  │              │ 可恢复   │
    └────┬─────┘              └──────────┘
         │ 提交
         ▼
    ┌──────────┐
    │  提交中  │ FS9-I-FORM-SUBMITTING
    └────┬─────┘
         │
    ┌────┼────┐
    ▼         ▼
┌────────┐┌────────┐
│已提交  ││提交失败│ FS9-I-FORM-FAILED
└────────┘└───┬────┘
              │ 保留非敏感输入
              ▼
           回到可提交
```

### 4.4 关键转换规则

| 编号 | 规则 | 依据 |
| --- | --- | --- |
| `FS9-IR-01` | 编辑中不实时报错，失焦后才校验，避免输入过程被打断 | `UI9-NFR-07` |
| `FS9-IR-02` | 提交失败后保留非敏感输入；证明材料等敏感内容按安全规则处理 | `UI9-NFR-07`、`UI9-NFR-17` |
| `FS9-IR-03` | 提交中禁用提交按钮，防止重复创建 | `UI9-NFR-03` |
| `FS9-IR-04` | 草稿仅存本地，不上传服务端；会话过期后清除敏感字段 | `UI9-NFR-17` |
| `FS9-IR-05` | 多步表单中"上一步"不丢失已填内容 | `UI9-FR-32` |

### 4.5 多步表单的状态保持

认领流程为三步（`IA9-SEQ-06`），状态保持要求：

| 步骤 | 前进时 | 后退时 | 离开页面时 |
| --- | --- | --- | --- |
| 步骤 1 关系说明 | 校验后保存到流程状态 | 恢复已填内容 | 可本地暂存（非敏感） |
| 步骤 2 证明材料 | 校验后保存引用 | 恢复已选项 | 敏感材料不本地暂存 |
| 步骤 3 确认提交 | 提交 | 恢复步骤 2 | 不暂存 |

**待确认**：`FS9-Q01`（草稿本地暂存的保留时长与清除时机）。涉及隐私，需成员 1、6 与安全要求确认。

## 5. 视图呈现状态模型

### 5.1 状态清单

| 编号 | 状态 | 可选值 | 记忆范围 |
| --- | --- | --- | --- |
| `FS9-V-FILTER` | 筛选器面板 | 展开 / 折叠 | 本地记忆 |
| `FS9-V-TAB` | 成果类型标签 | 全部 / 论文 / 专利 / 项目 / 获奖 | URL 同步 |
| `FS9-V-AUTHORS` | 作者列表 | 折叠 / 展开 | 当前页面 |

| `FS9-V-SORT` | 排序方式 | 相关度 / 时间降 / 时间升 | URL 同步 |
| `FS9-V-PAGE` | 分页位置 | 页码 | URL 同步 |
| `FS9-V-VIEWPORT` | 视口模式 | 桌面 / 平板 / 移动 | 运行时检测 |

### 5.2 URL 同步规则

可分享、可后退的状态必须进入 URL：

| 状态 | 是否入 URL | 理由 |
| --- | --- | --- |
| 检索关键词 | 是 | 用户需要分享检索结果 |
| 筛选条件 | 是 | 后退时需恢复 |
| 排序方式 | 是 | 后退时需恢复 |
| 分页位置 | 是 | 后退时需恢复 |
| 成果类型标签 | 是 | 可分享具体分组 |
| 筛选器展开/折叠 | 否 | 个人偏好，不影响内容 |
| 作者/摘要展开 | 否 | 页面内临时状态 |

**规则 `FS9-VR-01`**：URL 承载的状态在后退、前进、刷新后必须完整恢复（`UI9-NFR-10`）。

### 5.3 视口切换的状态保持

| 从 | 到 | 保持 | 调整 |
| --- | --- | --- | --- |
| 桌面 | 移动 | 检索条件、排序、分页 | 筛选器转为抽屉，导航折叠 |
| 移动 | 桌面 | 同上 | 筛选器展开为侧栏，导航展开 |

**规则 `FS9-VR-02`**：视口变化不得丢失用户已输入内容与已设条件。

## 6. 会话权限状态模型

### 6.1 状态机

```text
    ┌──────────┐
    │  访客    │ FS9-A-GUEST
    └────┬─────┘
         │ 登录成功
         ▼
    ┌──────────┐
    │ 已登录   │ FS9-A-AUTHED
    └────┬─────┘
         │ 认领通过
         ▼
    ┌──────────┐
    │已授权学者│ FS9-A-SCHOLAR（针对特定门户）
    └──────────┘

    任意状态 ──会话过期──▶ FS9-A-EXPIRED ──▶ 回到访客
```

### 6.2 状态定义

| 编号 | 状态 | 可见能力 | 界面表现 |
| --- | --- | --- | --- |
| `FS9-A-GUEST` | 访客 | 检索、浏览、查看公开门户与统计 | 认领入口触发登录引导 |
| `FS9-A-AUTHED` | 已登录 | 继承访客能力，提交与查看本人申请 | 显示个人入口 |
| `FS9-A-SCHOLAR` | 已授权学者 | 维护特定授权门户 | 该门户显示维护入口 |
| `FS9-A-DENIED` | 无权限 | 无 | 说明需登录或无访问权 |
| `FS9-A-EXPIRED` | 会话过期 | 无 | 提示重新登录并保留当前上下文 |

### 6.3 关键规则

| 编号 | 规则 | 依据 |
| --- | --- | --- |
| `FS9-AR-01` | 前端隐藏按钮不得替代服务端授权校验 | `UI9-NFR-15` |
| `FS9-AR-02` | `FS9-A-DENIED` 的提示不得泄露受限记录或材料是否存在 | `UI9-NFR-14` |
| `FS9-AR-03` | 会话过期时保留当前任务上下文，登录后恢复，不丢失用户意图 | `IA9-SEQ-06` |
| `FS9-AR-04` | 会话过期时清除本地敏感草稿（证明材料、审核决定） | `UI9-NFR-17` |
| `FS9-AR-05` | `FS9-A-SCHOLAR` 按门户粒度判定，不是全局角色 | `IA9-SEQ-08` |

## 7. 业务映射状态模型

### 7.1 映射原则

业务状态由成员 3、8 定义，前端只做呈现映射，不自行推断。

| 业务状态（成员 3、8 定义） | 前端呈现 | 可用操作 | 不得呈现 |
| --- | --- | --- | --- |
| `PENDING` | "审核中" | 查看详情 | 不显示已获维护权 |
| `APPROVED` | "已通过" | 进入门户维护 | 不表示成果真实性背书 |
| `REJECTED` | "已驳回" | 查看原因、重新申请 | 不只写"材料不符" |
| 待确认扩展状态 | 候选呈现方案 | 待定 | 不写入正式状态枚举 |

### 7.2 一致性规则

| 编号 | 规则 |
| --- | --- |
| `FS9-BR-01` | 前端缓存的业务状态与服务端返回不一致时，以服务端为准并刷新显示 |
| `FS9-BR-02` | 提交操作后不本地推断结果状态，须以服务端返回的权威状态渲染 |
| `FS9-BR-03` | 通知失败不得使已提交的操作显示为未提交 |
| `FS9-BR-04` | 审核期间记录被他人先处理时，提示记录已更新并加载权威状态，不覆盖 |

**依据**：成员 4 的方案 A 文档第 4 节并发反馈要求，与本文一致，可作为共同基线。
