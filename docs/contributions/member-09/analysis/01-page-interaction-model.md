## 2. 交互模型的表达约定

### 2.1 三层分解

每个关键用例按三层描述，避免把界面方案写成业务规则：

| 层次 | 描述内容 | 示例 |
| --- | --- | --- |
| 用户意图层 | 用户想完成什么任务 | "找到某领域近三年的代表性论文" |
| 交互动作层 | 用户执行的可观察操作序列 | 输入关键词 → 勾选领域 → 设置年份 → 提交 |
| 系统响应层 | 页面的可观察反馈 | 显示条件标签 → 加载态 → 结果列表 → 总数与排序说明 |

### 2.2 参与者约定

沿用需求建模阶段的角色定义，交互模型中只区分四类：

| 代号 | 角色 | 交互特征 |
| --- | --- | --- |
| `U-V` | 访客 | 只读交互，触发认领时需先登录 |
| `U-L` | 登录用户 | 可提交认领申请，查看本人申请 |
| `U-S` | 已认领学者 | 可维护授权门户 |
| `U-A` | 平台管理员 | 可审核认领申请 |

### 2.3 编号规则

| 编号前缀 | 含义 | 数量 |
| --- | --- | --- |
| `IA9-UC-*` | 交互用例（Interaction Case） | 8 个 |
| `IA9-SEQ-*` | 交互序列（Sequence） | 8 个，与交互用例一一对应 |
| `IA9-RULE-*` | 交互规则（Rule） | 12 条 |
| `IA9-Q*` | 待确认问题 | 6 个 |

## 4. 交互序列详述

### 4.1 `IA9-SEQ-01`：关键词检索成果

**对应交互用例**：`IA9-UC-01`
**证据**：`E-B-Q-001-Q3`（84% 首选关键词检索）

**用户意图层**：访客想用一个词找到相关成果，不想先学习字段规则。

**交互序列**：

```text
U-V                     检索页面                  检索服务
 |                         |                         |
 |-- 聚焦检索框 ----------->|                         |
 |                         |-- 显示占位提示与对象选择 -|
 |-- 输入关键词 ----------->|                         |
 |                         |-- 字符数 >= 2 时请求建议 ->|
 |                         |<-- 返回建议列表 ----------|
 |<-- 显示最多 8 条建议 ----|                         |
 |-- 提交（Enter 或按钮）-->|                         |
 |                         |-- 进入加载态 ------------|
 |                         |-- 提交查询 ------------->|
 |                         |<-- 返回结果与总数 --------|
 |<-- 显示条件、总数、排序 -|                         |
 |<-- 显示结果列表 ---------|                         |
```

**系统响应层的必须项**：

| 反馈项 | 要求 | 依据 |
| --- | --- | --- |
| 检索条件回显 | 显示当前对象与关键词，用户可确认搜的是什么 | `UI9-FR-11` |
| 总数语义 | 显示精确总数或明确的近似标识，不伪造精确值 | `UI9-FR-14` |
| 排序说明 | 显示当前排序依据，不让用户猜 | `UI9-FR-13` |
| 结果项字段 | 标题、作者、年份、来源、更新时间 | `E-B-Q-001-Q5`、`Q7`、`Q8` |
| 加载态 | 超过 300ms 显示加载指示，保持页面框架稳定 | `UI9-NFR-08` |

**交互规则**：

- `IA9-RULE-01`：建议列表的请求失败不得阻塞用户继续输入与提交。
- `IA9-RULE-02`：同一查询在结果返回前重复提交只生效一次，不产生两次请求。

### 4.2 `IA9-SEQ-02`：组合筛选与排序

**对应交互用例**：`IA9-UC-02`
**证据**：`E-B-Q-001-Q3`（73% 使用多条件组合）

**用户意图层**：访客想在一屏结果里逐步收窄范围，并随时知道自己加了哪些条件。

**交互序列**：

```text
U-V                     结果页面                  检索服务
 |                         |                         |
 |-- 勾选领域条件 --------->|                         |
 |                         |-- 追加条件标签 ----------|
 |                         |-- 进入加载态 ------------|
 |                         |-- 带全部条件重新查询 ---->|
 |                         |<-- 返回结果与总数 --------|
 |<-- 更新结果与总数 -------|                         |
 |-- 设置年份区间 --------->|                         |
 |                         |-- 校验区间合法性 --------|
 |                         |   起始 > 结束：字段级报错 |
 |                         |   合法：重新查询 -------->|
 |<-- 更新结果 -------------|                         |
 |-- 切换排序 ------------->|                         |
 |                         |-- 回到第 1 页并重新查询 ->|
 |<-- 更新结果与排序说明 ---|                         |
 |-- 移除单个条件标签 ----->|                         |
 |                         |-- 保留其余条件重新查询 -->|
 |<-- 更新结果 -------------|                         |
```

**交互规则**：

- `IA9-RULE-03`：筛选条件变化后回到第 1 页；分页位置不跨条件保留。
- `IA9-RULE-04`：移除单个条件不清空关键词；"清除全部筛选"不清空关键词，除非用户选择完全重置。
- `IA9-RULE-05`：非法条件（如年份区间倒置）在字段级报错，不发起查询，不显示空结果。

**待确认**：`IA9-Q01`（筛选即时生效还是点击"应用"）。问卷显示 64% 期望即时生效（`E-B-Q-001-Q3`），但方案 A 倾向显式应用。本文按即时生效建模，由成员 1、6 与成员 4 共同确认后统一。

### 4.3 `IA9-SEQ-03`：查看成果详情

**对应交互用例**：`IA9-UC-03`
**证据**：`E-B-Q-001-Q5`（96% 看标题）、`Q7`（96% 关注来源）、`Q8`（94% 关注更新时间）

**用户意图层**：访客想确认这条成果是不是自己要找的，并判断信息可不可信。

**交互序列**：

```text
U-V                     结果页面      详情页面        成果服务
 |                         |             |               |
 |-- 点击结果标题 --------->|             |               |
 |                         |-- 跳转 ----->|               |
 |                         |             |-- 请求详情 --->|
 |                         |             |<-- 返回数据 ---|
 |<-- 显示标题、作者、年份 ---------------|               |
 |<-- 显示来源与更新时间 -----------------|               |
 |<-- 缺失字段显示"未提供" ---------------|               |
 |-- 点击作者名 -------------------------->|               |
 |                                        |-- 跳转门户 -->|
 |-- 返回（浏览器后退）------------------->|               |
 |<-- 恢复原结果页与检索条件 --------------|               |
```

**系统响应层的必须项**：

| 反馈项 | 要求 | 依据 |
| --- | --- | --- |
| 可信度信息 | 来源名称、更新时间同屏可见，不需展开 | `UI9-NFR-01` |
| 过时提示 | 更新时间超过阈值显示提示，不静默展示旧数据 | `UI9-NFR-05` |
| 缺失表达 | 区分"未提供""未知""真实为 0" | `UI9-NFR-02` |
| 模拟标记 | 模拟数据在详情顶部明确标注 | `UI9-NFR-04` |
| 返回恢复 | 后退后保留原检索条件与分页位置 | `UI9-NFR-10` |

**交互规则**：

- `IA9-RULE-06`：从详情返回结果页时恢复检索条件与分页位置，不重置为首页。
- `IA9-RULE-07`：原始链接不可用时说明状态，不自动跳转到不可信地址。

**待确认**：`IA9-Q02`（数据过时阈值）。需成员 2、7 依据实际更新频率给出，本文暂按 30 天建模。

### 4.4 `IA9-SEQ-04`：区分同名学者

**对应交互用例**：`IA9-UC-04`
**证据**：`E-B-Q-001-Q6`（80% 遇到同名困扰：24% 经常、56% 偶尔）

**用户意图层**：访客搜到多个同名学者，想在列表阶段就判断哪个是目标，不想逐个点开。

**交互序列**：

```text
U-V                     学者结果页               学者服务
 |                         |                         |
 |-- 检索学者姓名 --------->|                         |
 |                         |-- 提交查询 ------------->|
 |                         |<-- 返回多个同名实体 ------|
 |<-- 并列显示各实体 -------|                         |
 |   每条含机构、领域、代表成果                        |
 |-- 悬停某条 ------------->|                         |
 |<-- 显示代表成果摘要 -----|                         |
 |-- 点击目标实体 --------->|                         |
 |                         |-- 按实体 ID 进入门户 ---->|
```

**消歧信息的降级顺序**：

| 优先级 | 消歧线索 | 缺失时 |
| --- | --- | --- |
| 1 | 当前机构 | 降级到第 2 项 |
| 2 | 研究领域 | 降级到第 3 项 |
| 3 | 代表成果标题 | 降级到第 4 项 |
| 4 | 成果数量统计 | 显示"机构未知"，不隐藏该实体 |

**交互规则**：

- `IA9-RULE-08`：同名实体全部保留并列显示，不合并、不按姓名去重。
- `IA9-RULE-09`：姓名不作为跳转依据，点击后按不可变实体 ID 进入门户。

### 4.5 `IA9-SEQ-05`：浏览学者门户

**对应交互用例**：`IA9-UC-05`

**交互序列**：

```text
U-V                     门户页面                 门户服务
 |                         |                         |
 |-- 进入门户 ------------->|                         |
 |                         |-- 请求门户数据 --------->|
 |                         |<-- 返回信息与成果 --------|
 |<-- 显示姓名、机构、方向 -|                         |
 |<-- 显示认领状态标识 -----|                         |
 |<-- 显示四类成果分组 -----|                         |
 |-- 切换成果类型标签 ----->|                         |
 |                         |-- 切换内容区（无刷新）---|
 |<-- 显示该类成果列表 -----|                         |
 |   该类为空：显示明确空态                            |
```

**交互规则**：

- `IA9-RULE-10`：未认领门户可展示公开数据，但不得暗示平台已验证本人身份。
- `IA9-RULE-11`：已认领标识只表示认领关系通过，不表示平台为成果真实性背书。

### 4.6 `IA9-SEQ-06`：提交认领申请

**对应交互用例**：`IA9-UC-06`
**证据**：`E-B-Q-001-Q11`（90% 期望详情页入口）、`Q10`（78% 期望 ≤3 步）

**用户意图层**：用户发现疑似本人的成果或门户，想把它关联到自己名下。

**交互序列**：

```text
U-V/U-L            入口页面      认领流程页        认领服务
 |                    |              |                |
 |-- 点击认领 -------->|              |                |
 |                    |-- 检查登录态 -|                |
 |   未登录：                        |                |
 |<-- 说明需登录并保留上下文 ---------|                |
 |-- 完成登录 ----------------------->|                |
 |<-- 返回原入口并恢复认领上下文 -----|                |
 |   已登录：                        |                |
 |                    |              |-- 查重复申请 -->|
 |                    |              |<-- 已有待审申请 -|
 |<-- 打开既有申请，不新建 -----------|                |
 |                    |              |   无重复：      |
 |<-- 步骤 1：关系说明 ---------------|                |
 |-- 填写并下一步 -------------------->|                |
 |<-- 步骤 2：证明材料 ---------------|                |
 |-- 选择材料并下一步 ---------------->|                |
 |<-- 步骤 3：确认与隐私声明 ---------|                |
 |-- 提交 --------------------------->|                |
 |                    |              |-- 服务端校验 -->|
 |                    |              |<-- 创建申请 ----|
 |<-- 申请编号、状态、查询入口 -------|                |
```

**系统响应层的必须项**：

| 反馈项 | 要求 | 依据 |
| --- | --- | --- |
| 登录上下文恢复 | 登录后回到原入口，不丢失认领意图 | `UI9-FR-31` |
| 重复申请处理 | 打开既有申请，不产生第二个成功编号 | `UI9-FR-32` |
| 提交后反馈 | 申请编号、提交时间、当前状态、查询入口 | `UI9-FR-34` |
| 权限边界表达 | 提交成功不等于获得维护权 | `UI9-FR-37` |
| 字段级校验 | 错误定位到具体输入，保留其他非敏感内容 | `UI9-NFR-07` |

**交互规则**：

- `IA9-RULE-12`：登录成功不得显示为认领成功；申请创建不得显示为获得门户维护权。

**待确认**：
- `IA9-Q03`（最小证明材料集合与访问范围）：需成员 3、8 提案，成员 1、6 确认。
- `IA9-Q04`（是否允许撤回待审申请）：影响步骤 3 与申请详情的可用操作。

### 4.7 `IA9-SEQ-07`：查询认领状态

**对应交互用例**：`IA9-UC-07`
**证据**：`E-B-Q-001-Q10`（86% 期望状态通知）

**交互序列**：

```text
U-L                  申请详情页              认领服务
 |                       |                       |
 |-- 打开申请详情 ------->|                       |
 |                       |-- 请求申请状态 ------->|
 |                       |<-- 返回状态与时间线 ----|
 |<-- 显示编号、状态、时间 |                       |
 |<-- 显示状态变化时间线 --|                       |
 |   状态为已驳回：                               |
 |<-- 显示驳回原因与修正方向 ---------------------|
 |-- 重新申请 ----------->|                       |
 |                       |-- 带入上次非敏感内容 -->|
```

**状态反馈的表达要求**：

| 状态 | 用户可见表达 | 可用操作 | 禁止 |
| --- | --- | --- | --- |
| 待审核 | "审核中"，含提交时间 | 查看详情；撤回（待确认） | 不显示已获维护权 |
| 已通过 | "已通过"，含通过时间 | 进入门户维护 | 不表示平台为成果背书 |
| 已驳回 | "已驳回"，含原因与修正方向 | 查看原因、重新申请 | 不只写"材料不符" |
| 需补充材料 | "需补充材料"，含缺少项 | 补充材料 | 不泄露他人材料信息 |

**待确认**：`IA9-Q05`（"需补充材料"是否作为正式公共状态）。当前为界面展示候选，须与状态图、SPEC、接口一致后方可写入正式状态枚举。

### 4.8 `IA9-SEQ-08`：维护门户成果

**对应交互用例**：`IA9-UC-08`
**证据**：`E-B-Q-001-Q11`（54% 期望批量操作）

**交互序列**：

```text
U-S                  门户维护页              门户服务
 |                       |                       |
 |-- 进入维护 ----------->|                       |
 |                       |-- 校验授权范围 ------->|
 |                       |<-- 返回可维护内容 ------|
 |<-- 显示当前版本与更新时间 ---------------------|
 |-- 编辑个人公开字段 ---->|                       |
 |                       |-- 字段级校验 ----------|
 |-- 保存 --------------->|                       |
 |                       |-- 提交保存 ----------->|
 |                       |<-- 版本已变化 ----------|
 |<-- 保留输入并提示冲突，提供重新加载 ------------|
 |-- 选择多条成果 -------->|                       |
 |<-- 显示"已选 N 项"与批量操作 ------------------|
 |-- 执行批量隐藏 -------->|                       |
 |<-- 二次确认 -----------|                       |
 |-- 确认 --------------->|                       |
 |                       |-- 提交批量操作 ------->|
 |<-- 显示结果与受影响条数 -----------------------|
```

**权限边界的界面表达**：

| 操作对象 | 允许 | 禁止 |
| --- | --- | --- |
| 个人公开字段 | 编辑、保存 | 仅限授权门户 |
| 成果展示关联 | 新增、隐藏、纠错 | 不等于删除成果本体 |
| 共享成果元数据 | 提交纠错请求 | 不允许单方覆盖多作者共享内容 |
| 他人门户 | 无 | 不以隐藏按钮替代服务端授权 |
