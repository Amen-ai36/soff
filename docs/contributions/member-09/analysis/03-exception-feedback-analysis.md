# 异常反馈分析（成员 9，方案 B）

状态：成员 9 需求分析阶段贡献草案。`EX9-*` 是局部追踪编号，待成员 3 汇编、成员 8 复核。本文分析异常的分类、传达方式与恢复路径，不定义后端错误码。

编制日期：2026-10-13。阶段：第 7～8 周。分支：`b`。

## 1. 本文范围与依据

### 1.1 为什么需要独立的异常分析

问卷数据显示用户对"信息可信度"高度敏感：96% 关注数据来源、94% 关注更新时间（`E-B-Q-001-Q7`、`Q8`）。这意味着异常被错误地表达为正常数据时，会直接损害用户信任。本文把异常反馈作为独立分析对象，目的是：

1. 防止不同性质的异常被混为一谈（典型错误：把服务失败显示为"0 条结果"）
2. 防止异常反馈泄露隐私（典型错误：用错误提示暴露受限记录是否存在）
3. 为每类异常给出用户可执行的恢复路径，而不是只显示错误文案

### 1.2 承接关系

| 上游输入 | 使用方式 |
| --- | --- |
| [页面交互模型](01-page-interaction-model.md) | 交互序列中的异常分支 |
| [前端状态模型](02-frontend-state-model.md) | `FS9-L-ERROR`、`FS9-A-DENIED` 等状态的具体内容 |
| [可用性需求](../requirements/04-usability-requirements.md) | `UI9-NFR-04`（错误信息友好）、`UI9-NFR-14`（隐私隔离） |
| 成员 4 方案 A 第 5、7 节 | 状态矩阵与并发反馈，作为共同基线参照 |

### 1.3 不在本文范围

- 后端错误码取值与 HTTP 状态码（成员 3、8 定义）
- 日志格式与追踪标识生成规则（成员 5、10 与成员 3、8 定义）
- 采集任务与数据清洗的失败处理（成员 2、7 定义）
- 具体文案的最终措辞（构件设计阶段确定）

## 2. 异常分类框架

### 2.1 六类异常

把异常按"原因归属"分类，因为不同归属决定了不同的反馈语气与恢复路径：

| 编号 | 类别 | 原因归属 | 用户可否自行解决 | 示例 |
| --- | --- | --- | --- | --- |
| `EX9-C1` | 业务空结果 | 无人出错 | 可以（改条件） | 检索无匹配 |
| `EX9-C2` | 用户输入错误 | 用户 | 可以（改输入） | 年份区间倒置 |
| `EX9-C3` | 权限不足 | 规则限制 | 部分（登录或申请权限） | 未登录访问申请详情 |
| `EX9-C4` | 业务冲突 | 并发或状态变化 | 可以（刷新后重试） | 审核期间被他人处理 |
| `EX9-C5` | 依赖失败 | 系统 | 不能（只能重试） | 检索服务不可用 |
| `EX9-C6` | 数据不完整 | 数据源 | 不能（可反馈） | 字段缺失、来源失效 |

### 2.2 分类的关键判别

最容易混淆的三组：

| 易混淆 | 判别依据 | 混淆后果 |
| --- | --- | --- |
| `EX9-C1` 业务空 vs `EX9-C5` 依赖失败 | 服务是否成功响应 | 把失败显示成"0 条"，用户误以为真无数据 |
| `EX9-C2` 输入错误 vs `EX9-C5` 依赖失败 | 错误是否可由修改输入消除 | 把输入问题显示成系统错误，用户反复重试 |
| `EX9-C6` 数据不完整 vs 真实值为 0 | 字段是否存在 | 把"未知"显示为"0"，产生错误结论 |

**规则 `EX9-R-01`**：以上三组必须使用不同的视觉与文案，不得互相替代（承接 `UI9-NFR-02`、`UI9-AC-04`、`UI9-AC-05`）。

## 3. 各类异常的反馈分析

### 3.1 `EX9-C1` 业务空结果

**性质**：服务正常，条件下确实无数据。不是错误。

**反馈要素**：

| 要素 | 要求 | 禁止 |
| --- | --- | --- |
| 语气 | 中性，不使用警告或错误色 | 不用"错误""失败""异常" |
| 原因说明 | 说明当前条件下无匹配 | 不暗示系统问题 |
| 条件回显 | 保留并显示当前关键词与筛选条件 | 不清空用户输入 |
| 恢复操作 | 可点击的改词、清筛选、浏览推荐 | 不只给纯文案 |

**恢复路径**（按问卷证据排序，`E-B-Q-001-Q9`）：

| 优先级 | 操作 | 问卷支持 |
| --- | --- | --- |
| 1 | 推荐相似关键词（可点击直接检索） | 76% |
| 2 | 提示可能的拼写问题 | 60% |
| 3 | 推荐相关领域入口 | 44% |
| 4 | 提示放宽筛选条件 | 40% |

**场景化分析**：

| 场景 | 可能原因 | 针对性反馈 |
| --- | --- | --- |
| 关键词无结果 | 拼写、过于具体、数据未覆盖 | 相似词推荐 + 拼写提示 |
| 筛选后无结果 | 条件组合过窄 | 指出哪些条件可放宽，提供逐个移除 |
| 某类成果无结果 | 该类型数据未入库 | 说明该类型暂无数据，推荐其他类型 |
| 学者门户某类成果为空 | 该学者无此类成果 | 明确空态，不显示"加载失败" |

### 3.2 `EX9-C2` 用户输入错误

**性质**：输入不符合规则，用户可自行修正。

**反馈要素**：

| 要素 | 要求 | 禁止 |
| --- | --- | --- |
| 定位 | 错误指向具体字段 | 不用全局提示代替字段定位 |
| 原因 | 说明哪里不符合要求 | 不只说"输入有误" |
| 修正方向 | 给出正确格式或示例 | 不让用户猜 |
| 其他输入 | 保留非敏感的其他已填内容 | 不清空整个表单 |
| 时机 | 失焦后校验，不在输入过程打断 | 不逐字符报错 |

**典型场景**：

| 场景 | 反馈定位 | 修正方向 |
| --- | --- | --- |
| 年份区间倒置 | 年份字段 | 说明起始年需不晚于结束年 |
| 关键词超长 | 检索框 | 显示字数限制与当前字数 |
| 认领关系说明为空 | 该字段 | 说明必填及用途 |
| 材料格式不符 | 材料字段 | 说明允许的格式（具体规则待成员 3、8 提供） |
| 重复提交同一申请 | 全局提示 | 打开既有申请，说明已有编号 |

**规则 `EX9-R-02`**：输入错误不发起服务请求，不进入加载态，不显示空结果（承接 `IA9-RULE-05`）。

### 3.3 `EX9-C3` 权限不足

**性质**：规则限制，不是系统错误。反馈须兼顾可用性与隐私。

**反馈要素**：

| 要素 | 要求 | 禁止 |
| --- | --- | --- |
| 原因说明 | 说明需要登录或无访问权 | 不泄露记录或材料是否存在 |
| 恢复路径 | 提供登录入口或申请说明 | 不让用户停在死页面 |
| 上下文保留 | 登录后回到原任务 | 不丢失用户意图 |
| 一致性 | 前端隐藏不替代服务端校验 | 不以隐藏按钮作为唯一防护 |

**隐私敏感的反馈设计**：

| 场景 | 不安全的反馈 | 安全的反馈 |
| --- | --- | --- |
| 访问他人申请详情 | "该申请属于其他用户" | "无访问权限" |
| 访问不存在的申请 | "申请不存在" | "无访问权限"（与上一条相同） |
| 门户已被他人认领 | "已被用户 X 认领" | "该门户已被认领" |
| 材料访问被拒 | "材料 ID 12345 无权访问" | "无访问权限" |

**规则 `EX9-R-03`**：对"无权访问"与"不存在"使用相同反馈，使攻击者无法通过反馈差异推断记录存在性（承接 `UI9-NFR-14`、`UI9-AC-17`）。

**规则 `EX9-R-04`**：管理员自审场景下，操作入口不可用且服务端仍须拒绝（承接成员 4 方案 A 第 5 节，作为共同基线）。

### 3.4 `EX9-C4` 业务冲突

**性质**：并发或状态已变化，用户的操作基于过期信息。

**反馈要素**：

| 要素 | 要求 | 禁止 |
| --- | --- | --- |
| 冲突说明 | 说明记录已更新 | 不暴露他人操作细节 |
| 权威状态 | 加载并显示最新权威状态 | 不以本地旧状态覆盖 |
| 输入保留 | 保留用户已填内容 | 不丢弃用户工作 |
| 决策权 | 让用户看到最新状态后再决定 | 不自动重试覆盖 |

**典型场景分析**：

| 场景 | 冲突内容 | 反馈与恢复 |
| --- | --- | --- |
| 审核期间被他人先处理 | 申请状态已变 | 提示已更新，加载权威状态，不覆盖 |
| 门户在申请期间被认领 | 门户占用状态变化 | 冲突提示（不泄露认领人），引导返回或纠错 |
| 编辑时门户版本变化 | 字段版本冲突 | 保留输入，提示冲突，提供重新加载/比较 |
| 分页时数据集更新 | 结果集版本失效 | 提示重新查询，保留原条件 |
| 重复提交同一请求 | 已有权威结果 | 展示权威结果，不显示两个成功 |

**规则 `EX9-R-05`**：冲突反馈不得泄露他人身份、材料或内部决策细节。

**规则 `EX9-R-06`**：持久化失败时明确告知"提交未确认成功"，并提供查询权威状态的入口，避免用户盲目重试造成重复数据。

### 3.5 `EX9-C5` 依赖失败

**性质**：系统侧问题，用户无法自行解决。

**反馈要素**：

| 要素 | 要求 | 禁止 |
| --- | --- | --- |
| 可识别性 | 用户能看出这是系统问题 | 不伪装成空结果 |
| 追踪标识 | 显示公共契约提供的追踪信息 | 不显示技术栈与堆栈 |
| 重试入口 | 提供重试，保留原条件 | 不要求用户重新填写 |
| 备选路径 | 提供返回首页或其他入口 | 不让用户停在死页面 |
| 语气 | 说明暂时不可用 | 不归咎用户 |

**分级反馈**：

| 失败范围 | 反馈粒度 | 页面其余部分 |
| --- | --- | --- |
| 单个区域失败（如推荐列表） | 区域内提示 + 局部重试 | 其余部分正常显示 |
| 主要内容失败（如检索结果） | 主区域提示 + 重试 | 导航与检索框仍可用 |
| 全页失败 | 全页提示 + 重试 + 返回首页 | — |
| 提交失败 | 保留输入 + 明确未确认成功 | 不显示成功 |

**规则 `EX9-R-07`**：区域级失败不得使整页不可用；用户仍应能使用页面其他功能（承接 `FS9-LR-03` 的并发独立原则）。

**规则 `EX9-R-08`**：技术细节记录到日志，不呈现给用户（承接 `UI9-NFR-04`）。

### 3.6 `EX9-C6` 数据不完整

**性质**：数据源导致的字段缺失或过时，不是请求失败。这是本项目的高频情况，问卷显示 64% 用户认为现有系统缺少来源说明（`E-B-Q-001-Q7` 相关发现）。

**三种缺失的区分**：

| 情况 | 含义 | 界面表达 | 禁止 |
| --- | --- | --- | --- |
| 未提供 | 数据源未给该字段 | "未提供" | 不显示 0、不留空白 |
| 未知 | 字段存在但值不可确定 | "未知" | 不显示 0 |
| 真实为 0 | 确实是 0 | "0" | 不显示"未提供" |

**规则 `EX9-R-09`**：以上三种必须可区分（承接 `UI9-NFR-02`、`UI9-AC-14`）。

**过时数据的反馈**：

| 情况 | 反馈 | 恢复路径 |
| --- | --- | --- |
| 更新时间超过阈值 | 显示"数据可能过时"及最后更新时间 | 提供反馈入口 |
| 来源链接失效 | 说明链接状态 | 不自动跳转；提供反馈入口 |
| 来源缺失 | 标记为待治理 | 不隐藏该记录 |
| 模拟数据 | 明确标记 | 说明用途 |

**统计场景的特殊要求**：

统计页面若有未知类数据，必须显示未知类占比，否则用户会对分母产生错误理解。

| 要素 | 要求 |
| --- | --- |
| 统计口径 | 显示计数规则（如多作者多机构如何计） |
| 时间范围 | 显示统计覆盖的时间区间 |
| 未知类 | 显示未知类数量或占比 |
| 更新时间 | 显示统计快照时间 |

**规则 `EX9-R-10`**：统计不得在未知类存在时仅显示已知类百分比而不说明分母（承接 `UI9-NFR-03`）。

## 4. 异常反馈的呈现方式选择

### 4.1 呈现载体对照

| 载体 | 适用异常 | 不适用 |
| --- | --- | --- |
| 字段级提示 | `EX9-C2` 输入错误 | 系统失败 |
| 区域内提示 | `EX9-C1` 空结果、区域级 `EX9-C5` | 需要用户立即决策的冲突 |
| 全页提示 | 全页 `EX9-C5`、`EX9-C3` 权限 | 单字段错误 |
| 轻提示（Toast） | 操作成功、轻量冲突提示 | 需要用户阅读详情的错误 |
| 模态确认 | `EX9-C4` 需用户决策的冲突 | 频繁出现的轻量提示 |
| 行内标记 | `EX9-C6` 字段缺失 | 阻断性错误 |

### 4.2 选择规则

| 编号 | 规则 |
| --- | --- |
| `EX9-R-11` | 需要用户修正输入的异常用字段级提示，不用 Toast（Toast 会消失，用户无法对照修改） |
| `EX9-R-12` | 需要用户做决策的冲突用模态，不用 Toast |
| `EX9-R-13` | 高频轻量反馈用 Toast，不用模态（避免打断） |
| `EX9-R-14` | 字段缺失用行内标记，不用提示框（避免为每个缺失字段弹提示） |

## 5. 异常反馈的可访问性

承接 `UI9-A11Y-*` 要求，异常反馈的无障碍要点：

| 要求 | 具体做法 | 依据 |
| --- | --- | --- |
| 不只靠颜色 | 错误同时用图标与文字表达 | `UI9-A11Y-04` |
| 可被屏幕阅读器获取 | 错误提示与对应字段建立关联 | `UI9-A11Y-03` |
| 焦点管理 | 提交失败后焦点移到第一个错误字段 | `UI9-A11Y-02` |
| 模态焦点 | 模态内焦点不逸出，关闭后焦点归位 | `UI9-AC-15` |
| 对比度 | 错误文字对比度达标 | `UI9-A11Y-05` |

**规则 `EX9-R-15`**：表单提交失败后焦点自动移到第一个错误字段，键盘用户无需逐个 Tab 查找。
