## 1. 定位与边界

成员 6 的逻辑架构把系统分为展现层、业务服务层、存储访问、采集层、处理层、投影与发布。本文只细化展现层，即"公开检索/门户、认领流程、统计页和管理后台"的浏览器端部分。

| 展现层负责 | 展现层不负责 |
| --- | --- |
| 页面、路由、导航与页面状态 | 业务授权判定（只做界面提示，服务端必须再校验） |
| 把用户输入转成对业务服务的请求 | 检索排序、统计口径、认领规则（成员 3、8） |
| 按统一规则呈现成功、空结果、失败、无权、冲突 | 公共 API 路径、字段与错误码（待 OpenAPI 冻结） |
| 幂等键、版本号等并发参数的生成与回传 | 数据库、Elasticsearch、OBS 的任何直接访问 |
| 创新功能在页面上的接入点 | 创新功能的最终选定（成员 1、6 与老师确认） |

成员 6 的约束"页面不能直连数据库；管理后台不绕过业务授权直接写库"在本层的落实方式：浏览器代码只依赖一个 `ApiClient` 接口（见第 2 节），该接口的实现只发 HTTPS 请求到业务服务层，代码里没有任何存储客户端。

## 2. 展现层内部分层

```text
views/         页面：组合组件、读写 URL、调用 composables
components/    可复用界面组件：只接收 props、发出事件
composables/   页面状态：会话、异步加载状态、取消与防重
domain/        纯函数：查询参数校验、显示规则、加载状态、合作图算法
api/port.ts    ApiClient 接口与数据类型（展现层视角）
api/http.ts    HTTP 实现：请求构造、超时、错误归类
api/mock/      假实现：基于成员 8 合成夹具，供并行开发与测试
features/      创新功能注册表与候选模块
```

依赖方向只允许自上而下：

| 层 | 可以依赖 | 不可以依赖 |
| --- | --- | --- |
| views | components、composables、domain、api/port、features | api/http、api/mock（由启动代码注入） |
| components | domain | api、composables |
| composables | domain、api/port | views、api/http、api/mock |
| domain | 无（只依赖语言标准库） | vue、api、浏览器全局对象 |
| api/http、api/mock | api/port、domain | views、components |

这条规则不是靠约定维持的：`frontend/src/__tests__/architecture.test.ts` 扫描源码中的 `import`，`domain/` 引用 vue 或 api、`components/` 引用 api、`views/` 直接引用 http 或 mock 实现时测试失败。

把规则和算法放在 `domain/` 的原因：它们是展现层里最容易出错、也最值得单测的部分（查询参数校验、空值显示、加载状态转换、合作路径计算），放在纯函数里可以不启动浏览器就覆盖到 80% 以上。

## 3. 页面模块与路由

页面按业务服务划分为 6 个模块。路由守卫只用于引导用户（例如未登录时跳到登录页），不是权限控制；服务端拒绝时页面按"无权限"显示。

| 模块 | 路由 | 页面 | 访问提示 | 消费的业务服务 | 依据 |
| --- | --- | --- | --- | --- | --- |
| 检索 | `/` | 首页 | 公开 | 检索、统计（领域入口） | 问卷 Q4 |
| 检索 | `/works` | 成果检索结果 | 公开 | 检索 | SPEC-M8-SEARCH；IA9-SEQ-01、02 |
| 检索 | `/works/:id` | 成果详情 | 公开 | 检索 | IA9-SEQ-03 |
| 检索 | `/scholars` | 学者检索结果 | 公开 | 检索 | IA9-SEQ-04；问卷 Q12 |
| 门户与认领 | `/scholars/:id` | 学者门户 | 公开 | 门户与认领 | IA9-SEQ-05；问卷 Q14 |
| 门户与认领 | `/scholars/:id/claim` | 认领申请 | 需登录 | 门户与认领 | SPEC-M8-CLAIM；IA9-SEQ-06 |
| 门户与认领 | `/me/claims` | 我的认领申请 | 需登录 | 门户与认领 | IA9-SEQ-07 |

## 4. 状态管理

不引入全局状态库，状态按生命周期放在三个地方：

| 状态 | 放在哪里 | 原因 |
| --- | --- | --- |
| 检索条件、排序、分页、成果类型标签 | URL 查询参数 | 后退、刷新、分享后能恢复（UI9-NFR-10、FS9-VR-01） |
| 会话 | `composables/useSession.ts` 单例 | 全站共享，只读一次，登录、退出时更新 |
| 加载状态、表单输入、冲突提示 | 页面内 | 离开页面即丢弃，不需要跨页 |

URL 作为检索状态的唯一来源，意味着"改筛选→回到第 1 页"之类的规则只在一个纯函数里实现（`domain/searchQuery.ts`），页面只负责调用。决策理由见 ADR-M9-03。

## 5. 非功能考量

每一项都给出落实位置和验证方式，不只写原则。

| 质量属性 | 措施 | 落实位置 | 验证 |
| --- | --- | --- | --- |
| 安全：权限 | 界面隐藏按钮只是提示；所有写操作的结果以服务端响应为准 | views 中处理 401/403/404 | 假实现返回 FORBIDDEN 时页面显示无权限的组件测试 |
| 安全：信息泄露 | 对私有资源"无权"和"不存在"使用同一提示；不展示服务端原始错误正文 | `api/errors.ts` | 错误映射单测 |
| 安全：开放重定向 | 登录后返回地址只接受站内路径，拒绝 `//`、协议前缀 | `domain/redirect.ts` | 单测覆盖 `//evil.com`、`https://` 等 |
| 安全：凭据 | 不把令牌放进 URL 或 localStorage；会话机制待 SPEC-M8-AUTH 选型 | `api/http.ts` | 代码审查项 |
| 性能 | 列表只取一页（默认 20，最大 100）；按路由拆分代码；连续改条件时只保留最后一次请求 | `useAsync.ts`、路由懒加载 | 构建产物分块；"最后一次请求获胜"单测 |
| 可用性：异常 | 空结果、依赖失败、超时、无权、冲突、数据已更新分别显示，空结果不等于失败 | `domain/loadState.ts`、`LoadStateView.vue` | 状态转换单测与组件测试 |
| 可用性：缺失值 | `null` 显示"未提供"，`0` 显示 0，空列表显示"无" | `domain/display.ts` | 单测 |
| 可访问性 | 表单有标签；状态不只靠颜色；提交失败后焦点移到第一个出错字段；正文对比度 ≥ 4.5:1 | 组件与 `styles/tokens.ts` | 对比度在单测中按 WCAG 公式计算 |
| 可观测性 | 失败时显示服务端提供的追踪 ID，便于后端定位 | `LoadStateView.vue` | 组件测试 |
| 可维护性 | 分层依赖由测试强制；业务规则集中在 domain | `architecture.test.ts` | 测试 |
| 可测试性 | `ApiClient` 有假实现，页面可在无后端时运行和测试 | `api/mock/` | 全部组件测试使用假实现 |

性能指标（P95、并发数）没有写数字：SRS 已说明这些是候选指标，需要确定数据集和环境后共同批准。展现层能保证的是"不在浏览器里加载全集"。

### 6.1 真实问卷对页面设计的影响

样本为 30～35 名学生（本科生 32/35），没有教师和管理员，因此只能支撑公开检索类页面的设计，不能支撑认领、审核、维护页面。

| 题目与结果 | 设计决定 |
| --- | --- |
| Q4：最近一次从关键词进入 15/30，从领域分类进入 9/30 | 首页以检索框为主，领域入口作为第二入口放在首屏，不是三入口并列 |
| Q6：用过领域筛选 23/30、类型筛选 16/30、年份筛选 15/30、机构筛选 4/30 | 筛选面板顺序：领域、类型、年份、机构 |
| Q7：最先看标题 23/30、年份 16/30，数据来源 0/30 | 结果卡片突出标题和年份；来源放在卡片次要行和详情页，不占首要位置 |
| Q9：找不到原始出处"经常+有时"18/30 | 详情页必须有来源链接，链接失效时说明状态 |
| Q10：最影响效率的是"搜不到"19/30 | 空结果页给出可直接操作的修改入口 |
| Q11：空结果时换关键词 16/30、减少筛选 7/30，"看平台建议"0/30 | 空结果页放"修改关键词"和"逐个移除筛选"，不做复杂推荐 |
| Q12：区分同名看研究领域 18/30、代表成果 18/30、机构 11/30 | 学者卡片依次显示领域、代表成果、机构 |
| Q14（n=23）：看研究方向 17、成果列表 14、成果数量 11、合作者 6 | 门户首屏为研究方向与成果列表；合作者信息放次级位置 |
| Q15：经常看统计 6/30，偶尔 15/30，没看过 6/30 | 统计在主导航中，但不放首页首屏 |
| Q16：电脑 22/35，手机 10/35 | 桌面优先，窄屏可用 |

这些决定比我此前方案 B 的"三入口并列"更接近方案 A 的"检索优先"，原因是原先支撑三入口的数字不成立。
