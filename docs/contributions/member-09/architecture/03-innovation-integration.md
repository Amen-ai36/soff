# 创新功能接入架构（成员 9，方案 B）

日期：2026-11-11。阶段：架构设计。分支：`b`。状态：候选设计。

## 1. 现状

任务书要求"至少一项创新"，但团队尚未选定创新功能（统一 SRS 第 37 行：创新候选另立验收）。成员 1 的调研建议优先评估"专家合作网络的增强能力：领域和机构筛选、最短合作路径、中心度展示"，并提醒"仅展示一张网络图不能认定满足创新要求"。

因此本文分两部分：

1. **接入机制**：不管最终选哪项创新，展现层都按同一方式接入，不影响核心页面。这部分不依赖选题结论。
2. **B 组候选**：合作路径探索。作为第一个按此机制接入的模块实现，是否计为团队创新由成员 1、6 与老师确认。

## 2. 接入机制

### 2.1 功能注册表

创新模块不直接写进路由表和页面，而是在 `features/registry.ts` 中登记：

| 字段 | 含义 |
| --- | --- |
| `id` | 功能标识，例如 `collab-path` |
| `title` | 导航中显示的名称 |
| `status` | `candidate`（候选）或 `confirmed`（团队确认） |
| `route` | 该功能的路由，组件懒加载 |
| `navLabel` | 导航入口文字 |

启用哪些功能由构建变量 `VITE_FEATURES` 决定（逗号分隔，未设置时启用全部登记项；设为空字符串时全部关闭）。路由表只注册已启用功能的路由；导航和其他页面中的入口通过 `isFeatureEnabled(id)` 判断是否显示。

### 2.2 四条接入约束

| 约束 | 目的 | 实现方式 |
| --- | --- | --- |
| 只通过 `ApiClient` 取数，不新增后端直连 | 遵守"页面不能直连数据库" | 合作路径只用统计服务的关系边接口（A-13） |
| 创新模块失败不影响核心页面 | 候选功能不能拖垮检索、门户、认领 | 独立路由与懒加载；错误只在该页面内显示 |
| 关闭开关后核心功能完整可用 | 选题变化或演示出问题时可直接下线 | 测试：关闭全部功能后核心路由仍存在 |
| 页面上标明"候选功能" | 不把候选写成已通过的创新 | `status = candidate` 时页头显示候选标识 |

### 2.3 入口位置

| 入口 | 条件 |
| --- | --- |
| 主导航"合作路径" | 功能启用 |
| 学者门户中"查看该学者的合作路径" | 功能启用；链接带上当前学者 ID 作为起点 |

## 3. B 组候选：合作路径探索

### 3.1 用户能做什么

1. 选择两位学者，查看他们之间最少经过几位合作者能联系起来，以及每一步依据的共同成果。
2. 按领域、机构筛选合作关系的范围（筛选在统计服务端执行）。
3. 查看当前范围内合作者最多的学者（度中心性）。

### 3.2 与基础功能的区别

任务书背景中已有"专家关系网络"，统计服务按 SPEC-M8-STATS 第 4 条提供合作边。基础功能只回答"谁和谁合作过"。本候选在此基础上增加两点：

| 能力 | 基础关系 | 本候选 |
| --- | --- | --- |
| 合作边与权重 | 有 | 复用 |
| 两人之间的最短合作路径 | 无 | 有，并列出每一步的共同成果作为依据 |
| 按合作人数排序的中心度 | 无 | 有 |

是否足以构成"创新"不由本文判断。

### 3.3 算法放在哪一层

路径和中心度在浏览器中计算（`domain/collabGraph.ts`，纯函数），输入是统计服务返回的边列表。

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 前端计算（采用） | 不需要后端新增接口；可独立单测；不改公共契约 | 边数很大时浏览器负担重 |
| 后端计算 | 可处理大图 | 需新增公共接口，须成员 1、6 批准；成员 3、8 工作量增加 |

前端计算的适用范围：统计接口按筛选条件返回的边数在几千条以内。如果数据规模上来后关系边过多，应改为后端计算，接口换成"给定两点返回路径"；页面只依赖 `ApiClient`，替换时不改页面。这一条写进 ADR-M9-04 的后果。

### 3.4 算法规则

| 规则 | 内容 |
| --- | --- |
| 图 | 无向图；节点为学者 ID，边为统计服务给出的合作关系，权重为共同成果数 |
| 最短路径 | 按经过的边数最少（广度优先搜索）；起点等于终点时路径为该点自身；不连通时返回"无路径" |
| 确定性 | 相同输入得到相同路径：遍历邻居时按 ID 的码点顺序 |
| 度中心性 | 节点度数 ÷（节点数 − 1）；只有一个节点时为 0 |
| 依据 | 路径中每条边列出共同成果 ID，可点开成果详情核对 |

权重不参与最短路径的计算，只作为依据展示：合作次数多不代表"更近"，用它加权反而难以解释。

### 3.5 已知局限

- 合作边来自共同作者关系，作者消歧出错会直接产生错误路径。页面上写明这一点。
- 合作者信息不是用户最关心的内容：真实问卷 Q14（n=23）中会看合作者信息的为 6 人，低于研究方向（17）和成果列表（14）。所以该功能放在独立页面和门户次级入口，不放首页。
- 当前演示数据是合成数据，路径没有实际学术含义，只用于验证功能。
