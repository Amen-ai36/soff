# 普通用户访谈提纲（成员 9，方案 B 稿）

状态：提纲草案，尚未执行任何访谈。本文是待用的调研工具，不包含访谈结论。待成员 4 共同确认后合为一份提纲；科研人员与管理员部分由成员 3、8 补充（S2 第 5.1 节、S5 第 4.4 节）。

## 1. 用途与限制

本提纲用于探索普通用户查找与判断学术成果的真实过程，验证 [01-general-user-requirements.md](01-general-user-requirements.md) 中的 B-UH01～B-UH07。

限制：本提纲为探索性半结构化访谈工具，样本量小，不用于统计推断。提纲、原始记录、编码分析和结论必须分开归档（S5 第 4.4 节）。提纲本身不构成调研证据。

## 2. 访谈设计

| 项目 | 方案 B 建议 | 说明 |
| --- | --- | --- |
| 对象 | 有文献检索经验的在校研究生或高年级本科生 1～2 人 | 实际身份与经验必须如实记录，不得标注为专家或管理员 |
| 方式 | 半结构化访谈，配合多场景任务对比 | 方案 B 采用多场景法，比较检索、浏览、学者发现三种入口 |
| 时长 | 30～45 分钟 | 超时优先保留第 4、5 节 |
| 记录 | 取得知情同意后记录；使用匿名编号 P-B-01 起 | 公开仓库只保存匿名化摘要 |
| 材料 | 允许受访者展示其常用平台的检索与浏览过程 | 截图需去除个人身份信息 |

若无法接触符合条件的对象，须如实记录限制并改用公开资料分析，不得以同学模拟回答充当真实访谈（S5 第 3 节）。

## 3. 开场与知情同意

1. 说明访谈目的：了解查找学术成果的真实过程，用于课程项目的需求调研。
2. 说明记录方式、匿名处理、材料用途和保存范围。
3. 说明可随时中止、拒答或要求删除某段内容。
4. 取得口头或书面同意后开始，并记录同意时间。

## 4. 背景与多场景任务

| 编号 | 问题 | 目的 |
| --- | --- | --- |
| B-IQ01 | 你目前的研究方向和阶段是什么？ | 建立背景，不作身份推断 |
| B-IQ02 | 你平时查找学术成果主要用哪些平台？为什么选它们？ | 了解竞品使用习惯与选择依据 |
| B-IQ03 | 最近一次需要查找学术成果是为了什么？你是从什么入口开始的？ | 锚定真实场景，验证 B-UH01 |
| B-IQ04 | 如果让你找某个研究领域的代表性论文，你会怎么开始？ | 验证领域浏览场景 |
| B-IQ05 | 如果让你了解某位学者的研究方向和成果，你会怎么找？ | 验证学者发现场景，输入 B-U12 |
| B-IQ06 | 除了论文，你有没有找过专利、科研项目或获奖信息？在哪里找的？ | 覆盖四类成果，验证 B-U03 |

## 9. 提问约束

1. 从真实发生的任务出发，不问"你是否需要某功能""你喜不喜欢这个设计"。
2. 不向受访者描述本平台计划实现的功能后再征求认可。
3. 追问操作步骤、判断依据和具体案例，不追求肯定答复。
4. 一次只问一个问题，不预设答案方向。
5. 受访者跑题到科研人员或管理员议题时，记录下来并转交成员 3、8，不在本提纲内展开。

## 10. 记录与编码规则

原始记录按 `RS-普通用户-序号` 编号，至少包含：采集人、日期、匿名对象编号与实际身份说明、同意情况、方式、原始观察、局限、审查人（S5 第 5 节）。

分析时从记录中提取"场景、入口选择、判断依据、痛点、功能期望、频次或重要性、限制"七项，并回填到 B-U 与 B-UH 编号。没有记录支持的判断保持 `待验证假设`，不因访谈次数少而推出普遍结论。

## 12. 方案 A 与方案 B 的差异

| 维度 | 方案 A（成员 4） | 方案 B（成员 9） | 建议统一方式 |
| --- | --- | --- | --- |
| 访谈方法 | 关键事件回顾法 | 多场景对比法 | 两种方法可结合：先回顾真实任务，再补充场景对比 |
| 场景覆盖 | 以最近一次真实任务为主 | 检索、浏览、学者发现三种场景 | 合并后覆盖全部场景 |
| 问题数量 | 17 题 | 23 题 | 合并去重后控制在 20～25 题 |
| 重点验证 | A-UH01～A-UH06 | B-UH01～B-UH07 | 覆盖两组全部假设 |
| 移动端 | 未明确询问 | 专门询问 B-IQ20 | 保留移动端问题 |
| 引用数 | 未明确询问 | 专门询问 B-IQ09 | 保留引用数问题 |

两个提纲的核心结构一致，方案 B 增加了场景对比、引用数、合作网络、首页布局和移动端问题。汇编时应保留两方的合理问题，不应仅采纳一方而删除另一方的合理考虑。
