# AI辅助工作声明（成员10，第2—6周）

## 1. 声明目的与适用范围

本声明适用于本目录中由成员10独立整理的第2—6周阶段贡献材料，覆盖调研证据质量核查、证据登记、需求追踪与验收核查、跨文档问题记录、汇报内容提纲和交接检查。该材料依据《双组并行开发与合并方案》、当前提供的 `main` 仓库资料及成员5的独立贡献包进行交叉阅读；成员5材料仅用于比对互补证据和口径，不作为成员10工作的前置版本，也未被整包复制或简单改写。

## 2. AI辅助完成的具体工作

生成式AI用于以下辅助工作：

1. 将成员10在第2—6周的职责拆解为可交付的独立文件与检查项。
2. 起草证据登记表，整理证据来源、可支持的判断、局限和后续验证动作。
3. 建立 R01—R15 的个人需求追踪核查视图，关联需求来源、模型/规范覆盖点、验收证据、缺口及建议责任人。
4. 对已提供的问卷汇总人数进行算术复核，并提示需要回到统一报告、Word和PPT同步检查的数字口径问题。
5. 提出跨文档一致性检查问题，包括需求编号、状态模型、验收边界、数据规模证明、证据索引和汇报材料状态。
6. 整理需求调研与需求建模的汇报内容提纲，以及提交前检查清单。

以上是文档整理和静态核查辅助，不等同于已完成正式评审、外部平台复测或系统测试。

## 3. 人工责任与事实边界

成员10应在正式提交前亲自确认文件内容、仓库路径、课程要求和每一项事实陈述，并负责后续提交与修订。AI生成的内容不能单独作为真实执行证据。当前材料没有声称已完成以下事项：

- 对问卷原始答卷进行审计（目前依据的是已提供的汇总资料）；
- 开展真人访谈或将访谈提纲当作访谈结果；
- 重新在线测试所有学术平台或核实所有来源当前可用性；
- 在 CodeArts 中实际创建/导出模型或执行流水线；
- 运行系统、完成端到端测试或取得测试覆盖率结果；
- 召开正式评审会、获得教师/组长批准或完成 GitHub 远程提交。

若上述活动之后实际发生，应由执行人补充日期、执行环境、结果和可核查证据，再更新相应状态；不得仅凭本声明将其标为完成。

## 4. 数字与需求状态的处理规则

- 问卷比例必须保留题目范围、有效分母及多选题说明。Q9 当前核查口径为 19/30 = 63.33%；该结果是基于现有汇总人数的复算，仍需责任人确认并同步统一报告、Word和PPT。
- 课程要求、团队建议、候选设计和实际运行结果分别标注，不互相替代。
- R01—R15 表是成员10的追踪核查视图，不是第二份正式 SRS，也不意味着全部需求已验收。
- 10,000条成果数据是项目要求；没有实际数据清单、入库计数和检索/统计对账证据前，不得写成已达标。
- 对尚未冻结的用例编号、认领申请状态、创新功能范围及一期边界，只记录问题和建议，不代替成员1/6或对应模块责任人作决定。
