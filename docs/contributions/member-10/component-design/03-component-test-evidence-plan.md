# 构件设计测试支撑材料与证据计划（成员10）

## 1. 目标

将构件设计中的可验证规则转换为可复用的测试夹具、测试场景和证据登记，支撑后续A/B同标准比较。该文件是测试设计计划，不是测试报告。

## 2. 最小夹具集合

| 夹具ID | 内容 | 适用构件 | 预期覆盖问题 |
|---|---|---|---|
| FIX-DATA-01 | 同一成果来自两个公开来源，字段略有差异 | 数据库、ETL、去重 | 来源与规范成果分离；重复不重复计数 |
| FIX-DATA-02 | 同名作者但机构/领域信息冲突 | 消歧、学者关系 | 低置信度不自动合并 |
| FIX-DATA-03 | 缺失字段、未知值、空字符串和0混合 | 数据库、ETL、统计 | 空值语义与统计口径正确 |
| FIX-CLAIM-01 | 本人、非本人、管理员、已授权学者四类身份 | 认证、认领、UI | 权限边界、审核回避、授权时点 |
| FIX-CLAIM-02 | 同一门户的并发申请/审核请求 | 事务、API | 最多一个有效授权；失败无半授权 |
| FIX-SEARCH-01 | 公开成果、受限成果、无匹配关键词 | ES、API、UI | 权限过滤影响结果、total和分面；空结果语义正确 |
| FIX-SEARCH-02 | 中英文、缩写、标点、同义词和分页边界 | 检索、排序 | 分词、稳定排序和分页 |
| FIX-TASK-01 | 采集任务成功、失败、停止、重试和部分完成 | 调度、异步API | 状态迁移、检查点、幂等 |
| FIX-STATS-01 | 规模很小且可手工核算的成果集合 | 统计、缓存 | 分母、去重、分类聚合可复算 |
| FIX-SEC-01 | 带有模拟敏感字段的证明对象和访问日志 | API、对象存储、日志 | 未授权不可访问；日志脱敏 |

夹具应使用合成或获准公开数据，并在文件中标注来源和模拟标识；不得放入真实认领证明或个人敏感数据。

## 3. 证据目录建议

```text
docs/test-evidence/
├── shared-fixtures/
├── model-a/
├── model-b/
├── contract/
├── integration/
├── e2e/
├── coverage/
└── deployment/
```

A/B各自的运行日志、测试报告和制品信息分开保存；公共夹具、用例预期和评分口径只维护一份。最终汇编时在同一测试报告中并列展示A/B结果。

## 4. 每次测试证据字段

`evidence_id | test_case_id | requirement_or_spec | branch | commit_sha | build_id | artifact_version | environment | dataset_manifest | command_or_pipeline_url | executed_at | executor | result | defect_id | evidence_path | reviewer`

## 5. 交付物检查

- [ ] 每个用例有唯一ID、前置条件、输入、步骤、预期结果和严重级别。
- [ ] A/B使用相同夹具版本和预期结果。
- [ ] 运行报告记录提交SHA、环境、数据manifest和工具版本。
- [ ] 失败用例关联缺陷；修复后有回归结果。
- [ ] 覆盖率报告能追溯到提交SHA和模块范围。
- [ ] 端到端结果覆盖同批次“采集→清洗→入库→检索→统计”。
- [ ] 部署证据包括制品、部署版本、健康检查和回滚点。
- [ ] 截图和日志脱敏，且不把计划状态冒充实际执行状态。
