# 构件可测试性检查（成员10）

## 1. 检查目的与依据

依据课程任务书第5页“构件设计”要求，数据库设计需包含E-R图、核心表、字段类型/约束/索引、ES映射/分词/分面和缓存；UI设计需覆盖成果检索、学者门户、成果详情、认领申请、采集任务管理和认领审核；接口设计需包含RESTful规范、核心接口和异步任务接口；其他构件还包括爬虫调度、增量更新、检索排序和统计算法。

成员10负责检查这些设计是否能被验证，而不是替代成员2/7、3/8、4/9做设计决策。

## 2. 通用可测试性原则

每个构件至少明确：

1. 可识别输入：字段、类型、必填/可空、边界和合法值。
2. 可观察输出：返回值、持久化状态、事件/任务状态或页面反馈。
3. 可控依赖：测试时能替换数据源、时钟、搜索服务、对象存储或消息组件。
4. 可重复执行：固定夹具和版本；重复运行结果稳定；测试环境可重置。
5. 可注入故障：超时、断连、重复消息、并发请求、部分写入和权限不足可被模拟。
6. 可追踪证据：测试用例关联SPEC/需求、提交SHA、环境、数据版本、结果和缺陷。
7. 安全默认：测试日志和截图不暴露密码、令牌、证明材料正文或真实个人隐私。

## 3. 按构件类别检查

### 3.1 数据库与数据模型（成员3/8主责）

| 检查点 | 可测试性要求 | 建议测试 |
|---|---|---|
| 主键与外键 | ID规则、引用完整性、删除/更新策略明确 | 不存在的外键写入应失败；关联删除行为可预测 |
| 唯一性与去重 | 唯一约束范围明确，来源记录与规范成果分开计数 | 重复来源导入、同成果多来源、冲突唯一键 |
| 空值与默认值 | NULL、未知、0、空字符串语义区分 | 缺失字段、空字段、边界日期 |
| 状态字段 | 状态枚举及合法迁移与SPEC一致 | 非法状态转移被拒绝 |
| 事务 | 认领审核、授权和审计边界清楚 | 中途失败回滚；并发争用最多一个有效授权 |
| 迁移 | 每个迁移有唯一编号、前向与回滚影响说明 | 空库升级、旧版本升级、回滚演练（执行后记录） |
| 索引 | 说明服务的查询条件、排序、选择性与维护成本 | 典型查询计划/响应时间记录，不只凭索引名称验收 |

### 3.2 Elasticsearch/CSS检索索引（成员3/8主责）

- 映射字段须区分可检索、可聚合、可排序和仅展示字段。
- 分词策略须有中英文、缩写、特殊符号、同义词和精确短语测试样例。
- 公开权限过滤必须影响命中结果、total和分面统计，不能只在详情页隐藏。
- 稳定排序须包含可确定的次级排序键，分页翻页不重复、不遗漏（在数据版本不变条件下）。
- 空结果与索引不可用必须有不同错误语义。
- 索引更新需记录版本/批次；支持延迟检测、失败重试、重放或重建。

### 3.3 RESTful API与异步任务接口（成员3/8主责）

- OpenAPI需描述请求/响应schema、必填、枚举、错误响应、鉴权要求和分页结构。
- 同一公共API在A/B中保持路径、语义、字段和错误码一致；实现差异不得泄漏为公共契约差异。
- 认领申请、审核和授权接口需验证本人身份、管理员权限、审核回避、重复提交和并发请求。
- 采集任务提交接口应返回可追踪任务标识；状态查询能区分排队、运行、成功、失败、停止等已批准状态。
- 超时/重试必须有幂等语义；客户端重复提交不能创建无法识别的重复任务。
- API错误不得泄露堆栈、数据库凭据或证明内容。

### 3.4 数据采集、清洗、消歧和增量更新（成员2/7主责）

- 数据源适配器可注入固定响应，不依赖每次访问真实网络。
- 采集任务支持限速、停止、重试、检查点和来源追溯。
- 清洗规则以输入/预期输出样例表达；未知值不被自动替换为0。
- 去重/消歧提供高置信、低置信、冲突和人工修正样例；低置信度不得静默合并。
- 增量更新需验证不覆盖人工修正，失败重试不重复计数。
- 模拟数据应可识别、可隔离统计。

### 3.5 UI与交互构件（成员4/9主责）

- 每个关键页面明确初始、加载、成功、空结果、错误、无权限和重试状态。
- 检索过滤与分页保留查询条件；排序和分页状态变化可观察。
- 认领页面区分“已提交申请”和“已获得维护授权”，不把申请成功显示成认领成功。
- 受控证明材料只向有权限角色展示；页面、浏览器日志和截图不泄露敏感内容。
- 关键操作提供可访问的标签、键盘操作和错误定位。
- E2E测试可通过稳定测试ID或可访问名称定位控件，避免依赖脆弱的屏幕坐标。

### 3.6 统计与分析构件（成员3/8主责，成员2/7提供数据质量输入）

- 明确统计对象、时间范围、去重规则、分母、空值处理和数据版本。
- 提供可手工复算的小样本夹具。
- 同一输入版本重复计算应得到相同结果。
- 统计任务失败不得输出部分结果并标为成功。
- 页面展示统计口径、数据更新时间或版本。

## 4. 设计评审检查清单

- [ ] 每个构件能映射到统一SRS的M1-FR或经确认的SPEC编号。
- [ ] 公共实体、API、错误码、状态枚举没有被某一组单方面改变。
- [ ] 正常、边界、异常、权限、并发、重复和依赖故障场景均有测试入口。
- [ ] 测试夹具不依赖真实账号、收费数据源或不可控外部网络。
- [ ] 数据库迁移、索引重建、缓存失效和任务重试有明确可观察结果。
- [ ] 关键日志具备关联ID且经过脱敏。
- [ ] 设计可支持至少三个核心模块行覆盖率不低于80%的测试目标。
- [ ] 设计图、表、OpenAPI、SPEC与UI状态一致。
- [ ] 未验证的性能目标标记为候选，未把建议值写成课程硬性要求。
