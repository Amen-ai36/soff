# A/B部署、测试与运行保障对照及交接（成员10）

## 1. 对照原则

双组并行方案要求A、B在相同核心需求、公共接口和验收标准下独立实现，使用同一数据集和公共测试验收；最终按功能完整性、缺陷数、覆盖率、性能、代码质量、文档和部署稳定性评分。成员10只对测试、部署、流水线和运行保障岗位进行对照，不替其他岗位决定服务架构或数据库方案。

| 对照维度 | A组（成员5现有供稿） | B组（成员10本次供稿） | 当前结论 |

## 3. 公共测试与差异保留

- 测试用例ID、输入数据、预期结果、严重级别由成员1/6与模块负责人共同确认，A/B不得各自修改预期。
- 构建命令、运行时版本、制品类型、部署脚本可因技术实现不同而不同，必须记录实际值。
- 测试工具不同可以接受，但结果口径、覆盖率计算范围、数据集manifest和缺陷等级必须一致。
- A/B实际测试结果未收齐前，不给出“B组优于A组”或“某组部署更稳定”的结论。

## 4. 建议最终评分维度

| 维度 | 观察证据 | 比较要求 |
|---|---|---|
| 功能完整性 | 公共验收用例通过率 | 同一用例集 |
| 缺陷质量 | 阻断/严重/一般缺陷数量及遗留情况 | 相同缺陷定义和复核流程 |
| 测试质量 | 三个核心模块行覆盖率、边界与异常覆盖 | 相同统计工具或明确换算口径 |
| 性能 | 固定数据集、固定环境下响应时间和吞吐 | 同配置/同负载，记录环境差异 |
| 部署稳定性 | 部署成功、健康检查、回滚演练、故障恢复 | 相同部署步骤和记录模板 |
| 可维护性 | 日志、配置、迁移、文档、可追溯性 | 同一检查清单 |

评分权重由成员1/6和全组确认，本文件不擅自设定权重。
