## 3. 一致性检查清单

### 3.1 业务语义
- [ ] 学者、用户账号和认领授权不是同一个概念。
- [ ] 四类成果具有公共属性，同时保留类型差异。
- [ ] 原始来源记录与规范化成果分开，合并后可追溯。
- [ ] 学者—成果关系支持多作者及单独维护关联。
- [ ] 认领证明与公开门户字段分离。
- [ ] 采集任务包含各处理阶段的成功、跳过、失败计数。
- [ ] 类图没有提前绑定具体数据库、ES 映射或微服务拆分。

### 3.2 异常与权限
- [ ] 空检索结果与服务故障分开。
- [ ] `200 OK` 但返回类型或结构错误仍视为采集失败。
- [ ] `401/403`、验证码和明确拒绝不会触发绕过式采集。
- [ ] `429` 处理遵守来源策略并限制重试。
- [ ] 认领通过与权限建立一致；自审和并发认领冲突被阻止。
- [ ] 数据库成功但索引刷新失败时能重试且不谎报全链路成功。
- [ ] 缺失、未知与数值 0 分开表达。

### 3.3 交付一致性
- [ ] 统一 SRS 中每条 P0 需求均能映射到类、交互或明确标注的非业务要求。
- [ ] 两组使用同一需求编号、数据语义和验收样例。
- [ ] 正式交付物只有一份；成员个人材料放在贡献目录供追溯。
- [ ] 待确认事项未被表述为已批准的公共契约。
- [ ] 评审意见、修改人、日期与修改文件有记录。

## 4. 当前已知缺口（不隐藏）

1. 仓库快照中未发现独立正式 SRS 文件，故暂以统一需求边界 R01–R15 作追踪基线；需成员 1、6确认 SRS 位置与版本。
2. 当前三个时序模型覆盖任务书明确要求的采集入库、认领审核、检索请求；认领后成果维护、统计分析尚需在正式评审中决定是否增加独立时序图。
3. `R12` 创新方向仍为候选，不能把推荐、合作网络或热点预测任意一项写成已批准功能。
4. R15 一期范围需向教师确认，分析模型暂不包含支付或付费下载类。
5. 模型中的字段、状态名和操作名为分析候选，不应直接当作数据库列或接口签名使用。
