# 成员10阶段贡献包（第2—6周）

**角色：B组测试、部署与AI证据岗位；本阶段重点：调研证据核验、需求追踪、交付质量检查与汇报材料组织。**

## 文件目录

| 文件 | 用途 | 第6周前的定位 |
|---|---|---|
| `research/调研证据质量核查.md` | 从证据强度、可复现性、数字口径和合规边界审查调研材料 | 成员10独立核查记录 |
| `research/证据登记表.csv` | 登记证据来源、用途、限制与后续验证动作 | 供统一证据索引合并 |
| `requirements/需求追踪与验收核查表.csv` | 将 R01—R15 与证据、模型、验收证据和缺口关联 | 成员10的追踪核查视图，不是第二份SRS |
| `requirements/需求建模交付核查.md` | 对用例图、活动图、状态图、SRS/SPEC、评审状态逐项检查 | 建模阶段质量门禁 |
| `review/交叉核查问题单.md` | 记录跨成员/跨文档发现的问题和责任建议 | 待团队确认的问题单 |
| `review/修改与决策记录.csv` | 记录修改、决策与关闭证据；未发生的会议/审批不预填为完成 | 可持续更新 |
| `slides/需求调研汇报内容提纲.md` | 需求调研汇报分页内容及证据提示 | PPT制作底稿，不是PPT成品 |
| `slides/需求建模汇报内容提纲.md` | 需求建模汇报分页内容及待确认事项 | PPT制作底稿，不是PPT成品 |
| `handoff/提交前核查清单.md` | 提交前文件、链接、编号、证据边界检查 | 每次提交前执行 |
| `handoff/AI辅助工作声明.md` | 说明本目录的AI辅助范围及人工责任 | 适用于调研/建模文档，不冒充核心代码日志 |
| `references/资料入口与使用边界.md` | 列明本次实际对照的仓库资料和引用规则 | 便于追溯 |

## 本阶段任务边界

依据根目录《双组并行开发与合并方案》：成员5、10在第2—6周共同整理调研证据、参考资料、会议记录和评审问题，并共同支撑需求调研PPT；在需求建模阶段共同维护需求追踪表、规范评审记录、图表编号和建模PPT。成员10不应代替成员1/6冻结公共需求，也不应代替成员2/7编写数据处理SPEC、成员3/8决定认领规则，或声称已在CodeArts完成模型绘制。
