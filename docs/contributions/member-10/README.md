### 4.1 本阶段设计覆盖范围

1. **部署拓扑：** 按外部数据源、访问接入、应用计算、异步计算、关系数据、对象数据、检索数据和工程运维划分部署区域。
2. **组件职责：** 说明 ECS/CCE、RDS、OBS、CSS 及 CodeArts 在候选部署方案中的职责和访问边界。
3. **数据流：** 覆盖采集、原始批次保存、ETL处理、权威数据入库、公开索引更新、检索、认领审核和统计分析。
4. **运行保障：** 设计环境隔离、最小权限、日志脱敏、健康检查、备份、回滚、任务恢复和依赖故障处理。
5. **流水线：** 设计变更检查、代码获取与依赖检查、静态检查与构建、单元测试、API契约测试、集成/E2E、制品归档、测试环境部署、冒烟与回滚检查等门禁。
6. **测试环境：** 规划开发、集成测试、演示/验收环境的数据、账号、配置、资源隔离和准入条件。
7. **A/B比较：** 使用相同测试用例、数据集、结果口径和缺陷等级比较两组，避免仅凭设计描述判断实际优劣。

### 5.1 本阶段质量检查覆盖范围

- **数据库与数据模型：** 主外键、唯一性、空值语义、状态约束、事务、迁移和索引是否可验证。
- **ES/CSS检索：** 字段映射、分词、权限过滤、分面统计、稳定排序、分页、索引延迟和重建能力。
- **RESTful API与异步任务：** OpenAPI schema、错误响应、鉴权、幂等、任务标识、状态查询和异常路径。
- **采集与ETL：** 固定数据源响应、限速、停止、重试、检查点、去重、低置信消歧和增量更新。
- **UI交互：** 加载、成功、空结果、错误、无权限、重试状态；认领申请与授权语义区分；敏感信息保护。
- **统计构件：** 统计对象、时间范围、分母、去重规则、空值处理、数据版本和可复算性。

### 5.2 评审与证据支撑

- 使用评审问题表记录问题编号、来源文件、关联需求/SPEC、严重级别、责任人、截止时间、处理决定和复核证据。

- 使用固定合成或获准公开数据夹具覆盖重复成果、作者消歧、认领权限、并发审核、检索权限、任务失败恢复、统计复算和敏感信息保护。
- A/B两组应使用相同公共测试夹具、预期结果和严重级别；内部实现可以不同，但公共业务语义不能分叉。

### 5.3 汇编与交接

- 本阶段质量检查、评审记录、证据计划和 A/B 质量对照材料交给**成员8汇编、成员3复核**，作为唯一正式构件设计说明书及 PPT 的质量保障支撑。

- 成员10负责检查这些设计是否可验证、可复现、可观察、可注入故障和可留证，不替代上述岗位作出设计决策。

### 5.4 真实性边界

1. 本目录保存成员10个人贡献、候选方案和支撑材料；正式阶段交付物统一维护在 `docs/deliverables/`。
2. B组实现与个人候选材料对应分支 `b`；公共正式文档按团队约定在 `shared-baseline` 或最终 `integration` 分支维护。
3. 公共需求、API、业务实体、状态枚举、错误码和验收口径变更，必须由成员1、6共同确认。
4. A/B两组只对内部实现保留差异；统一文档中并列说明方案A、方案B并形成共同结论。
5. 文件存在、方案写成或 PPT 制作完成，不等于平台配置、评审、测试、部署或课程验收已经完成。
6. 核心代码相关 AI 活动按项目统一要求留存模型使用情况、人工修正案例和审查证据；调研、普通文档撰写和阶段材料整理不冒充核心代码 AI 日志。

**本 README 的作用：** 作为成员10第2—12周阶段贡献的连续索引，保留早期成果并补充后续阶段成果，便于组长、汇编负责人和复核负责人查阅、接收与追溯。
