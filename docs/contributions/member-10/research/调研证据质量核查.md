# 调研证据质量核查（成员10独立工作稿）

版本：1.0（2026-10-13）  
核查类型：对所提供的 `main` 仓库与成员5交接包进行静态交叉阅读；不代表线下访谈、在线复测或教师评审。

## 1. 核查目标

成员10在调研阶段的工作不是重新写一份调研报告，而是检查统一报告中的关键结论是否有可追溯依据、是否把计划写成事实、是否混淆了课程要求和建议值，以及是否给需求建模留下可验收的输入。

本轮核查围绕四个维度：

1. **来源可追溯**：结论能否定位到课程任务书、成员贡献或可识别的操作记录。
2. **证据强度匹配**：问卷只支撑样本内观察；官方资料不等于系统实测；访谈提纲不等于访谈结果。
3. **数值口径一致**：比例保留分子、分母与题目范围，不能将四舍五入后的比例再相加。
4. **需求可验收**：调研结论应能转成需求、模型或验收条件，而不是停留在口号。

### 发现与处理建议

- 统一调研报告当前版本第6.2节将“结果太多（经常或有时）”写成63.34%，建议按人数 `19/30` 统一为63.33%，并检查Markdown和Word是否同步。
- 对高级搜索，需在文字中写明“至少偶尔”还是“偶尔”单一选项；两种统计口径不同。
- 每个问卷结论保留题目、人数、分母和多选属性。若原始答卷不可得，报告应明确不能复核重复填写、发放渠道和缺失值处理。
- 不应编造问卷开放题原话；当前可用材料是汇总统计。

## 4. 对需求建模的转化建议

| 调研观察 | 需求/模型应体现的内容 | 后续可验收证据 |
|---|---|---|
| 用户使用关键词并按领域/类型/年份筛选 | 检索用例应覆盖关键词、组合筛选、分页和排序 | 固定样例集下的查询结果与筛选条件记录 |
| 用户会遇到无结果或结果过多 | 空结果反馈、筛选调整、排序口径应进入需求 | 无结果、过宽查询、组合筛选的验收场景 |
| 同名学者需要上下文 | 结果/认领候选展示机构、领域或代表成果等区分信息 | 同名样例的候选区分与误合并检查 |
| 外部接口可能限流或返回异常页面 | 采集任务需区分失败、重试、停止和成功；校验响应类型 | 429、非预期HTML、超时、停止及重试用例 |
| 来源许可和公开范围不同 | 数据记录保留来源、时间、许可/公开状态及处理记录 | 来源字段完整性和禁止公开数据检查 |
| 认领会改变维护权限 | 认领申请状态与授权动作应有明确约束 | 未批准不可维护、驳回无授权、重复申请等场景 |

## 6. 本轮结论

现有资料足以支撑“形成需求调研初稿并提出需求建模方向”，但不足以证明所有角色需求都经过真人访谈，也不足以证明候选数据源已稳定接入。下一阶段应把本文件第4节中的转化建议落实到统一需求追踪表与验收场景，并由成员1/6确认公共需求边界。
