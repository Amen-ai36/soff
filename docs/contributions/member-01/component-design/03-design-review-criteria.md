# 构件设计评审标准

评审结论使用“通过、需修改、待共同确认”三种状态；没有接口、数据或测试证据的内容不得标记为通过。

| 维度 | 通过标准 | 证据 |
| --- | --- | --- |
| 边界 | 输入输出、所有权、依赖和失败责任明确 | 构件图、接口清单、依赖矩阵 |
| 公共契约 | ID、字段、状态、分页、错误、时间和空值规则与SRS一致 | OpenAPI、实体字典、契约检查 |
| 数据一致性 | 权威事实、索引投影、版本和水位关系清楚 | 发布流程、重放记录、集合对账 |
| 安全与权限 | 认证、授权、回避、自审禁止及证明隔离完整 | 正常/越权/并发验收场景 |
| 可恢复性 | 超时、限流、断电、索引失败和重复重试有路径 | 故障时序、检查点、补偿和告警 |
| 可扩展性 | 百万级目标有容量估算和分档试验，不把目标写成已达成 | 容量表、1万/10万/100万试验计划 |
| 可测试性 | 每个关键规则有可执行夹具、输入、预期和清理方式 | 测试矩阵、契约测试和回归入口 |
| 可运维性 | 日志不泄露证明，指标能定位积压、延迟、失败和版本 | 指标字典、告警规则、恢复手册 |
| 可替换性 | A/B内部实现可通过适配器替换，迁移可回切 | 端口、影子比较、迁移清单 |
| 合规性 | 来源、许可、限速、模拟标记和删除/撤下策略可追溯 | 来源manifest、治理记录 |

## 一票否决项

- 将提交申请当作已授权。
- 只过滤当前页却返回旧total或统计总数。
- 证明材料进入公开索引或日志正文。
- 重试产生重复成果或覆盖人工修正。
- 以文档存在替代实际工程、测试或性能证据。
- 单方面修改公共API、业务实体、数据库语义或验收标准。
