# SRS 目录与系统边界建议

状态：成员 1 方案 A 贡献草案，待成员 1、6 共同确认。本文件只定义统一 SRS 的组织方式和总体边界，不替代各模块 SPEC。

## 1. 建议的统一 SRS 目录

1. 引言
   - 编写目的、范围、术语、引用资料和文档约定。
2. 总体描述
   - 产品定位、系统上下文、用户类别、运行约束、假设和依赖。
3. 系统边界与业务规则
   - 一期范围、不在范围、数据公开边界、身份与认领边界。
4. 功能需求
   - 认证与权限。
   - 数据源与采集任务管理。
   - 清洗、标准化、去重、作者消歧和增量更新。
   - 成果检索、详情与学者门户。
   - 门户认领、审核和成果维护。
   - 机构排名、成果类型、领域分布、关系网络和热点分析。
   - 数据治理、反馈和审计。
   - 创新功能。
5. 外部接口与数据约束
   - 用户界面、外部数据源、公共 API、错误和分页语义；只引用经确认的公共契约。
6. 非功能需求
   - 性能、安全、隐私、可靠性、可追溯性、可用性、兼容性和合规。
7. 验收标准
   - 课程硬性验收、功能场景、数据质量、异常和权限场景。
8. 需求模型
   - 用户故事、用例图、用例说明、认领审核活动图、采集任务和认领申请状态图。
9. SPEC 索引与追踪矩阵
   - SRS 需求到 SPEC、模型、测试和责任人的映射。
10. 待确认问题、变更记录和批准记录。

## 2. 产品定位

平台面向普通用户、科研人员和平台管理员，使用经许可的公开数据或明确标注的模拟数据，完成学术成果的采集、治理、检索、展示、认领和统计分析。成果至少覆盖论文、专利、科研项目和获奖四类，并以学者门户统一呈现。

系统的核心价值不是提供论文全文交易，而是提供可追溯的成果元数据、可信的学者归属、面向公开用户的检索与分析，以及面向管理员的数据治理能力。

## 3. 系统上下文

```text
公开数据源/经批准的导入文件
  -> 采集任务
  -> 清洗、标准化、去重、作者消歧
  -> 规范数据库与检索索引
  -> 检索/门户/认领/统计服务
  -> Web 前台与管理后台
```

外部数据源、CodeArts、邮件或消息服务是依赖系统，不是本平台的受控内部功能。依赖失败必须可识别，不得伪装成正常空结果或成功状态。

## 6. 关键术语与边界

- **账号**：可登录系统并接受权限校验的主体。
- **学者**：由来源数据整理出的科研人员规范档案，不等于平台账号。
- **学者门户**：围绕学者档案组织的公开页面，可处于未认领或已认领状态。
- **认领关系**：账号经审核后获得对指定门户的受限维护授权；不转移成果所有权。
- **成果**：论文、专利、项目或获奖的规范记录，可关联多个学者和机构。
- **来源记录**：外部数据源中的原始标识、采集时间、许可和处理证据；与规范成果分开追溯。
- **公开数据**：经许可和字段级公开审查后可被访客读取的数据。
- **证明材料**：用于认领审核的受限数据，不属于公开成果或门户内容。
- **规范化成果数量**：通过许可检查、清洗和去重后的可公开 canonical 成果数；同一成果的多来源记录不得重复计数。
