# 参与者、用户故事与总体功能需求

状态：成员 1 方案 A 贡献草案。总体需求用于统一各模块供稿，详细算法、字段和接口必须由对应成员在 SPEC 中定义并经公共评审。

## 1. 参与者

| 参与者 | 目标与权限边界 |
| --- | --- |
| 访客 | 无需登录即可检索和查看允许公开的成果、门户与统计；不能提交认领、维护数据或查看受限材料 |
| 登录用户 | 继承访客能力，可提交认领和查看本人申请；不得因提交申请自动获得维护权 |
| 已认领学者 | 继承登录用户能力，可在授权范围内维护本人门户和提交成果补录/纠错；不得删除共享成果本体或修改他人门户 |
| 平台管理员 | 管理采集任务、认领审核、数据治理和审计；不得绕过回避规则审核本人申请 |
| 外部数据源 | 向采集或导入流程提供公开且经许可的数据，是次要参与者，不接受平台权限授予 |
| 定时调度器 | 按获批策略触发增量任务，是自动化次要参与者；不能替代管理员作业务审批 |

管理员可以按后续设计细分采集管理员、审核管理员和系统管理员，但本阶段不自行冻结角色枚举。

## 2. 核心用户故事

| 编号 | 用户故事 | 验收关注点 |
| --- | --- | --- |
| M1-US-01 | 作为访客，我希望按关键词和条件检索成果与学者，以便快速定位可信信息 | 过滤组合、排序口径、分页稳定、来源可见、空结果与故障区分 |
| M1-US-02 | 作为访客，我希望浏览学者门户及四类成果，以便了解其研究产出 | 四类栏目、缺失值表达、认领状态、隐私隔离 |
| M1-US-03 | 作为登录用户，我希望提交门户认领并查看进度，以便获得本人门户维护权 | 证明材料受控、重复申请、状态反馈、申请不等于授权 |
| M1-US-04 | 作为管理员，我希望基于证据审核认领，以便防止冒领 | 回避、理由、并发占用、状态与授权原子一致、审计 |
| M1-US-05 | 作为已认领学者，我希望补充本人信息并纠正成果关联，以便保持门户准确 | 授权范围、共享数据保护、版本冲突、修改留痕 |
| M1-US-06 | 作为管理员，我希望配置并控制采集任务，以便安全、可恢复地更新数据 | 来源许可、限速、停止、重试、部分失败、处理进度 |
| M1-US-07 | 作为管理员，我希望查看清洗、去重和消歧结果，以便处理不确定或冲突数据 | 规则版本、置信度、人工复核、不可静默丢弃 |
| M1-US-08 | 作为访客，我希望查看排名、分布、关系和趋势，以便理解机构与领域情况 | 去重口径、未知值、时间范围、来源版本、可追溯 |

## 3. 总体功能需求

| 编号 | 总体需求 | 优先级 | 主要责任供稿 |
| --- | --- | --- | --- |
| M1-FR-01 | 系统应支持账号登录、退出、会话失效处理和服务端权限校验；错误不得泄露账号是否存在 | P0 | 成员 3、8 |
| M1-FR-02 | 管理员应能创建、启动、停止、查看和重试采集任务；任务必须保留来源、批次、时间、状态和错误摘要 | P0 | 成员 2、7 |
| M1-FR-03 | 系统应从经批准的公开 API、数据集或导入文件接收四类成果；拒绝未授权或审批未通过的数据公开入库 | P0 | 成员 2、7 |
| M1-FR-04 | 系统应执行清洗、标准化、去重、作者消歧和机构归一化，并保存规则版本、处理结果与不确定项 | P0 | 成员 2、7 |
| M1-FR-05 | 系统应支持增量更新和失败恢复；更新不得静默覆盖人工修正，数据库与检索索引差异必须可检测 | P0 | 成员 2、7、3、8 |
| M1-FR-06 | 访客应能检索公开成果和学者，并按成果类型、时间、机构和领域过滤，支持分页和明确的排序口径 | P0 | 成员 3、8、4、9 |
| M1-FR-07 | 访客应能查看成果详情、来源、更新时间及学者门户；门户按论文、专利、项目、获奖组织成果 | P0 | 成员 3、8、4、9 |
| M1-FR-08 | 登录用户应能对可申请门户提交认领；系统应校验材料访问权、重复申请和门户占用，创建申请但不立即授权 | P0 | 成员 3、8 |
| M1-FR-09 | 非申请人的授权管理员应能有理由地通过或驳回申请；通过结果、门户授权和审计记录必须一致 | P0 | 成员 3、8 |
| M1-FR-10 | 已认领学者应能在授权范围内维护个人字段、提交成果补录或关联纠错；共享元数据冲突进入治理流程 | P0 | 成员 3、8、4、9 |
| M1-FR-11 | 系统应按去重成果提供机构排名、成果类型分布、领域分布等基础统计，并展示统计时间、范围和未知值 | P0 | 成员 3、8 |
| M1-FR-12 | 系统应提供基于共同成果的专家关系和按时间的领域热点分析；不得将同名学者自动视为同一人 | P0 | 成员 3、8 |
| M1-FR-13 | 管理员应能处理数据纠错、隐藏、合规状态和冲突，关键操作必须可审计 | P0 | 成员 2、3、7、8 |
| M1-FR-14 | 系统应能使用同一批次数据演示采集、清洗、入库、检索和统计完整链路，并关联各阶段计数 | P0 | 全体技术岗位 |
| M1-FR-15 | 系统应实现至少一项经成员 1、6 和课程评审确认的创新功能，并为其建立单独验收标准 | P0 约束 | 待决策 |

## 4. 需求关系和约束

- M1-FR-08、09、10 依赖 M1-FR-01，但“登录”不等于“已认领”或“管理员”。
- M1-FR-06、07、11、12 只能读取许可通过且允许公开的数据，依赖 M1-FR-03、04、05。
- M1-FR-14 是端到端验收，不得用五段相互无关的演示代替同一批次链路。
- M1-FR-15 的创新功能不能替代 M1-FR-11、12 的基础统计范围。
- 认领通过只建立受限维护授权，不改变成果的知识产权归属，也不自动允许公开证明材料。
