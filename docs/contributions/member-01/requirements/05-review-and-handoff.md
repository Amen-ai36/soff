## 3. 建议提供给统一 PPT 的成员 1 内容

1. 一页“系统边界”：一期必做、后期增值服务待确认、公开数据与证明材料隔离。
2. 一页“参与者与全局用例图”：突出账号、学者、门户和认领关系的区别。
3. 一页“总体需求与完整链路”：四类成果、10,000 条、采集到统计的同一批次追溯。
4. 一页“非功能与验收”：合规、权限、可追溯、故障区分，以及量化阈值仍需冻结。
5. 口头说明：两组核心需求相同，模型和实现方案可以不同；本包是 A 组输入，唯一正式 SRS 由成员 6 汇编、成员 1 复核。

## 4. 可能问答准备

| 问题 | 回答要点 |
| --- | --- |
| 为什么账号和学者要分开？ | 来源数据可先形成学者档案；只有审核通过的账号才获得门户维护授权，避免输入学者 ID 即越权 |
| 10,000 条如何计数？ | 以许可通过、清洗去重后的规范成果计数，多来源不重复；数据库和索引需对账 |
| 如何防止冒领？ | 证明材料受控、重复/占用检查、管理员回避、有理由决定、并发控制、状态与授权原子一致、全程审计 |
| 外部接口失败为什么不能返回空结果？ | 空结果是业务事实，依赖失败是系统状态；混淆会误导用户和统计，也无法恢复与追踪 |
| 两个小组如何保证能合并？ | 共享 SRS、数据语义、验收场景和冻结输入；各组可采用不同内部算法，最终按同一测试选择主版本并逐模块迁移 |
