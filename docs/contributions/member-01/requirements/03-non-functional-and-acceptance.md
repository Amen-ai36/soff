# 非功能需求与验收基线建议

状态：成员 1 方案 A 贡献草案。标记“课程硬约束”的条目可直接追溯到任务书；标记“建议冻结”的量化值必须由成员 1、6 与相关负责人确认，当前不得宣称已达标。

## 1. 非功能需求

| 编号 | 类别 | 需求 | 验证方式 | 状态 |
| --- | --- | --- | --- | --- |
| M1-NFR-01 | 数据规模 | 去重且允许公开的规范化成果不少于 10,000 条，并能用于检索和统计 | 数据库计数、索引计数、随机抽查和端到端演示 | 课程硬约束 |
| M1-NFR-02 | 合规 | 只采集经许可的公开数据或明确标注的模拟数据；不绕过访问控制，不公开受限全文、隐私和认领证明 | 数据 manifest、许可快照、公开字段扫描 | 课程硬约束 |
| M1-NFR-03 | 安全 | 认证、授权和资源归属在服务端校验；越权、自审、伪造角色和过期会话不能导致写入 | 权限矩阵和负向接口测试 | 建议冻结原则，角色细分待确认 |
| M1-NFR-04 | 隐私 | 证明材料和私有联系方式不进入公开响应、检索索引或日志正文；敏感操作保留最小必要审计信息 | 响应、索引和日志字段检查 | 建议冻结原则，保留期限待确认 |
| M1-NFR-05 | 可追溯 | 公开成果可追溯到来源、采集批次、处理规则和更新时间；审核与人工修改可追溯到操作者和版本 | 抽样沿链路反查 | 建议冻结 |
| M1-NFR-06 | 数据质量 | 未知、缺失和真实 0 分开表达；重复和消歧不确定项进入人工复核，不能静默删除 | 标注样本、边界样本和处理日志 | 建议冻结，阈值待确认 |
| M1-NFR-07 | 可靠性 | 外部依赖失败、业务空结果和部分失败必须区分；任务停止、重试和恢复不造成不可解释重复 | 故障注入和恢复测试 | 建议冻结 |
| M1-NFR-08 | 一致性 | 同一静态输入、规则版本和参数应得到可复现结果；数据库和索引差异可检测并修复 | A/B 同 manifest 重跑和对账 | 建议冻结 |
| M1-NFR-09 | 性能 | 在统一硬件、统一 10,000 条以上数据和统一脚本上报告检索及统计 P50/P95、吞吐和错误率 | 基准测试报告 | 必须报告；具体阈值待确认 |
| M1-NFR-10 | 可用性 | 关键操作显示加载、成功、失败、无权限和空数据状态；表单错误能定位到字段，键盘操作和文字对比度可检查 | 任务走查和可用性检查 | 建议冻结；移动端范围待确认 |
| M1-NFR-11 | 可维护性 | 核心模块编码前存在经评审的 SPEC；规则、接口和测试可追踪，配置不硬编码密钥 | SPEC/代码/测试追踪检查 | 课程硬约束 |
| M1-NFR-12 | 可部署性 | 在 CodeArts 完成代码托管、检查、构建、测试、流水线和部署证据 | CodeArts 运行记录 | 课程硬约束，后续阶段执行 |

## 2. 课程级验收基线

| 编号 | 验收条件 | 证据要求 |
| --- | --- | --- |
| M1-AC-01 | 背景必做功能全部实现；一期范围歧义已得到书面确认 | 最终 SRS、范围决策和功能验收记录 |
| M1-AC-02 | 至少一项创新功能实现并按独立场景验收 | 创新 SPEC、演示和测试记录 |
| M1-AC-03 | 规范化成果数据不少于 10,000 条，且支持检索与统计 | 数据 manifest、去重后计数、索引计数和抽查 |
| M1-AC-04 | 演示同一批次“采集 -> 清洗 -> 入库 -> 检索 -> 统计”完整链路 | 批次 ID、各阶段计数、页面或接口结果 |
| M1-AC-05 | 用例图覆盖六类指定用例，参与者及关系正确 | CodeArts Modeling 源文件和清晰导出图 |
| M1-AC-06 | 认领审核活动图覆盖提交、验证、审核、通过/驳回及异常 | 源文件、导出图和对应文字用例 |
| M1-AC-07 | 采集任务与认领申请状态图覆盖任务书规定状态及合法流转 | 源文件、导出图、状态说明和反向场景 |
| M1-AC-08 | SRS 完整且与用户故事、模型、SPEC 表述一致 | 追踪矩阵和评审记录 |
| M1-AC-09 | SPEC 至少覆盖数据清洗、去重、作者消歧和检索排序规则 | SPEC 目录、评审记录和后续代码映射 |
| M1-AC-10 | 课堂展示和终稿材料齐全，展示后反馈逐项记录和验证 | PPT、Word、模型、修改记录、自查清单 |

## 3. 总体功能的场景化验收

| 场景 | Given | When | Then |
| --- | --- | --- | --- |
| M1-E2E-01 合规采集链路 | 已批准来源、固定 manifest 和新批次 | 管理员运行采集到统计 | 各阶段共享批次标识；失败可定位；最终计数能与来源和去重结果对账 |
| M1-E2E-02 重复与消歧 | 含跨源重复成果、同名异人和别名样本 | 执行清洗、去重和消歧 | 重复成果只形成一个规范记录且保留多来源；同名异人不被错误合并；不确定项进入复核 |
| M1-E2E-03 公开检索 | 已完成公开范围审核且索引可用 | 访客组合过滤、排序和分页 | 只返回公开记录；条件和总数明确；固定版本翻页不重不漏 |
| M1-E2E-04 依赖故障 | 检索或统计依赖不可用 | 用户发起查询 | 返回可识别失败和追踪标识，不伪装成 total=0 |
| M1-E2E-05 门户认领 | 门户未认领且用户已登录 | 用户提交有效申请 | 生成待审核申请但无维护权；材料不公开；本人可查进度 |
| M1-E2E-06 审核与授权 | 待审申请且审核者不是申请者 | 管理员通过或有理由驳回 | 通过时状态与授权一致；驳回无授权且保留理由；并发占用只允许一个通过 |
| M1-E2E-07 授权维护 | 用户已获得指定门户授权 | 修改个人字段并尝试删除共享成果 | 允许范围内修改成功并留痕；共享成果删除被拒绝或进入治理流程 |
| M1-E2E-08 统计口径 | 固定公开数据快照包含未知字段和多机构成果 | 查看排名、分布、关系和趋势 | 返回快照时间、口径和未知类；去重规则一致；缺失不当作真实 0 |

## 4. 待共同冻结的量化建议

成员 2、7 已建议：来源字段完整率 100%、核心必填字段完整率不低于 99%、至少 200 对去重标注样本、至少 200 条消歧独立样本、检索索引与数据库公开记录数差异不高于 0.1%。成员 8 建议在统一 10,000 条数据、10 并发、预热后连续 5 分钟的环境中，以检索 P95 不高于 2 秒、简单统计 P95 不高于 3 秒为候选目标。

以上数值具备可测试性，但样本构成、硬件、统计方法和课程工作量尚未共同确认。本贡献包只保留候选值，不能写入“已通过”结论。
