# 成员1功能实现与合并门禁

## 开发前

1. 成员1/6确认公共 API、实体、状态、错误码、分页和验收标准。
2. 每个模块先提交 SPEC，再开始核心代码。
3. A组成员在 `a` 分支开发，B组成员在 `b` 分支开发，不直接改另一组实现。

## 每次同步

1. 成员负责人提交代码、测试命令、结果、已知缺陷和变更说明。
2. 成员1更新 A 组台账；成员6更新 B 组台账。
3. 两组用同一公共测试数据和验收用例比较结果。
4. 契约变更先暂停合并，提交影响范围、兼容方案和迁移步骤。

## 合并前

- 构建和启动命令真实可执行。
- 核心测试、契约测试和异常路径有证据。
- 数据规模、来源、模拟数据和失败记录可追溯。
- 数据库迁移、OpenAPI、前端字段和 SPEC 一致。
- 选择主版本后逐模块迁移，不机械合并两套实现。
- 成员1和成员6共同确认主版本、差异表和迁移清单。

## 当前结论

本目录完成成员1的功能实现阶段协调基线，但 A 组核心实现尚未从远程分支提交，因此不能标记功能完成或进入最终合并。
