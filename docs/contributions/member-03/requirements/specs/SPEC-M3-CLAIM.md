# SPEC-M3-CLAIM：门户认领、审核与维护 v0.1

状态：方案 A 候选；用例 UC3-04/05/06/08；验收 AC3-12～20、24。输入：目标学者 ID、本人证明引用、说明、幂等键；审核决定/理由/预期版本；维护允许字段/版本。输出申请 ID、状态、版本、权威修改结果或治理请求编号。账号身份由服务端取得。

## 1. 认领创建

检查会话、目标存在且可申请、材料引用非空且归本人、门户未占用。同用户同门户最多一个待审申请；不同用户对未占用门户可各提交待审，审核时争用唯一授权。重复请求按幂等语义返回原结果，同键不同内容冲突，不因重试创建额外申请。

有效创建进入 PENDING，仅授予本人查询申请权。姓名相同、存在 ORCID 或引用了公开成果均不能单独自动通过真实身份审核。证明组合标准由成员 1/6 确认，当前只能用合成材料说明流程。

## 2. 状态与审核

| 当前状态 | 事件及守卫 | 结果 | 授权 |
| --- | --- | --- | --- |
| 未创建 | 有效提交 | 新 PENDING | 不授予 |
| PENDING | 非本人管理员通过，版本一致、门户空闲、证据满足批准标准 | APPROVED | 原子建立 |
| PENDING | 非本人管理员有理由驳回，版本一致 | REJECTED | 不新增 |
| PENDING | 本请求发生占用/版本/事务失败 | 不提交本请求变更，读取最新状态 | 不产生局部授权 |
| APPROVED/REJECTED | 新审核请求 | 拒绝冲突；相同幂等重放返回旧结果 | 不改变 |
| REJECTED 的旧记录 | 补充后重新提交 | 旧记录保持终态，新 ID 进入 PENDING | 不授予 |

草稿/上传中属于 UI 状态，不持久化为审批状态。证据不足经审核有理由驳回，申请人补充后新建申请关联旧 ID。撤回、申诉、授权撤销和门户转让需专门规则，未默认实现。

审核必须服务端检查职责和非本人，写理由，提交时再次校验版本和占用。通过决定、门户唯一授权和审计在同一事务或等价原子机制提交，任一步失败无部分成功。两个申请同时通过只能一个成功；失败请求不伪造另一个申请的驳回，也不回滚另一个已提交结果。管理员可根据最新占用另行有理由处理。

通知独立于审核事务，通知失败记录重试，申请查询反映已保存决定。过期版本刷新后重新核验，不自动沿用旧决定。

## 3. 维护和治理

- 自有门户字段候选白名单：个人简介、研究兴趣；机构身份等来源规范字段不能随意改为自我认证事实。
- 成果补录和 DOI/题名/项目号等公共字段纠错进入治理，不直接覆盖来源。
- 本人移除展示关联只影响本人视图；不删除公共成果、他人关联或原始作者证据。公开合作网络仍以经治理确认的规范作者关系计算，避免隐藏按钮无意改变公共统计。
- 每次修改检查当前授权、预期版本和允许字段，保存修改人、时间、前后版本与依据。源数据更新遇人工值冲突保存两者并转治理，不静默覆盖。
- 已保存与已发布分开反馈；索引失败保留待同步及权威版本。下线/隐私变更按权威策略立即约束公开读取。

## 4. 异常和验证

他人材料拒绝，材料失效不得自动通过；申请无权查询不泄露存在性。会话失效、自审、门户已占用、非法字段、过期版本明确失败。受限材料不进入门户、搜索、统计或日志正文，审计仅保留必要引用与决定。

模型源文件与本状态表一致。后续接口测试覆盖创建、幂等、无权、并发审核、事务回滚、通知失败、驳回重提和维护边界；真人证明标准和防冒领效果待真实复核。
