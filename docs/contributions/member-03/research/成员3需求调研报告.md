## 1. 调研问题与方法

本次围绕五个问题开展调研：

1. 公开用户如何检索成果、科研人员和机构，并判断结果是否可信。
2. 平台生成的作者页如何由本人认领，管理员如何防止冒领。
3. 认领后哪些内容可由本人维护，哪些修改必须保留来源并经过审核。
4. 管理员如何创建、停止、重试采集任务并判断数据链路是否完成。
5. 竞品公开说明与实际可访问能力是否一致。

调研样本为 OpenAlex、Semantic Scholar、ORCID、dblp 和 ResearchGate。它们分别代表开放学术图谱、论文发现工具、研究者身份记录、专业书目库和学术社区。

本次采用三层证据：

- 实际操作：在未登录、无专用凭证的公开环境中打开页面或调用公开接口，记录结果、响应状态和返回类型。
- 官方资料：阅读平台官方帮助中心、产品页和数据说明，确认认领、维护、统计和可见性规则。
- 需求推导：把实际观察与课程任务书映射为候选流程和待验证需求，明确标注尚未开展真实访谈。

没有绕过安全验证、登录墙、验证码或限流，也没有提交认领申请和修改任何外部数据。

## 2. 实际操作记录

统一检索主题采用 `graph neural network`。详细证据与复核入口见[证据记录与复核事项](证据记录与复核事项.md)。

### 2.1 OpenAlex

网页端 `https://openalex.org/works` 在本次浏览器访问中进入 Cloudflare 安全验证，未继续操作。公开 Works API 可正常访问。

使用 2023 年以后、成果类型为 article 的过滤条件，默认相关性排序返回 292,697 条候选，前 3 条分别为：

1. `Targeted Branching for the Maximum Independent Set Problem Using Graph Neural Networks`。
2. `A Survey of Graph Neural Networks for Recommender Systems: Challenges, Methods, and Directions`。
3. `Spatio-Temporal Graph Neural Networks for Predictive Learning in Urban Computing: A Survey`。

相同查询改为按引用量降序后，头部出现 `Exploiting Generative AI to Scale up Intelligent Tutoring Systems` 和 AlphaFold 3 论文等偏离主题的结果。这说明“高引用”不能简单替代文本相关性；排序字段、搜索分数和筛选条件必须分别解释。

结论：OpenAlex 适合验证结构化搜索和来源字段，但其公开实体页不能替代本项目的“本人认领 + 管理员审核 + 门户维护”流程。

### 2.2 Semantic Scholar

公开搜索页在本次浏览器访问中加载超时，页面没有形成可读结果；同一主题的 Academic Graph API 请求返回 `429 Too Many Requests`，未进行密集重试。

官方产品页和 FAQ 说明其支持论文/作者搜索、过滤、作者页认领、论文归属维护、推荐和提醒。由于本次实际查询失败，这些能力在报告中标为“官方说明”，不能写成已完成界面实测。

结论：系统必须为限流和依赖失败提供明确反馈；推荐与提醒可以是增强功能，但不能替代基础检索。

### 2.3 ORCID

通过公开 Search API 查询姓名 `Geoffrey Hinton`，返回唯一 ORCID：`0000-0002-8063-7209`。继续读取公开记录可以得到姓名 `Geoffrey Hinton`。使用独立端点复核后，公开可见的 Employment 有 1 个分组，Works、Funding 和 Peer Review 分组为 0。

这不是在判断该学者没有成果，而是说明“身份 ID 可查”与“门户资料完整”是两件事。公开记录可能受用户维护、来源写入和可见性设置影响。

官方资料还说明：用户可以设置内容可见范围；可信组织必须获得授权，并且只能修改或删除自己写入的条目。

结论：本项目应记录字段来源和写入主体；缺失值不得显示为事实上的 0，也不能只因存在 ORCID 就认为成果清单完整。

### 2.4 dblp

请求 dblp publication search API 时，HTTP 状态为 `200`，但 `Content-Type` 是 `text/html`，正文是 Anubis 反自动化验证页，不是 JSON 搜索结果。

这一观察暴露出重要异常：只检查 HTTP 状态会把挑战页面误判为成功响应。采集端必须同时校验状态码、内容类型、响应结构和业务字段。

dblp 官方 FAQ 说明其使用唯一 person key 与别名处理同名/异名；用户不能直接修改作者数据，需要提交人物键、文献键和消歧证据，由维护团队处理。

结论：作者消歧需要稳定 ID 和人工复核；用户纠错不应直接覆盖规范数据。

### 2.5 ResearchGate

公开研究者搜索请求本次返回 `403 Forbidden`，无法验证未登录搜索体验。官方 Authorship 和 Stats 帮助页可以访问并返回完整 HTML。

官方资料区分“认领已有成果”和“创建新成果页面”，全文上传另行确认权利；个人 Stats 包含阅读、引用、推荐等指标，并对计数规则和覆盖不足作出说明。

结论：已有成果认领、新成果补录、全文上传必须拆成不同用例；统计指标必须标明来源、更新时间和口径。

## 3. 同类平台对比

| 平台 | 公开检索 | 学者门户 | 认领/维护 | 统计与追溯 | 本次实测边界 |
| --- | --- | --- | --- | --- | --- |
| OpenAlex | 多实体搜索、字段过滤和排序能力强 | 作者、机构是图谱实体 | 未核验面向作者的完整认领闭环 | 标识符、来源位置、引用量等字段丰富 | UI 被安全验证拦截；API 查询成功 |
| Semantic Scholar | 官方说明支持论文/作者搜索与过滤 | 自动作者页 | 可申请认领并维护作者信息和论文归属 | 引用、推荐、提醒 | 搜索页超时；API 返回 429 |
| ORCID | 以身份和记录连接为主，不是全文搜索平台 | 用户控制的身份记录 | 用户授权可信组织，按写入来源维护 | 字段来源和可见性清晰 | 姓名检索成功；公开记录内容可能为空 |
| dblp | 计算机领域书目搜索 | 唯一作者页和别名 | 邮件勘误，用户不能直接修改 | person key、publication key 便于追溯 | 200 响应实际为反自动化 HTML |
| ResearchGate | 公开搜索本次不可验证 | 研究者资料与成果页 | 认领已有成果或创建新成果页 | 阅读、引用、推荐等指标 | 搜索 403；帮助页可访问 |

不能直接选择某一个竞品照搬。本项目需要组合：OpenAlex 式结构化检索、ORCID 式来源分权、Semantic Scholar/ResearchGate 式认领、dblp 式人工消歧，以及可解释的统计口径。

## 4. 科研人员与管理员诉求

以下内容是基于任务书、平台观察和流程分析形成的需求假设，不是访谈结论。

### 4.1 科研人员

- 能通过姓名、机构、领域、成果和稳定标识找到候选门户，并区分同名人员。
- 发起认领前能看到材料要求、用途、公开范围和处理过程。
- 能查看申请状态，并在材料不足或驳回时获得可行动的反馈。
- 认领后能维护个人门户、补充遗漏成果、移除错误关联和提交字段纠错。
- 一名作者移除本人关联时，不会删除其他作者仍需使用的公共成果。
- 能理解“系统已收录”“本人已认领”“管理员已认证”的差异。
- 查看引用、阅读或排名时，能看到数据来源、更新时间和计数口径。
- 能请求更正、隐藏或删除个人信息，认领证明不在公开页面展示。

### 4.2 管理员

- 在审核页看到目标门户来源、证明完整性、重复申请和同名冲突。
- 审核动作记录依据、审核人和时间，并支持回避、复查和争议处理。
- 能创建、停止和重试采集任务，查看各阶段成功、重复、跳过和失败数量。
- 遇到 `401/403/429`、验证码、内容类型异常或许可问题时停止并转人工。
- 能识别数据库、检索索引和统计结果之间的不一致，并执行幂等修复。
- 能追溯字段来源、处理版本、合并依据和历史变更。
- 敏感证明、审核备注、密钥与公开成果数据分权存储和访问。

## 5. 四条核心业务流程

### 5.1 检索与查看

1. 用户输入关键词，选择成果类型、领域、作者、机构、年份和排序方式。
2. 系统校验条件，仅在允许公开的索引范围内检索。
3. 结果返回稳定 ID、题名、作者/机构、类型、年份、来源和排序说明。
4. 用户查看成果详情或学者门户；页面明确区分系统生成门户与已认证门户。
5. 无结果时保留原条件并给出放宽建议；同名作者展示机构、领域、ORCID/来源 ID 等消歧信息。

异常要求：统计缺失显示“暂无数据”而不是 0；依赖服务失败不得回退到未授权数据；排序变化应可解释。

### 5.2 门户认领与审核

1. 登录用户选择未认证门户，查看材料用途、可见范围和保留说明。
2. 用户提交最小必要证据，系统检查重复申请、门户占用和材料完整性。
3. 管理员核对来源、账号历史、同名风险和证明，记录审核依据。
4. 通过后建立账号与门户的认证关系；需补充或驳回时提供原因。
5. 证明材料进入受限存储；公开页面只展示认证结果。

候选状态为草稿、已提交、待审核、需补充、已通过、已驳回、已撤回。正式名称和值域必须在后续 SPEC 中确定。

### 5.3 认领后的成果维护

1. 系统区分门户自有字段、成果关联关系、规范成果字段和受限字段。
2. 个人简介、研究兴趣等门户字段可按批准规则更新并产生版本。
3. 新增/移除成果关联形成关系变更，检查作者、机构和标识符冲突。
4. DOI、正式题名、来源项目号等规范字段只能提交纠错，不直接覆盖来源记录。
5. 通过的变更触发门户、索引和统计增量更新，并保留前后值、来源和审核记录。

异常要求：来源更新与用户纠错冲突时进入复核；索引刷新失败保留待同步状态并可重试；全文上传与元数据维护分离。

### 5.4 采集任务与更新

1. 管理员选择已批准来源、范围、时间窗口、限速和是否模拟运行。
2. 系统冻结任务配置，记录创建人、许可规则和版本。
3. 采集服务按限速获取数据，并校验状态码、内容类型、响应结构和业务字段。
4. ETL 完成校验、清洗、去重、消歧和审批分流；未知或冲突项进入隔离/人工队列。
5. 合格数据写入规范存储，再更新索引和统计；各阶段分别计数。
6. 任务返回最终状态和可定位错误，失败项可幂等重试。

异常要求：`401/403`、验证码或明确拒绝立即停止；`429` 遵守 `Retry-After`；停止请求不再派发新工作；HTTP `200` 但内容类型或结构错误仍判为失败。
