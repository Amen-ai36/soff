# SPEC-M3-DESIGN-001 · 设计模型与可执行试验 v0.1

状态：成员三内部候选；2026-11-11。本SPEC仅规定本轮设计资产与其校验，不替换公共SRS、四项业务SPEC或AC3验收。依据 SPEC-M3-AUTH/SEARCH/CLAIM/STATS、AN-I01～08、分工§5.4/5.5。

## 1 目标与边界

输出存储/检索/业务/一致性架构、关系模型、索引映射、接口草案、需求追踪和真实试验记录。不上线系统、不连接真实数据、不冻结公共字段或选定框架；不以SQLite试验证明生产引擎并发、ES能力或HTTP契约已通过。

## 2 输入输出

- 输入：16条M3需求及原用例/SPEC/24验收编号，已复核分析模型，成员1/2/4与B组总体架构。
- 模型：内部SQL表名使用小写蛇形，ID非空字符串，年份整数1000～9999或null，四类成果及三态申请沿用既有候选；版本为正整数，模拟标记为0/1。SQL时间字段使用带时区ISO文本，由服务层校验，本模型不声称SQLite校验了时区。
- 输出：只读文档、Mermaid图源、SQL正向/回退模型、OpenAPI 3.0.3 JSON、ES字段映射JSON、CSV追踪、JSON验证结果。OpenAPI所有新路径/字段均带草案状态，不能对外冒充已批准接口。

## 3 正常与异常流程

SQL仅在临时SQLite库执行，启用外键；每个试验重建夹具，事务失败必须回滚。审核试验使用条件版本写，决定、授权、审计、通知事件和幂等结果同事务。注入任一写点故障后应与事务前状态相同。第二个门户占用请求不得改变其PENDING状态；旧版本不得影响已完成终态。

批次与outbox通过外键和唯一键验证关联。公开数据集版本固定成果revision，发布指针及水位同一事务；集合核验需比较完整ID和投影哈希，条数相等不充分。策略版本变化必须阻断候选发布；此发布控制仅用设计试验说明，真实Worker待实现。

## 4 核查规则

1. 追踪表与原16条需求集合一致，use_case/spec/acceptance对应集合不漂移，24项AC定义均被映射；映射是设计覆盖，不算AC执行通过。
2. 本轮所有相对链接存在、Markdown围栏成对、JSON能解析；所有OpenAPI内部引用、路径参数、operationId、安全声明和写入版本/幂等参数一致。
3. 严格映射拒绝未声明字段，排除凭据、私有证明与审核内容；成果与学者索引区分，不把姓名设唯一键。
4. SQL正向建模、回退、重建均成功；完整性检查无错误；唯一、外键、年份、类型及版本约束拒绝非法写入。
5. 申请终态不可修改；通过申请对应唯一决定与授权，审核试验覆盖自审、第二次终态、冲突和故障；生产环境服务层仍负责职责与材料核验，SQL不是完整权限系统。

## 5 通过标准及限制

静态检查和全部列明设计试验无失败，结果记入 validation-results.json 与人工可读报告。发现缺陷先加入复现断言，再修改模型并复跑。脚本不捕获异常后假报PASS，不降低断言。

未执行项明确列出：真实HTTP/OpenAPI官方验证器、生产数据库并发锁与死锁、会话/CSRF、真实ES映射部署/召回/排序、百万规模、故障恢复、真人证明及人工评审。运行系统覆盖率不由设计试验推算。
