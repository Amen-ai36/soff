## 2 小样本与可复算数据

以下是设计时的算例，用来说明口径，**不是测试结果**。

### 2.1 增量固定输入

旧快照有 P1～P4，P1 含已批准的人工标题。本轮来源数据：P1 改标题，P2 不变，P3 明确撤回，P4 改普通字段，新增 P5。

| 键 | 分类 | 依据 |
| --- | --- | --- |
| P1 | `update` + 冲突 | 来源标题变化与人工值冲突；并存两份证据，继续用人工值 |
| P2 | `unchanged` | 同键同哈希 |
| P3 | `withdraw` | 来源明确撤回；触发 epoch 递增 |
| P4 | `update` | 普通字段变化 |
| P5 | `new` | 新键 |

完整输入：`new` 1，`update` 2（其中 1 个同时冲突），`unchanged` 1，`withdraw` 1，失败 0。把 P3 换成"本轮没有返回"的缺页变体：P3 不撤回，保留旧观测。

### 2.2 公开集合对账

权威候选真实集合 `{W1, W2}`，W1 有两条来源，模拟集合 `{S1}`。候选索引真实集合若为 `{W1, W3}`：报告缺 W2、多 W3，不切换代次。修复后：真实公开总数 2，同过滤条件下搜索 total 和统计分母均为 2，模拟总数单列为 1。W2 因许可撤回后，按新策略重新核验，真实总数变 1。

### 2.3 批次账目

一个批次 10 行：valid 7（new 3、updated 2、unchanged 1、duplicate 1）、quarantine 2、filtered 1。检查：`read = 7 + 2 + 1 = 10`；`valid = 3 + 2 + 1 + 1 = 7`。同一批次重放：账目不变。

## 3 容量与恢复试验计划

只写计划，不写预期数值。

- **输入**：两组用同一冻结 manifest（来源、文件哈希、版本、过滤条件、许可范围、规则版本、模拟标记），同一硬件、并发和缓存状态。
- **分档**：1 万、10 万、100 万条。分档用来定位瓶颈；百万级真实公开目标另按已获准、可公开的规范成果验收。早期 SRS 的一万条是历史基线，规模口径由 1/6 统一。
- **测量**：每阶段吞吐；峰值内存；原始证据、规范数据、索引的体量；两个候选代次共存所需空间；发布延迟；outbox 积压；恢复耗时。
- **故障场景**：来源限流、批次提交中断、索引故障三组；记录是否出现丢批、重复计数、候选误发布。
- **留痕**：每次运行保留公开 ID 集合对账、规则和策略版本、环境参数、任务与批次摘要。
