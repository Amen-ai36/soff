# 数据部分展示讲稿与问答

供团队PPT汇编使用，不是独立全队PPT。建议正文用两页展示：第一页放来源验证矩阵，第二页放采集状态图和两组边界规则。正式展示须使用CodeArts实际导出图，不能把本包预览称为平台截图。

## 1 来源调查约一分钟

我们将数据来源的公开许可、字段覆盖和实际访问分开验证。论文选OpenAlex为候选主源，本次获得了真实JSON样例；DBLP虽然有开放元数据许可，但本次请求返回反爬页面，暂不把它写成已接入。项目方面取得CORDIS页面和NSF接口的少量样例；国家科技奖取得官方目录中的事实字段。国内专利和国内项目的授权及数据级样例仍需补齐，公开入口不等于批量采集许可。

我们只考虑获准的元数据和必要事实，摘要、全文、原始数据包单独判断。数据量指标采用团队批准口径，真实与模拟分列，不把原始行、重复记录或许可待定记录凑成一万条。

## 2 建模与规则约一分钟

数据处理分为采集更新、清洗和去重消歧三份SPEC。缺失年份和引用数不补当前年或零；同DOI也要检查冲突；同名作者没有强证据时保留不同实体。机构和领域依据批准映射表，不靠名称相似猜测。

采集状态包含待执行、运行中、成功、失败、重试、已停止，另用安全停止中说明批次取消。429按Retry-After等待，访问拒绝不自动重试；只有新版本发布确认后才推进水位。我们有合成规则样例，尚不宣称真实一万条系统运行或真实F1达标。

## 3 常见问答

问：为什么不直接爬国内专利和NSFC？答：尚未证实具体数据产品的获取及展示权限，也没有合法样例。我们先补授权证据，必要时由老师确认课程模拟或导入路线，不绕登录、验证码或访问限制。

问：为什么同名不自动合并？答：姓名不是身份标识，误合并会影响门户和合作网络。优先强标识与人工确认映射，弱证据进入复核。数据作者关联不等于真人认领审核。

问：测试通过是否意味着任务完成？答：当前执行的是资料和规则样例验证。用户已提供CodeArts手绘SVG，可编辑项目源文件、共同复核、公共审批、正式Word以及后续生产集成验收仍分别记录，不互相替代。

问：A和B有什么差异？答：本包是B组保守规则候选。A组实际算法及模型效果需成员2提供真实记录，再在同输入同验收下比较；不在没有记录时编写胜负结论。
