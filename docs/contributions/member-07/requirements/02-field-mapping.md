# 数据字段映射与领域分类提案

版本0.1。以下是数据模块的逻辑语义，不是数据库DDL或冻结的公共JSON。来源原字段存在性分为本次样例证实、官方页面可核对及待验证，不将计划字段当作实测字段。

## 1 四类成果字段

| 逻辑字段 | 类型和含义 | 来源与证据 | 缺失处理 |
| --- | --- | --- | --- |
| 成果ID | 不透明稳定字符串 | 本平台分配，保留跨源映射 | 无ID不得发布；不使用标题/姓名作公共ID |
| 成果类型 | paper/patent/project/award | 来源适配器明确映射；OpenAlex/NSF的Award为project | 未知类型隔离 |
| 来源键 | source + source_record_id | OpenAlex Work ID、DBLP key、项目来源号、奖项公告年度+类型+项目号 | 缺来源键隔离 |
| 标题名称 | 非空字符串 | OpenAlex title、NSF title实测；CORDIS和科技奖网页证实 | 缺失隔离，不用“未知标题”造有效记录 |
| DOI | 规范化DOI或null | OpenAlex doi实测；CORDIS DOI应由project命名空间区分 | 不代表所有项目都有DOI；跨类型不按DOI合并 |
| 专利标识 | 局别+公开号+kind code | EPO/CNIPA候选，未实测 | 不把申请号、公开号、授权状态混为一谈 |
| 年份与日期 | 整数/null；来源有精度的日期 | OpenAlex publication_year；NSF startDate；奖项年度与公告日期分别存 | 不用当前年份补齐；月/年精度不伪造成某天 |
| 作者参与人 | 有角色和来源的关系数组 | 论文作者、专利发明人、项目负责人、获奖完成人不可混作同一角色 | 来源未提供记关联未知标志；不能用[]冒充证实无人 |
| 机构关系 | 机构ID、来源和角色 | NSF awardeeName实测；CORDIS协调机构；获奖主要完成单位 | 作者当前机构不代替成果发表时机构 |
| 领域标签 | 体系+原代码+版本及映射 | OpenAlex primary_topic存在性实测；其他来源须另核实 | 映射未知公共unknown；无字段不猜分类 |
| 引用数 | 非负整数或null，含来源和观察时间 | OpenAlex cited_by_count实测；DBLP核心书目数据不保证引用数 | 未提供为null；0只表示来源明确返回零 |
| 摘要全文 | 许可单独判断的可选内容 | 本次不获取；不从元数据许可推导全文许可 | 无依据不公开，不补编摘要 |
| 来源与处理信息 | URL、获取时间、哈希、规则/许可版本、模拟标记 | 本次访问记录有响应哈希 | 原包无法留存时说明证据限制 |

## 2 字段级许可与下游投影

处理权限分为获取、受限存储、公开展示、导出，每个字段单独判断。记录层获准不表示字段层全部获准。公开投影仅包含记录获准且字段获准的白名单；摘要、全文、图片、证明、私人联系方式和受限原包默认不公开。

公开成果总数是发布版本内唯一成果ID数，不能把“作者-成果关系数”“来源行数”“申请和公开阶段数”直接累加。若某来源不得再分发原包，A/B共同基准使用获准的输入或模拟夹具，不能以公平比较为由共享受限载荷。

## 3 领域分类方案

建议第一期使用一个经1/6批准的公共领域表及版本，来源各自标签通过映射表接入。OpenAlex topics的domain/field/subfield/topic层次仅作为来源分类，不直接冒充中国学科目录；CORDIS的EuroSciVoc也不是同一套编码。

映射表至少记录原体系、原代码、原名称、目标领域ID、映射方式、依据、审批人及版本。一个来源标签可以映射多个公共领域，不通过翻译同名自动认定等价。来源无类别或映射待定时保留unknown；记录类型paper/patent/project/award不属于学科领域。

实现顺序建议：确定演示学科范围，收集每类至少两个样例，人工建立小规模映射，经成员2/7交叉核验再交1/6批准。未开展跨学科覆盖率测量，本包不提供虚构分类准确率。

## 4 公共变更说明

变更原因：为成员8的领域/机构过滤、稳定排序和成员9的界面提供明确的缺失及关联语义。影响范围：SRS、领域表、公开投影、统计分母、检索排序及夹具。兼容方案：新增可选字段和来源映射，既有ID保留，不擅自删除旧来源字段。迁移步骤：1/6批准语义，3/8冻结契约，2/7生成映射和回填报告，5/10执行前后计数与权限检查，最后汇编统一文档。

本提案未创建公共字段枚举、OpenAPI或迁移脚本，须先评审。
