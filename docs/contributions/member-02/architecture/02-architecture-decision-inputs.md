# 数据管道架构决策依据与 A/B 对照

成员 2 · 2026-11-05 · 配套[方案 A 架构正文](01-data-pipeline-architecture.md)

以下三项供成员 1、6 编写统一 ADR。比较范围限定在数据接入和发布链路，B 组描述引用已有分析设计，运行指标按同一场景测量。

## 1. 控制端与执行端分离

| 候选 | 主要取舍 |
| --- | --- |
| API 请求内同步抓取和处理 | 调用链短，但来源限流、长任务和进程故障会占住请求。恢复点和部分成功仍需单独保存 |
| 持久任务账本与独立执行器 | API 可快速返回任务标识，执行器能恢复与扩容。需管理租约、退避时间、积压与并发 |
| 独立消息中间件编排各阶段 | 跨服务扩容灵活。任务状态、业务事务和消息的一致性仍需设计，同时增加部署和排查成本 |

**A 组选择。** 以持久任务账本和独立执行器承载长任务，处理阶段先保留在同一数据管道内。按来源限流，按任务租约防止并发回写。是否拆出额外队列取决于压测中任务入队延迟、轮询负载及峰值积压。

**检验。** 同范围重复启动、执行进程中断、429 后到期恢复和人工停止。观察 API 受理延迟、最长等待、重复提交数和恢复后的批次计数。

## 2. 业务事务与搜索投影解耦

| 候选 | 主要取舍 |
| --- | --- |
| 数据库与 Elasticsearch 同步双写 | 完成时延直观，但任一侧失败就有部分成功，恢复需要识别哪一侧已写入 |
| 业务事务内写 outbox，独立投影 | 数据和投影待办共同持久化，可按成果补偿。需要幂等处理、版本防倒序、回执和积压监控 |
| 批次候选持久化后集中生成隔离投影 | 易于绑定完整候选和开展发布前对账。快照重建成本随数据体量增加，失败影响集中在发布阶段 |

**A 组选择。** 通过 outbox 记录已提交变更，投影执行器异步准备候选。发布仍按候选数据版本做集合对账、字段权限检查和条件切换。事件用于恢复和补偿，公开读取由已发布版本控制。按目标版本做全量重建作为回退手段。

**检验。** 模拟索引不可用、写后回执丢失、旧事件迟到和相同条数却不同 ID 集合。对照是否重采、重复入库、出现旧值回写，以及对账后的发布结果。

## 3. 批次恢复位置与公开发布水位分离

| 候选 | 主要取舍 |
| --- | --- |
| 一个水位在批次入库后推进 | 恢复简单。若索引或公开校验失败，后续任务可能跳过仍未发布的数据 |
| 一个水位只在整轮发布后推进 | 基线安全。长任务中断后重做已提交批次的成本较高 |
| 批次检查点与发布水位分开 | 已提交批次可恢复，公开基线仍绑定已核验版本。需要保存两类进度与其版本关联 |

**A 组选择。** 批次检查点随权威事务推进，公开水位随已核验的发布版本切换。撤回和字段权限收紧通过当前权威公开策略即时约束读取。来源有延迟时用有界重叠与幂等处理，完整冻结数据可用于重同步和统一对照。

**检验。** 在批次提交前后分别中断，在发布前注入索引故障和权限收紧。记录两个水位、已公开版本、补偿范围和真实公开计数。

## 4. A/B 已有设计与同口径比较

| 比较项 | A 组方案 | B 组分析材料中的机制 | 共同测量 |
| --- | --- | --- | --- |
| 停止后恢复 | 管理员显式恢复 `STOPPED` 任务，复用已提交检查点 | 停止后以新任务运行并关联旧任务，失败人工重试增加 attempt | 停止生效边界、恢复耗时、重复写入与漏处理数量 |
| 投影与发布 | 事务 outbox 驱动候选投影，失败按事件或版本补偿。核验通过后切换发布指针 | 先持久化候选与处置账目，再构建隔离候选索引、核验并确认发布 | 候选落库至可公开耗时、需补偿的数据范围、ID 集合差异 |
| 增量与撤回 | 批次检查点与发布水位分离，采用有界窗口或文件差分 | 以发布水位和固定上界选择增量，候选检查点可恢复。确认发布后推进成功水位 | 重跑的净新增、漏更新数量、撤回后残留暴露及分母偏差 |
| 匹配质量 | 强键优先，弱证据按经样本校准的阈值处理 | 弱证据只提出候选，强键冲突进入治理 | 相同标注集上的误合并、漏合并、人工队列规模及回滚结果 |
| 公开规模 | 已发布版本内真实、获准且有效的规范成果 | 同版本对账并按真实、模拟及成果类型分列 | 同一冻结 manifest 下的合格公开总数、每类计数、耗时与资源峰值 |

B 组依据见[成员 7 数据处理交互分析](https://github.com/Amen-ai36/soff/blob/ca84369/docs/contributions/member-07/analysis/02-data-pipeline-interactions.md)。共同约束和历史差异见[统一交互分析](https://github.com/Amen-ai36/soff/blob/982ddca/docs/deliverables/03-analysis/02-key-use-case-interactions.md)及[统一分析差异记录](https://github.com/Amen-ai36/soff/blob/982ddca/docs/deliverables/03-analysis/06-review-and-conflicts.md)。

测量以相同的冻结 manifest、模拟标记、字段权限样例和故障注入点为输入。分别报告每分钟有效处理记录数、候选提交到公开的延迟、恢复后重复数、同版本 ID 差异及消歧质量。每项都保留数据版本、执行环境、测量区间和分母。
