# 数据源适配与采集调度

依据 [SPEC-DATA-001](../requirements/specs/SPEC-DATA-001-source-adapter.md)、[SPEC-DATA-002](../requirements/specs/SPEC-DATA-002-collection-task.md)和[采集任务状态机](../requirements/03-collection-task-state-machine.md)，覆盖 R02、R04、R11、R14。

## 1. 来源适配

接入清单区分来源的业务类型、传输方式和许可配置。选用哪一路以上线时核准的来源注册表为准。下表以[已有访问与字段样本](../requirements/evidence/2026-10-12-source-accessibility-validation.md)作为设计依据。

| 成果 | 接入路径 | 来源身份及批次边界 | 适配约束 |
| --- | --- | --- | --- |
| 论文 | OpenAlex 获准 API，DBLP 官方冻结快照 | OpenAlex Work ID 按有界查询分页，DBLP Key 按文件哈希与分片边界续读 | DOI 单独保留为跨来源去重证据。DBLP 自动接口出现挑战页时结束相应请求 |
| 专利 | 已获授权的官方 API 或批准的批量文件 | 以来源键留存观测，公开号、专利局及文献种类代码按来源定义归一化 | 公开号用于成果匹配。申请号和优先权号用于候选关联。许可逐字段读取 |
| 项目 | NSF 获准 API 或 CORDIS 获准导出 | 来源与项目 ID 共同标识观测。资助方及项目编号保留为机构范围内的匹配证据 | 资助方、执行单位和负责人分别映射。导出版本及字段映射纳入清单 |
| 获奖 | 人工核验官方公告并提交有界 CSV | 来源记录键按单项授奖生成，关联公告 ID、年度、奖项类别和来源 URL | 同一公告可产生多条授奖记录。备注、材料和附件各自按许可处理 |

适配器的内部执行顺序为校验配置与授权 → 固定请求或文件读取计划 → 请求/读取 → 校验响应 → 解析并按字段许可保留 → 返回批次记录和元数据。

- **请求计划。** 固定来源、规范化范围、配置版本、映射版本、许可快照和运行上限。有序页使用稳定排序键，有效游标放入当前批回执，冻结数据校验文件哈希后流式读取。CSV 固定编码、表头和必填字段，按解析后的逻辑记录切分。无增量能力的输入只支持有界读取或全量快照差分。
- **终止判定。** 正常完成以来源声明的末页、可信快照结束或计划范围已覆盖为准。空结果先验证响应契约。重复游标、结构变化、页上限提前耗尽和文件校验失败均登记失败或不完整。按样本上限结束的 `sample` 任务只在采样范围内结算。
- **许可检查。** 调度和请求前检查当前来源是否启用、目标范围是否获准及访问条件。页面采集仅在站点条款与 robots 规则均允许时启用。分别执行 `access`、`collect`、`store`、`display`、`export` 五项许可。未获采集授权的字段不转换成内部记录，不能留存的内容不写原文存储。允许留存的原始证据由内容哈希关联。
- **校验与追踪。** 依次验证状态码、响应类型、字节上限、编码、根结构和必需字段。200 HTML 挑战页按结构异常处理。成功批输出 `SourceRecord`、来源版本、下一游标或文件位置，以及请求数、状态类别、时间、字节数和解析结果。已合法获取的坏行按行级问题处置，批级结构错误阻断该批。日志只写脱敏摘要、证据引用与 `request_trace_id`。

## 2. 调度与重试

1. 控制端从服务端会话确定操作者，按来源和操作授权创建或更新任务。同主体同操作的幂等键和同一请求摘要复用原结果，摘要不一致返回冲突。调度器按 `next_attempt_at` 和稳定任务键领取已到期工作。
2. 领取在权威存储内一次完成。验证来源配置、任务状态及活动键，递增执行代次，写入租约及到期时间。保留 SPEC 的 `source_id + scope_hash + mode` 活动唯一性，方案 A 再对同来源或重叠范围的线上写任务执行互斥；可验证独立的分片按既有架构约束执行。样本范围使用独立账目。
3. 采集按来源配额执行，默认单并发。遇到 429 优先遵守合法 `Retry-After`，并更新来源级冷却时间，避免其他任务立即发起同源请求。若下一次允许访问的时间已超出任务预算，记录耗尽并结束自动重试。暂时性 5xx、连接超时和读超时采用有上限的指数退避及抖动。退避测试注入固定时钟与随机种子。
4. 401/403、有效许可失效及内容契约不匹配进入对应的 SPEC 错误分类，等待人工处理。可确定归因为永久错误的解析失败也结束自动重试。规则按已提交批次及剩余阶段选择终态或补偿路径。来源故障、行级质量问题与索引待同步分开计数。
5. 停止请求由控制端持久化。执行器停止领取新批次，在当前安全边界提交或回滚，记录最后已提交检查点并进入 `STOPPED`。执行权失效时，旧代次不得写结果，接管方重新校验停止标记和回执。显式恢复从已提交检查点开始，`PARTIAL_SUCCESS` 只补失败范围或索引阶段。已进入 `FAILED` 的任务由人工修正后发起新任务。

## 3. 批次事务与回执

采用两个层次的幂等键。任务内使用 `task_id + batch_index + source_version`，追踪重试和阶段计数。增量来源批次使用 `source_id + source_version + batch_hash`，识别重放的来源输入。派生结果仍按固定规则版本处理，换规则后的重新计算可显式重用来源观测。

| 顺序 | 执行点 | 条件和结果 |
| --- | --- | --- |
| 1 | 受控存储 | 按许可保存证据或证据摘要。权威事务失败后，有相同内容与许可的重放复用有效证据，未引用对象按保留规则清理 |
| 2 | 权威批次事务 | 校验当前执行代次与租约。先判断已有批次回执和内容摘要，再校验新批次的预期检查点。已成功且同摘要的批次回放原回执。同键不同摘要进入冲突处置 |
| 3 | 权威批次事务 | 新批写入来源记录、规范结果或明确处置、批次回执、阶段计数及所需 outbox。条件更新处理检查点，所有写入共同提交 |
| 4 | 调度器 | 提交成功后继续读取后续批次。若提交结果未知，用批次键查询回执。计数从提交回执复算，执行尝试单独记审计 |

检查点只跨过连续且已有持久处置的输入。允许审计的隔离记录可作为处置结果，但批级读取失败、未知缺页或提交失败保留断点。索引故障发生在独立的投影阶段，恢复时按已提交事件补偿。
