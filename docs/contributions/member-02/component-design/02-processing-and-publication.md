# 清洗消歧、增量更新与数据质量

对应 [SPEC-DATA-003 清洗](../requirements/specs/SPEC-DATA-003-cleaning-normalization.md)、[SPEC-DATA-004 去重消歧](../requirements/specs/SPEC-DATA-004-dedup-disambiguation.md)、[SPEC-DATA-005 增量更新](../requirements/specs/SPEC-DATA-005-incremental-update.md)及 [SPEC-DATA-006 质量准入](../requirements/specs/SPEC-DATA-006-quality-gate.md)，覆盖 R03、R04、R05、R07、R11、R14。

## 1. 清洗和字段证据

每个批次固定字段映射、清洗规则、枚举和别名表版本。以一条 `SourceRecord` 生成一条 `NormalizedRecord` 及关联质量问题。原始复合条目在适配层完成拆分。遇到单条脏数据时保留来源与问题定位，按规则写入隔离或治理队列。字段候选携带原值或其许可允许的证据引用、来源键及版本、规则版本和字段级许可。

| 字段 | 处理 | 示例或边界 |
| --- | --- | --- |
| 标题与名称 | HTML 实体解码一次，Unicode NFKC、清除指定控制字符、折叠空白。单独生成匹配指纹，保留获准存储的原值 | ` Ａ&amp;Ｂ　 ` 的规范化值为 `A&B`，比较指纹保留 `&` |
| DOI、ORCID、ROR | DOI 去解析域名前缀并转小写。验证 ORCID 的校验位及 ROR 的标识结构，并保留标准 URL。来源本地 ID 仅在其命名空间内比较 | `https://doi.org/10.1000/ABC` 映射为 `10.1000/abc`。无效标识记录问题，保留合法证据 |
| 日期与分类 | 完整日期按 ISO 8601 保存，年月与年度保留精度。分别记录缺失、未知和非法。用固定映射处理类型和领域 | `2024` 保留年精度，`2024-02-30` 记非法日期。未知成果类型转治理 |
| 学者与机构 | 保留作者原始姓名、顺序、来源 ID、通讯作者标记和机构列表。同一作者的多个机构保留多个引用 | 空列表表示已知无关联，缺失或未知依字段状态处理。缺少身份依据时保留待解析关系 |

规则版本更新重新计算受影响的派生结果，比较规范值、质量问题和目标投影差异，形成影响记录。原来的来源观测和当时的处理结果继续可追溯。

## 2. 去重、消歧与人工治理

1. **定位成果。** 先按成果类型和强键查找。论文使用合法 DOI 和各自命名空间的 OpenAlex/DBLP 标识，专利用专利局及规范公开号，项目保留来源项目键并使用资助方范围内的项目号，获奖以授奖项对应的官方标识和公告内记录区分。多条授奖共用一个公告时，公告号只作分桶和来源证据。强键命中一个身份且无冲突时建立关联。强键指向多个已有身份，或候选有相斥有效强键时，保留原联系并登记治理。
2. **生成候选。** 同类型内对规范化标题与相邻年度、venue 或机构证据做可重叠分桶，再比较标题、作者集合与顺序、年份差、venue、机构、语言和 DOI 缺失情况。缺少年份时仍可走其他分桶，未找到候选与候选超限分别记录。证据同时输出特征值、取值覆盖和规则版本，供人工复算。
3. **判定学者与机构。** 学者优先使用可靠强 ID 或有效人工决定。弱证据比较姓名变体、机构时间线、领域及合作者。仅有姓名、机构或合作者之一时保持独立或送人工。机构优先 ROR，再按含生效时间和来源的核准别名匹配。父子、同名与等价关系分别保留。
4. **处置候选。** 硬冲突和有效的人工拒绝优先。其余候选按版本化上下阈值、最低证据覆盖和第一、第二候选分差做判定。证据不足、候选过多或分差不足时送人工。只有固定标注集达到团队的误合并容许范围后才开启弱证据自动通过。校准前，弱证据仅排序和辅助人工。稳定 ID 用于结果排序和复算，分数相同的高分候选转人工。
5. **保存变更。** 锁定有竞争的稳定标识或用条件版本提交确认当前仍无冲突。保存合并前后关联、规则版本、证据、决定理由与操作人。回滚按原关联和后续变更生成新规范版本，更新受影响成果、学者、机构、索引和统计。人工字段保持现有已批准值，除非后续获批准改动或许可收紧要求隐藏。

## 3. 增量窗口与回放

| 进度 | 固定条件 | 更新时点 |
| --- | --- | --- |
| 批次处理检查点 | 来源、范围、候选输入窗口及其 manifest | 同批次、计数和 outbox 一起提交。游标或分片缺口保留原位置 |
| 公开发布水位 | 来源、范围及已发布版本 | 候选完整、对账通过且权威发布指针切换时共同更新 |

1. 读取公开水位，冻结基线版本、窗口上界、查询条件和规则/许可版本。支持时间增量时，以更新时间和稳定来源 ID 作有序续读键。重叠窗口的大小按来源延迟确定，重叠数据按来源身份、版本与内容哈希判重。快照来源固定文件版本和哈希，以同范围、完整且可验证的快照差分。游标失效就回到最后可验证的 manifest，再决定是否重做本轮窗口。
2. 对每个稳定来源键比较前版与本轮内容。分别记录 `NEW`、`UPDATED`、`DELETED`、`UNCHANGED`、`CONFLICT`，失败另计。相同来源键和版本发生不同内容哈希时转来源冲突，保留旧观测。多版更新以来源保证的版本或时间顺序为依据，无法可靠排序的变更交治理。
3. 来源明确撤回或同范围完整快照差分才生成撤回标记。固定范围读取失败、缺页、样本边界和得不到上版证据时保留此前观测。撤回后按当前许可重算剩余有效来源。新值与人工值冲突时并存两份证据，继续使用仍获准的上次批准值。
4. 候选版本固定上一个已发布版本、纳入批次、来源版本、拟推进水位、规则版本与许可策略。回放某一未发布候选要复用已提交批次及回执，处理检查点继续用于恢复。对整轮从已发布基线重算时也应去重。索引补偿只消费已提交的 outbox，不重新访问来源。

## 4. 公开准入与版本切换

质量闸门先检查来源证据、受控类型、核心标题、审批、模拟标记、高严重度冲突和适用规则（R-Q-001～010）。按有效许可为每个打算公开的字段选择可公开的来源证据，再审核投影白名单。若必要字段无可公开证据，隔离该候选。任何实际准备进入公开投影的受限或待定字段触发 R-Q-007。警告随报告输出，模拟数据分范围展示，导出和 AI 输入分别按对应授权校验。

| 步骤 | 接口语义 | 失败或竞争时 |
| --- | --- | --- |
| 批次已提交 | `AppendNormalizedBatch` 返回已提交回执，处理检查点与规范版本及 outbox 同事务 | 同键同内容重放原回执。写入冲突保留已提交状态 |
| 准备候选投影 | `PreparePublication` 固定基线和候选清单。消费 `ProjectRevision` 时按目标版本、成果 ID、规范版本与摘要校验 | 索引成功后回执丢失，可用同版本同摘要补回执。旧版本忽略，同版本异摘要转隔离 |
| 核验目标版本 | 按相同数据、许可范围及策略版本比较权威与索引的完整公开 ID 集合和投影摘要。复核真实/模拟、类型和统计分母 | 记录差异 ID，补齐或重建候选。统计缺失或核验未通过时保持当前发布 |
| 提交发布 | `ConfirmPublication` 比较当前指针代次、候选基线、任务代次、停止状态、策略版本和核验证据。单次权威事务更新指针及公开水位 | 在同一事务中重新核验前置条件。基线或策略变更时按当前状态重建候选，停止已成立时按任务状态机结算 |

撤回或许可收紧时，权威公开策略先使受影响对象或字段不可见，再更新索引、缓存与统计。查询端在过滤、排序分页、`total` 和聚合前应用策略。无法保证受影响查询仍满足当前策略时停止该查询并返回对应的依赖状态。

公开规模按发布版本内的合法真实规范成果 ID 去重计数。另报来源记录、重复输入、模拟、受限、隔离、撤回和待发布数据。阶段处理数从批次回执计算，最终公开数从已发布候选计算，两份账分别按来源、类型、规则和数据版本追溯。正式试验按百万级真实公开目标报告，1 万和 10 万用于分档定位瓶颈。
