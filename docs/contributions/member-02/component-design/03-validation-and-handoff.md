# 验收场景与汇编交接

以下是实现阶段的验收设计。离线夹具使用明确标识的虚构来源记录和可控响应。每个用例从独立的任务、权威存储和投影环境开始，固定规则版本、许可策略、时钟及输入清单。失败注入后恢复依赖，再检查任务回执、权威数据及投影，按用例清理隔离环境。

## 1. 需求追踪与通过条件

| 用例 | 需求 / SPEC | 输入及操作 | 可核验结果 |
| --- | --- | --- | --- |
| ETL-01 来源映射 | R02、R14 / DATA-001 | 按 2 页 API、冻结文件、项目导出及人工 CSV 导入四类夹具。包含同公告的两项授奖及含引号换行的 CSV 字段 | 同一清单两次输出的稳定来源键、切片边界、字段映射结果一致。两项授奖保留各自身份 |
| ETL-02 接入异常 | R02、R14 / DATA-001 | 注入合法空页、200 HTML 挑战页、401、403、重复游标及错误文件哈希 | 合法空页按来源终止条件结算。其他响应按故障类别记录，无成功回执或公开水位推进 |
| ETL-03 退避与互斥 | R04、R11 / DATA-001、002 | 同来源同范围并发触发 `full` 和 `incremental`，重复提交同幂等键。在执行请求中注入 429 和 60 秒 Retry-After | 同一请求复用该任务。最多一个重叠线上写任务持有有效执行权；冷却期间同源无新请求。假时钟推进后按预算决定重试或结算 |
| ETL-04 停止、接管与重放 | R04、R11 / DATA-002、005 | 分别在批次提交前和提交后回执返回前终止进程。接管后重放该批，再让旧执行器回写。另在批次中发出停止请求 | 未提交批次从旧检查点重做，已提交批次返回原回执，旧代次不能提交。停止后不领新批，记录安全边界及可恢复位置 |
| ETL-05 规范化 | R03、R14 / DATA-003 | 导入全角标题、大小写 DOI、年份、非法日期、真实零值、缺失字段及多机构作者 | 输出可复算，保留获准原值证据。部分日期不补日，零值与缺失可区分，作者顺序及机构列表不丢失 |
| ETL-06 去重与冲突 | R03、R11 / DATA-004 | 载入跨来源同 DOI 的论文、相似标题但 DOI 冲突的论文、同公告的不同授奖项 | 同 DOI 关联一个规范成果；强键冲突转治理并保留两份证据；独立授奖项各计一次 |
| ETL-07 消歧及回滚 | R03、R07 / DATA-004 | 加入同名不同身份、有效 ORCID、父子机构及人工拒绝记录。批准一次合并后回滚 | 同名保持独立，强 ID 可关联，父子关系不合并，拒绝记录仍有效。回滚产生新版本并触发索引与统计重算 |
| ETL-08 增量与不完整输入 | R04、R11、R14 / DATA-005 | 按固定窗口导入新增、修改、未变化、明确撤回、人工冲突和一次分页失败。完整输入重放两次 | 同窗口输入的变化分类可复算。缺页不引发撤回，人工批准值与来源证据并存。重放不增加成果及变更账目 |
| ETL-09 异步投影与发布竞争 | R04、R05、R11 / DATA-002、005、006 | 模拟索引写入后回执丢失、乱序事件和两候选争用同一发布指针。第二次执行在核验后变更许可策略 | 同摘要回放修复回执，迟到事件无法覆盖新版本。只有仍匹配基线和策略的候选可原子推进指针及公开水位 |
| ETL-10 公开许可与计数 | R05、R11、R14 / DATA-006 | 同批加入获准真实成果、重复来源、带标记的模拟成果、待定字段和撤回记录。另用总数相同但 ID 不同的候选索引 | 真实计数按规范 ID，模拟独立。待定字段不出现在公开 DTO、导出与 AI 输入。集合差异阻断发布。收紧许可后旧索引和缓存不再暴露受限内容 |

## 2. 小样本与可复算指标

- **增量固定输入。** 旧快照有 P1～P4，P1 含已批准的人工标题。本轮针对 P1 改来源标题，P2 无变化，P3 明确撤回，P4 改普通字段，再新增 P5。在完整输入中，`NEW`、`UPDATED`、`UNCHANGED`、`DELETED`、`CONFLICT` 各 1，失败 0。逐记录以冲突为该轮分类，字段级变化另存依据。重复投递复用已登记结果。另用完整快照差分测试隐式撤回，并以缺页变体核验 P3 不因单纯缺失而撤回。
- **公开集合。** 权威候选真实集合为 `{W1, W2}`，W1 有两条来源，模拟集合为 `{S1}`。索引真实集合若为 `{W1, W3}`，应报告缺 W2、多 W3。修复后真实公开总数为 2，同过滤条件下搜索 `total` 和统计分母均为 2，模拟总数单列为 1。许可撤回 W2 后按当前策略复核各公开入口及计数。
- **匹配质量。** 固定标注集保留同名、弱证据、强键冲突和多机构等切片。对标注配对计算 `Precision = TP / (TP + FP)`、`Recall = TP / (TP + FN)`、`F1 = 2TP / (2TP + FP + FN)`。人工待定与未生成候选分别报告。需要自动匹配且未匹配的标注正例纳入 FN，同时单报待人工比例。分母为 0 标记不适用并带样本量。报告合并证据完整率、回滚正确率和强冲突漏转治理数。
- **质量报告。** 记录阶段输入、输出、隔离、重复与失败数，校验来源和批次账目。按发布版本记录必填字段完整率、未允许字段进入公开层的次数（须为 0）、冲突队列大小及最老年龄。报告同时附固定 manifest、规则及策略版本、对账结果和差距。

## 3. 容量与恢复试验

固定数据集来源、覆盖范围、硬件、并发、缓存状态及查询组合，两组使用同一 manifest。先跑 1 万、10 万和 100 万条分档。模拟负载可用于压测，真实目标按已核准且可公开的规范成果另行验收。测量每阶段吞吐、峰值内存、原始证据/规范数据/索引体量、两个投影版本共存所需空间，以及发布延迟、索引积压和恢复耗时。增加来源限流、批次提交中断和索引故障三组场景，记录是否出现丢批、重复计数或候选误发布。

每次保留公开 ID 集合对账、规则/策略版本、环境参数、任务与批次摘要及测试结果。量化 SLA、自动匹配阈值和容量结论用实际测试数据评定。

| 成员 4、9 | 任务状态、阶段、进度、停止及恢复语义 | [管理后台交互](../../member-04/component-design/04-interaction-and-state-spec.md)用同一任务和批次快照验证，区分已保存、待索引和已发布 |
