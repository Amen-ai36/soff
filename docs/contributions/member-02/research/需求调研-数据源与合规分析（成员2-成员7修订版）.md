## 1. 修订说明

本版保留原稿关于 OpenAlex、DBLP、EPO OPS、CORDIS、NSF、NSFC、国家科技奖等来源的主体分析，并完成以下修订：

1. 区分“可访问”“可采集”“可存储”“可展示”“可导出”五类权限，不再仅用单一许可证字段表达。
2. 更正 OpenAlex 全文访问方式：元数据为 CC0，PDF/TEI 保留原始版权；单文件可按 API 用量下载，全量持续同步服务另行付费。
3. 将 DBLP 月度持久化快照设为可复现实验首选，并明确单次 Search API 的 `h` 上限为 1,000、可通过 `f` 分页。
4. 将 CORDIS 官方框架计划全量 open-data 数据包设为冻结基准数据首选，DET API 用于增量更新。
5. 增加 CORDIS 项目摘要、报告、交付物的字段级权利判断，避免把受益方材料统一视为 CC BY 4.0。
6. 增加 NSF 年度下载不可用时的 API/搜索导出回退机制。
7. 将 NSFC、Google Patents、需登录或验证码的 CNIPA 自动化统一降为 P2/待授权。
8. 针对 A/B 两组提出共用冻结数据集、10,000 条计数口径、质量指标和契约测试建议；是否纳入公共方案由成员 1、6 确认。
9. 增加外部 AI、云服务、认领材料、个人信息保护影响评估和跨境数据流要求。

## 2. 调研目标与边界

本调研回答以下问题：

1. 论文、专利、科研项目、科研获奖分别从哪些官方或权威来源取得。
2. 各来源是否提供 API、批量下载、注册授权或稳定更新机制。
3. 采集、存储、清洗、公开展示和导出分别需要什么权利依据。
4. 如何满足“两组使用同一输入、分别实现、统一验收”的课程要求。
5. 如何形成不少于 10,000 条去重后、可公开展示的规范化成果记录。
6. 如何控制限流、个人信息、数据跨境、AI 工具和原始数据再分发风险。

本项目默认只处理公开学术成果及其必要事实字段，不采集私人手机号、私人邮箱、身份证号、家庭住址、登录后简历、评审意见等非必要信息。

## 3. 总体结论

### 3.1 数据源优先级

| 级别 | 来源 | 定位 | 推荐接入方式 |
| --- | --- | --- | --- |
| P0 | OpenAlex | 论文、作者、机构、主题和资助关联主源 | API 定向查询；保存查询清单和响应哈希 |
| P0 | DBLP | 计算机领域论文和 venue 规范补充 | 月度持久化 XML 快照；流式解析 |
| P0 | CORDIS | 欧盟科研项目主源 | 官方框架计划 open-data 数据包；DET API 仅作增量 |
| P0 | NSF Award Search | 美国科研项目主源 | 官方 JSON 年度下载；不可用时切换 API/搜索导出 |
| P0 | MOST/NOSTA 正式授奖页面 | 国家科技奖主源 | 人工复核 CSV 或低频半自动结构化 |
| P1 | EPO OPS | 全球专利样本 | OAuth 2.0 API；控制 4 GB/周和约 1 Mbit/s |
| P1 | USPTO 官方批量数据 | 美国专利补充 | 官方批量产品或 ODP API |
| P1 | CORDIS DET API | 项目增量更新 | 注册 API key；遵守平台动态限额 |
| P2 | Google Patents BigQuery | 原型和交叉比对 | 具体数据集许可审查通过后方可公开使用 |
| P2 | NSFC 门户 | 中文项目补充 | 少量人工核验；批量使用前取得书面授权 |
| P2 | CNIPA 页面、省部级和学会奖项 | 中国专利与奖项补充 | 逐站审批；不绕过登录、验证码或访问控制 |

### 3.2 10,000 条入库口径

“不少于 10,000 条”定义为：

> 完成字段校验、跨源去重和许可审核后，进入 canonical 表且 `approval_status=approved`、允许进入公开检索层的有效记录总数。

以下记录不计数：原始抓取行、重复来源记录、ETL 失败记录、许可待定记录、隔离记录、软删除记录。

建议最低分布如下：

| 类型 | 建议最低数量 |
| --- | ---: |
| 论文 | 8,000 |
| 专利 | 700 |
| 科研项目 | 1,000 |
| 荣誉获奖 | 100 |
| 总量 | ≥10,000 |

如课程或指导教师另有数量要求，应修改分布，但不得改变“去重后、许可通过、可公开记录”的计数原则。

## 4. 数据源核验与接入策略

### 4.1 OpenAlex

官方资料：

- API 认证与限额：<https://help.openalex.org/api/authentication/>
- 定价：<https://help.openalex.org/access/pricing/>
- 快照：<https://help.openalex.org/access/snapshot/>
- 全文：<https://help.openalex.org/access/fulltext/>
- Award：<https://help.openalex.org/data/awards/>

已核验结论：

1. OpenAlex 元数据整体以 CC0 提供；免费账户每天有 1 美元 API 用量额度。
2. API 硬限制为每秒 100 请求；`per_page` 最大 100；普通分页最多 10,000 条，超过时使用 cursor paging。
3. 2026 年 6 月公开快照包含约 649 million 条记录；JSONL 和 Parquet 各是一份完整副本，压缩量分别约 750 GB 和 780 GB。
4. Award 表示单项科研资助/项目，不是荣誉奖项，必须与国家科技奖等荣誉分表。
5. OpenAlex 内容归档中的 PDF/TEI 保留原始版权。单文件可使用 API key 按用量下载；完整持续同步需要相应付费服务。

建议使用字段：OpenAlex Work ID、DOI、题名、发表日期、作者、ORCID、机构、ROR、主题、引用数、OA 状态、来源位置、资助方和 Award 关联。

实施要求：

- 使用 API key、`select`、`per_page=100` 和 cursor paging。
- 只下载目标机构、主题、年份或 venue 的子集。
- 不因 OpenAlex 元数据为 CC0 而自动缓存或公开 PDF。
- 摘要、OA 链接和全文许可分别记录，不使用一个总开关代替。

### 4.2 DBLP

官方资料：

- 数据许可：<https://dblp.org/faq/1474677.html>
- 爬取规则：<https://dblp.org/faq/1474706.html>
- Search API：<https://dblp.org/faq/How%2Bto%2Buse%2Bthe%2Bdblp%2Bsearch%2BAPI.html>
- XML 解析：<https://dblp.org/faq/How%2Bto%2Bparse%2Bdblp%2Bxml.html>

已核验结论：

1. DBLP 元数据采用 CC0 1.0，并继续提供 ODC-BY 1.0 兼容性双许可。
2. 官方建议连续请求之间至少等待 1–2 秒；遇到 `429` 时遵守 `Retry-After`。
3. Search API 的单次 `h` 参数最大为 1,000，可通过 `f` 分页。
4. DBLP 不提供论文摘要、统一机构归一化或引用次数。
5. 每日 XML dump 无固定版本；月度持久化 snapshot 更适合实验复现。

实施要求：

- 使用月度持久化 snapshot，并记录 XML 与 DTD 的 URL、日期和哈希。
- 采用 SAX、StAX 或其他流式解析，不使用 DOM 全量载入。
- API 仅用于小规模定点补全和增量查询。
- DOI 相同可直接合并；无 DOI 时必须综合题名、作者、年份和 venue，不得仅凭标题覆盖。

### 4.3 EPO Open Patent Services

官方资料：

- 公平使用规则：<https://www.epo.org/en/service-support/ordering/fair-use>
- OPS 条款：<https://www.epo.org/en/service-support/ordering/terms-and-conditions/ops-terms-and-conditions>
- 产品与价格：<https://www.epo.org/en/service-support/ordering/patent-information-products>

已核验结论：

1. 免费额度为每自然周不超过 4 GB；自动查询流量上限约 1 Mbit/s。
2. 超过免费额度的 OPS 年度订阅价格当前为 EUR 2,800。
3. 用户可以把 OPS 数据纳入自己的机器可读数据库、产品或服务，并作为产品组成部分分发。
4. 不得把 OPS 数据“作为数据本身”原样公开、复制或分发。
5. EPO 建议自动任务安排在 GMT 19:00–07:00 或周末。

实施要求：

- OAuth 2.0 凭证只保存在后端秘密管理中。
- A/B 两组不得共享个人账户密码或在代码、日志中暴露密钥。
- 每周按实际响应字节统计；3.5 GB 告警，4 GB 硬停。
- 公共基线只包含经批准的规范化衍生字段，不包含 OPS 原始 XML。
- EPO 通知数据更正时，应记录并执行更正任务。

### 4.4 CORDIS

官方资料：

- 项目及全量开放数据：<https://cordis.europa.eu/projects>
- 数据提取工具：<https://cordis.europa.eu/about/dataextractions/en>
- DET API：<https://cordis.europa.eu/about/dataextractions-api>
- 法律声明：<https://cordis.europa.eu/about/legal>

推荐顺序：

1. 使用 Horizon Europe、Horizon 2020 或 FP7 官方 open-data 数据包形成冻结基准。
2. 使用网页导出处理小规模临时查询。
3. 使用 DET API 处理自动化增量；API key 仅限注册用户，并受平台动态限额约束。

许可边界：

- 欧盟拥有权利的编辑内容通常适用 CC BY 4.0，要求署名并标明修改。
- 受益方提供的材料仍受资助协议约束，不自动适用网站通用 CC BY 4.0。
- 项目事实字段、项目摘要、报告、交付物、图片和视频必须分开登记权限。
- 未确认项目摘要权利时，公开页面只展示事实字段和官方链接。

### 4.5 NSF Award Search

官方资料：

- Award Search：<https://www.nsf.gov/funding/award-search>
- 年度下载：<https://www.nsf.gov/awardsearch/download-awards/>

已核验结论：

1. NSF 明确其网站发布的 Award 数据（含 award abstract text）属于公有领域，不受美国版权保护。
2. 出版物和会议论文仍按出版者许可处理。
3. 年度下载自 2025 年 1 月起由 XML 改为 JSON。
4. 本次核验时，年度下载页显示暂无可用导出文件，因此实现不能只依赖 ZIP。

回退顺序：年度 JSON → Award API → 搜索结果导出。每条记录保留 Award ID、抓取时间、来源 URL 和原始哈希。

### 4.6 USPTO

官方条款：<https://www.uspto.gov/terms-use-uspto-websites>

已核验结论：USPTO 检索界面不是批量下载工具；异常高频访问可能被拒绝。专利文本和附图在美国通常不受版权限制，但可能包含第三方版权材料、商标或其他例外。

实施要求：优先使用官方批量产品或 ODP API；不得把美国法下的版权结论外推为其他法域的无条件再分发许可。

### 4.7 NSFC、CNIPA 与 Google Patents

- NSFC 开放获取政策不等于项目数据库整体可批量再利用。未取得书面授权前，只允许少量人工核验，不做隐藏接口或登录后数据自动化。
- CNIPA 页面遇到登录、验证码或反自动化措施时立即停止；不得规避。
- Google Patents 代码仓库的 Apache-2.0 不等于 BigQuery 数据集本身采用 Apache-2.0。保存具体 dataset/table 条款后方可决定公开用途。

### 4.8 国家科技奖与其他荣誉

官方资料：

- 科技部 2025 年授奖专题：<https://www.most.gov.cn/ztzl/gjkxjsjldh/jldh2025/index.html>
- 国家科学技术奖励工作办公室：<https://www.nosta.gov.cn/>

处理原则：

1. 优先使用科技部法定主动公开或正式授奖页面，不把所有政府新闻页一概视为无版权内容。
2. 只抽取奖项、年度、项目名、编号、主要完成人、主要完成单位等事实字段。
3. 人物介绍、新闻稿、照片、证书扫描件、页面版式和第三方材料另行判断。
4. 国家科技奖允许人工复核 CSV 导入；半自动解析必须经过人工批准后发布。

## 5. 法律与合规分析

### 5.1 著作权

依据《中华人民共和国著作权法》第五条，法律法规、具有立法行政司法性质的国家机关文件、单纯事实消息、历法、通用数表等不适用著作权法；第十五条规定，具有独创性选择或编排的数据库或资料集合可能构成汇编作品。

官方原文：<https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html>

因此：

- 事实字段可能不构成作品，但数据库整体、摘要、报告、图表、照片和版式仍可能受保护。
- “公开可访问”“课程项目”“非商业用途”均不当然等于可以复制和公开传播。
- 不存在统一的“短摘要安全字数”；无明确依据时使用事实性自写概述或仅提供链接。

### 5.2 个人信息

公开的姓名、单位、职称和成果关系仍可能属于个人信息。处理已公开个人信息必须在合理范围内进行；个人明确拒绝时，除法律另有规定外应停止处理。认领材料、管理员审核记录、私人联系方式应进入受限层。

官方原文：<https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html>

最低要求：

1. 发布清晰的个人信息处理规则和联系方式。
2. 区分“来源记录”和“本人认领确认”。
3. 提供查阅、更正、隐藏、删除和申诉入口。
4. 认领证明采用最小必要原则，并设置独立保留期限。
5. 对公开、委托处理、自动化决策、敏感信息和跨境提供等高风险活动开展个人信息保护影响评估；报告和处理记录至少保存三年。

### 5.3 数据安全与网络数据

《数据安全法》要求数据分类分级、全流程安全管理和合法正当收集。《网络数据安全管理条例》自 2025 年 1 月 1 日起施行，适用于网络数据的收集、存储、使用、加工、传输、提供、公开和删除。

官方原文：

- <https://www.npc.gov.cn/npc/c2/c30834/202106/t20210610_311888.html>
- <https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm>

建议分级：

| 等级 | 数据 | 控制 |
| --- | --- | --- |
| L1 | 获准公开的成果事实元数据 | 可检索；保留来源和权利依据 |
| L2 | 统计和衍生标签 | 保存算法与版本 |
| L3 | 认领资料、审核记录、邮箱 | 加密、最小权限、审计、限期删除 |
| L4 | EPO 原始 XML、待授权数据、敏感缓存 | 隔离存储，不进入公网或 AI 工具 |

### 5.4 跨境和外部 AI

向境外云、代码平台或 AI 服务提供个人信息，可能构成跨境提供。应依据《个人信息保护法》第三十八至四十条和《促进和规范数据跨境流动规定》判断是否适用安全评估、标准合同、认证或豁免。

官方资料：<https://www.cac.gov.cn/2024-03/22/c_1712776612187994.htm>

公共规则：

- 禁止把认领身份证明、私人联系方式、审核材料、密钥、EPO 原始 XML 或待授权数据输入外部模型。
- 使用合成样本或已批准公开字段进行 AI 辅助开发。
- AI 日志提交前自动检测密钥和个人信息并脱敏。
- 记录模型供应商、处理地区、保留期限、训练用途、删除机制和委托处理安排。

## 6. 统一数据与许可模型

每条来源记录至少保留：

```text
source_id
source_name
source_record_id
source_url
retrieved_at
raw_payload_hash
etl_version
reuse_basis_type
reuse_basis_reference
license_checked_at
field_policy
access_scope
approval_status
retention_until
personal_data_level
```

`approval_status` 取值为 `approved`、`restricted`、`pending`、`denied`。只有 `approved` 且 `access_scope` 包含 `public` 的字段才能进入公开检索层。

## 7. 对 A/B 共用数据的协调建议（不修改双组方案）

依据现有《双组并行开发与合并方案》中“两组使用同一数据集和公共测试验收”的要求，本调研建议由成员 1、6 组织确认同一个数据 manifest。建议内容如下：

```text
dataset_version
generated_at
source_versions[]
files[].path
files[].sha256
record_counts_by_source
record_counts_by_type
filter_conditions
licence_snapshot_paths[]
etl_contract_version
```

为保持比较公平，建议实时增量数据不参与 A/B 基准评分。A/B 可独立实现清洗、去重、消歧和入库算法，但输入文件、公共字段语义和验收脚本宜保持一致。本节仅提出数据与合规方面的协调意见，不直接变更双组方案、分支规则或人员职责。

## 8. 去重和消歧

| 类型 | 强标识符 | 候选特征 |
| --- | --- | --- |
| 论文 | DOI、OpenAlex ID、DBLP Key | 题名、作者、年份、venue |
| 专利 | 专利局 + 公开号、申请号 | 优先权号、申请人、题名 |
| 项目 | 来源项目号 | 资助方、机构、题名、起止时间 |
| 获奖 | 公告编号、奖项编号 | 奖项、年度、项目名、获奖人、单位 |

要求：

- 强标识符冲突时不得自动覆盖。
- 自动合并必须记录规则版本、置信度和来源记录列表。
- 低置信度和字段冲突进入人工复核队列。
- 合并必须可撤销，并保留合并前后的 ID 映射。

## 9. 爬虫伦理与运行控制

1. API、批量下载和官方导出优先于网页抓取。
2. 不绕过登录、验证码、付费墙、IP 封锁、robots.txt 或访问控制。
3. User-Agent 标明项目、版本和联系邮箱。
4. 默认单并发；按来源限额配置速率。
5. 遇到 401、403、验证码或明确拒绝时立即停止并转人工。
6. 遇到 429 时遵守 `Retry-After`；否则采用 1、2、4、8 秒指数退避，第五次失败熔断。
7. 禁止使用代理池、轮换账号或换 IP 规避限制。
8. 请求日志不得记录 API 密钥、个人认证材料或完整敏感载荷。

## 10. 建议的公共接入范围（待方案负责人确认）

从数据可得性、许可和可复现性出发，建议成员 1、6 在后续 SRS 或公共基线评审中确认是否将以下内容设为两组共同接入范围：

1. OpenAlex API 定向采集。
2. DBLP 月度 snapshot 导入。
3. CORDIS 官方 open-data 文件导入。
4. NSF 官方文件或 API 导入。
5. 一种经批准的专利导入方式。
6. 国家科技奖人工复核 CSV 导入。

本调研建议 NSFC、Google Patents、需验证码或登录的 CNIPA 页面、省部级和学会奖项不作为核心必做连接器。最终范围以现有双组方案的变更审批结果和统一 SRS 为准。

## 11. 建议提交统一 SRS 确认的验收指标

下列指标属于成员 7 基于交叉核验提出的修改建议，不直接修改《双组并行开发与合并方案》。是否采用及最终阈值由成员 1、6 和相应测试负责人共同确认。

| 维度 | 指标 |
| --- | --- |
| 规模 | 去重且许可通过的 canonical 公开记录 ≥10,000 |
| 类型覆盖 | 四类成果均达到约定最低数量 |
| 可复现性 | A/B 输入 manifest、文件哈希、许可快照完全一致；同版本重跑计数差异为 0 |
| 来源完整性 | 公开记录的来源 ID、URL、采集时间、权利依据和审批状态完整率 100% |
| 必填字段 | 各类型主键、标题/名称、来源和时间字段完整率 ≥99% |
| 去重 | 至少 200 对人工标注；误合并率 ≤0.5%，漏合并率 ≤2% |
| 消歧 | 至少 200 条独立样本；报告 Precision、Recall、F1，建议 F1 ≥0.95 |
| 合规 | `pending/denied` 数据公开数为 0；未授权全文、图片、原始包公开数为 0 |
| 限流 | 自动化覆盖 401、403、429、`Retry-After`、超时、熔断和人工恢复 |
| 检索一致性 | 搜索索引和数据库可公开记录数差异 ≤0.1% |
| 安全 | 密钥进入日志次数为 0；AI 日志脱敏检查通过率 100% |
| 性能 | 在统一硬件上报告导入吞吐、失败率、峰值内存和检索 P95 |

## 13. 风险清单

| 风险 | 级别 | 处理 |
| --- | --- | --- |
| 两组输入不一致 | 高 | 冻结 shared-baseline manifest |

| 年度文件不可用 | 中 | API/搜索导出回退 |

## 15. 最终结论

本项目可以使用 OpenAlex、DBLP、CORDIS、NSF 和正式授奖页面构建主要演示数据；EPO OPS 和 USPTO 用作专利补充。NSFC、Google Patents、CNIPA 自动化及其他奖项来源在许可明确前不得承担核心进度。

本调研建议后续技术实现以“统一冻结输入、字段级许可、可追溯处理、去重后计数、两组共同验收”为数据基线。具体纳入方式由成员 1、6 依照既有双组方案审批；满足最终批准的验收指标并完成上线前人工复核后，数据链路方可进入公开演示。
