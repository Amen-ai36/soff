# 数据采集与治理需求

> 编制：成员 2
> 追踪需求：R02、R03、R04、R05、R11、R14
> 状态：需求建模阶段数据采集与治理需求，可直接作为统一 SRS 章节输入。

## 1. 范围与术语

本文件定义从公开来源或显式模拟数据到 canonical 成果记录的过程需求，包括来源适配、采集任务、清洗、去重、作者消歧、机构归一化、增量更新、数据质量和公开准入。

不在本文件范围：检索排序算法、认证与权限模型、门户认领审核、统计图表实现和前端视觉设计。

| 术语 | 含义 |
| --- | --- |
| Source Record | 某个来源的一条原始或解析后记录，保留来源主键和原始载荷哈希 |
| Canonical Work | 经清洗、合并和审批后进入统一成果表的记录 |
| Batch | 一次采集任务产生的有界记录集合 |
| Watermark | 数据源增量位置，可为时间、游标、页号或来源版本 |
| Candidate Pair | 等待比较或人工确认的重复或消歧候选 |
| Release Gate | 允许记录进入公开检索层前的许可与质量闸门 |

## 2. 采集与来源适配需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DR-COL-001 | 来源注册表应记录来源名称、官方链接、成果类型、接入方式、许可、限流、字段映射和负责人 | P0 | 每个启用的 source_id 均有这些字段；缺失项阻止 `approved` |
| DR-COL-002 | 每个来源使用独立适配器读取，不把来源字段直接写入 canonical 表 | P0 | 至少 4 类成果可映射到统一 Source Record；未知字段保留在扩展区 |
| DR-COL-003 | 支持 API、分页导出、冻结文件、人工 CSV 四类接入方式 | P0 | 每个适配器声明 `access_mode` 和可重复运行的输入参数 |
| DR-COL-004 | 采集范围必须可配置为时间、主题、机构、venue、记录数或来源游标 | P0 | 同配置重跑得到同一请求清单或明确差异说明 |
| DR-COL-005 | 每次请求保存来源 URL、请求摘要、响应状态、内容类型、下载时间、哈希和许可版本 | P0 | 任一公开 canonical 记录均可回溯到至少一个来源证据 |
| DR-COL-006 | 密钥、令牌和认证信息只能通过秘密引用注入 | P0 | 日志、任务参数和 Git 仓库中不得出现真实密钥 |
| DR-COL-007 | 遇到 401、403、429、验证码、内容类型异常或结构异常时不得当作空结果 | P0 | 任务状态为失败或部分失败；错误类型可区分 |
| DR-COL-008 | 429 使用 `Retry-After`，无该头时使用有上限的指数退避 | P0 | 自动测试覆盖 429、超时和恢复 |
| DR-COL-009 | 不支持绕过登录、验证码、付费墙、IP 封锁和来源禁止的自动化 | P0 | 代码审查和行为测试均无规避逻辑 |
| DR-COL-010 | 对来源原始载荷实行最小保留和访问控制 | P0 | 原始包不进入公开索引；保留期限可配置 |
| DR-COL-011 | 支持小样本探测模式 | P1 | 可在不触发大规模采集时验证字段、编码和成功判定 |
| DR-COL-012 | 支持来源停用和字段级下线 | P0 | 停用后可停止新增、隐藏对应公开字段并保留审计链 |
| DR-COL-013 | 抓取速率按来源独立配置，默认单并发 | P0 | 配置变更留痕；不能全局提高到来源上限 |
| DR-COL-014 | 模拟数据必须使用显式 source_id 和 `is_simulated=true` | P0 | 模拟记录在检索、详情和导出中可见标识，不冒充真实数据 |

| DR-TASK-003 | 任务状态至少覆盖排队、运行、停止中、已停止、重试等待、部分成功、成功和失败 | P0 | 状态机、接口和 UI 文案一致 |
| DR-TASK-004 | 任务应记录每个阶段的开始、结束、输入数、输出数、失败数和错误摘要 | P0 | 可从批次追溯到 fetched、parsed、cleaned、merged、persisted 数量 |
| DR-TASK-005 | 停止请求应使运行中的任务在安全边界停止 | P0 | 不在未完成事务或半写入批次中强制退出 |
| DR-TASK-006 | 重试应区分可重试错误和永久错误 | P0 | 网络超时、429 可重试；许可拒绝、解析契约不符默认不可自动重试 |

| DR-TASK-010 | 任务结束应生成摘要和质量报告 | P0 | 摘要可导出并在管理端查看 |

## 10. 非功能需求

1. 可重复性：同一输入、算法版本和配置重跑，计数和 canonical 主键差异应为 0；预期差异必须在报告中解释。
2. 可伸缩性：清洗和去重支持分批或流式处理，不能要求将完整来源数据集全部载入内存。
3. 安全性：秘密通过运行时注入；日志脱敏；原始数据目录最小权限。
4. 可观测性：任务阶段计数、耗时、错误类别、限流次数、质量指标和 checkpoint 可查询。
5. 兼容性：字段映射和算法版本可回退；公共字段语义变更须成员 1、6 共同确认。
6. 可用性：依赖失败和业务空结果必须返回不同状态。

## 11. 异常与人工恢复

| 场景 | 系统行为 |
| --- | --- |
| API 401/403 | 立即停止该来源任务，标记授权失败，不自动重试 |
| API 429 | 按 Retry-After 或退避策略进入等待，达到上限后失败 |
| 返回 HTML 挑战页 | 结构校验失败，不解析为业务记录 |
| 部分批次失败 | 交易提交成功批次，标记 `PARTIAL_SUCCESS`，保留失败清单 |
| 重复任务运行 | 返回既有 task_id 或拒绝创建，不启动第二个并发运行 |
| 人工停止 | 完成当前安全事务后转为 STOPPED，保留 checkpoint |
| 写库成功后索引失败 | 任务为部分成功，进入索引补偿，不重复写 canonical 表 |
| 合并结果争议 | 通过 merge_event 回滚并重算检索和统计 |
| 来源条款变化 | 暂停来源新增，待负责人更新 source_registry 后恢复 |

## 12. 验收标准

1. 至少完成 4 类成果的小样本端到端导入。
2. 10,000 条计数可由固定脚本基于 canonical 公开记录复算，且与任务摘要一致。
3. 采集任务状态图、接口状态和实际运行记录一致。
4. 清洗、去重、消歧、增量更新各有一组正例、边界和异常测试。
5. 至少 200 对人工标注去重样本和 200 条作者消歧样本完成评估。
6. 未授权字段、原始包、私人联系方式和模拟数据不会混入公共真实数据导出。
7. 同一 manifest 在 A/B 两组产生相同的公共记录数和字段语义。

## 13. 需要并入统一 SRS 的建议位置

建议成员 1、6 在 SRS 中新增“数据采集与治理”一章，并按以下顺序合并：

1. 数据源与许可；
2. 采集任务和状态；
3. 清洗与标准化；
4. 去重与消歧；
5. 增量更新；
6. 数据质量与公开准入；
7. 异常、人工恢复和验收。
