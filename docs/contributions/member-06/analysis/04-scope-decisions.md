# 成员9所提组长问题：成员6评审建议

2026-10-19。输入：[成员9交接问题](../../member-09/analysis/04-handoff-and-actions.md)第4.3节。以下是可供讨论的明确建议，成员1尚未共同确认；不是对公共SRS、API或验收的直接修改。确认前原文件继续保留候选分支。

## M6-DEC-01 筛选即时生效还是显式应用（IA9-Q01）

建议：公共语义统一为“明确已提交的有效条件决定结果，结果可解释且可复现”；一期B组优先采用显式“应用筛选”，方案A/B可在不改变该语义下保留不同触发方式。编辑条件与已生效条件在界面区分，未应用修改不得伪装为结果条件；执行查询后回到第一页，保持其他有效条件；晚到的旧请求不得覆盖新结果。

依据：成员9现有即时筛选分析与A组显式应用倾向存在差异。显式操作便于表达多条件组合、减少每次编辑的请求；缺少负载与可用性实测，不声称更快或已验证更易用。

影响：成员4/9筛选序列、有效条件状态；成员3/8实际收到的完整条件和稳定结果语义保持相同，不新增API字段。

验证建议：连续改两项后应用仅显示最终组合；旧响应晚到不覆盖；重试保留已生效条件；无结果与查询失败区分。由5、10后续实现验证，当前未执行。

## M6-DEC-02 批量操作是否纳入一期（IA9-Q06）

建议：一期先完成单条授权内维护、展示关联调整及公共字段纠错；批量维护作为扩展，不作为分析阶段的已承诺功能。需要覆盖课程成果管理目标，不能把“暂不批量”解释为删除全部维护。

影响：成员9门户维护保留单条路径，批量按钮/混合成功/批量回滚分支先列候选；成员3/8无需因界面草案新增批量写接口。如教师明确要求批量，重新给出权限、部分失败、重复执行和审计规则后共同确认。

验证建议：本人可维护授权范围，他人不可；删除个人关联不全局删除成果；共享字段变更进入治理，不直接覆盖公共元数据。

## M6-DEC-03 本地草稿保留与清除（FS9-Q01）

建议：一期认领表单的未提交非敏感内容只在当前会话内存中暂存；不默认写入持久浏览器存储，不暂存证明正文、密码、令牌或可复用证明下载链接。返回上一步可恢复当前会话输入；退出、切换账号、会话失效或明确放弃时清除。刷新/关闭页面可能丢失未提交草稿，离开前有可理解提示。

本建议不设虚构的“保留N天”。证明上传、服务端临时文件清理周期及材料归属由3、8另行定义。已提交申请的权威状态不随本地草稿清除而删除；提交结果不明时先查询权威记录，不盲目新建。

影响：4、9草稿状态与提示；3、8材料生命周期/归属校验。验证建议：退出后另一账号不能恢复草稿；浏览器后退不展示前账号私有内容；会话失效不泄漏证明；网络不明时不宣布已失败或已成功。

## M6-DEC-04 用户数据问题反馈是否纳入一期（EX9-Q06）

建议：保留一期授权内公共元数据纠错申请与管理员治理路径；面向任意访客的独立反馈工单系统先列扩展，避免新增未经定义的受理、回复、滥用治理和保存周期承诺。二者不是同一个范围。

影响：成员9可在失败页提供重试、返回、查看来源等已有操作；只有存在真实有效的联系渠道时才显示该入口，不能放虚假邮箱。若加入公开工单，需另补业务对象、权限、隐私与时序，经1、6确认。

验证建议：已有纠错权限路径可达；未实现反馈不显示成功提交；错误页不暴露私有材料；不把依赖故障当零结果。
