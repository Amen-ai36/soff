# 需求边界与优先级建议

状态：讨论草案，待成员 1、6 联合确认；不是已生效的 SRS 或验收标准。来源编号见本目录 README。

## 1. 范围建议

一期围绕四类学术成果、科研人员、机构与学术领域提供成果共享，包含数据获取与更新、清洗、检索、门户及认领、维护和统计。可先选一个学科领域组织演示数据，但仍覆盖四类成果和完整业务链路；该数据范围建议需共同确认。

系统边界内包括访客与登录用户操作、管理员管理、任务执行及数据处理。公开数据平台和身份材料的外部来源属于系统边界外；访问方式与验证方式需调研后确定，不承诺外部平台能力。

有偿科技成果转让、付费全文下载、专利交易及支付结算建议列为后期扩展，依据为 S1 正文第 1 页“后期成熟后应考虑”。由于验收同时要求背景需求全部实现，应请老师确认本期排除这些付费业务的理解。

## 2. 优先级原则

- P0：任务书或仓库明确要求，或完成完整业务链路的必要条件，必须覆盖。
- P1：需要共同选择的创新候选或增强项；“至少一项创新”本身是 P0 约束。
- P2：建议后期扩展，不能在存在歧义时直接认定已排除。

优先级不用于删除课程硬性要求；同级内部建议按数据可行性、前置依赖和用户证据安排顺序。以下只是需求调研的核查要点，不替代后续正式验收用例。

## 4. 创新候选建议

建议优先评估专家合作网络可视化的增强能力：领域和机构筛选、最短合作路径、中心度展示。它可以复用成果与作者关系，但前提是作者关联质量和样本网络足够支撑演示。基础专家关系网络已在背景中出现，不能仅展示一张网络图就认定满足创新要求。

备选为领域热点时序分析增强或基于内容的相关成果推荐。成员 7、8、9 共同提供数据、算法和界面可行性意见，成员 1、6 决策。当前未选定创新方案，也未增加第二项必做创新。
