# 架构决策记录 成员6主编候选

日期2026年11月9日。以下四条均为Proposed，成员1、6及相关岗位尚未共同批准；没有实施或性能验证证据。

## ADR M6 ARCH 01 分层业务模块与独立执行进程

背景：百万条公开成果目标、外部采集长任务、十人课程团队，在线认领需明确事务边界。七类逻辑职责不要求七个独立微服务。

候选：单进程同步执行所有工作；全面微服务；分层业务模块＋独立ETL/投影进程。

建议决策：采用第三种，业务模块用显式接口隔离，长任务持久受理后异步执行，不把抓取放在线请求内。

后果：部署与调试较简单、长任务可独立限流恢复；在线模块仍共享故障域，需监控worker积压与API资源争用。不能据此承诺吞吐或高可用。

验证：中止worker后任务仍可查，恢复不重复计数；采集阻塞不耗尽在线请求。成员2/7、3/8、5/10供实测后共同决定。来源S1、S2、S3。

## ADR M6 ARCH 02 权威事务与公开投影解耦

背景：数据库写入与索引写入不是天然同一事务，任一侧故障可能部分成功；B组分析已要求候选索引核验发布。

候选：同步双写后即宣称成功；事务outbox异步投影；仅定时全量重建。

建议决策：outbox与权威变更同事务记录，独立投影worker至少一次处理；候选版本集合核验后才公开切换，重建作为恢复路径。outbox不替代版本核验，也不保证恰好一次消费。

后果：可追踪补偿并减少丢变更风险；增加待办、回执、幂等与积压治理。涉及数据结构与事务范围，须7/8及1/6确认，不在本轮建立表。

验证：索引不可用、写成功回执丢失、重复和乱序事件；权威数据不丢、旧事件不覆盖新值、候选未就绪不发布。来源S4及成员2架构供稿。

## ADR M6 ARCH 03 检索和统计采用统一公开版本

背景：分析阶段要求完整合法集合、稳定分页及不泄漏统计分母，来源行数不能算成果数；CSS是云托管搜索候选。

候选：仅RDS全文查询；CSS投影加RDS权威状态；把CSS作为全部业务权威库。

建议决策：使用CSS中的Elasticsearch候选投影承接检索，RDS作为业务权威；检索与统计绑定已发布版本，按规范成果ID去重，权限在排序/分页/total及聚合前生效。

后果：搜索与事务职责清楚，但必须处理索引滞后、策略收紧及重建。若旧索引无法在查询前排除受限字段影响，关闭受影响查询并报依赖/同步异常，不能仅过滤当前页后返回错误total。

验证：同条数不同ID、撤回字段、旧快照、空集合、多机构多领域的分母对账；实际索引字段和性能由3/8确认。来源S5与M8-SEARCH/STATS。

## ADR M6 ARCH 04 先ECS运行 后按证据评估CCE

背景：课程需要华为云部署视图，但目前没有本项目规格、预算和容器运维证据。

候选：ECS上分进程；CCE编排；混合部署。

建议决策：以ECS＋RDS＋OBS＋CSS作为首轮候选，进程和配置保留可迁移边界；CCE作为后续独立扩容与发布需求下的替代。

后果：降低首轮部署概念复杂度；ECS单节点存在故障风险，备份不等于高可用。没有实际费用或资源授权前不采购、不声称已上线。

验证：5/10补私网、安全组、身份、健康检查、故障恢复和费用核查，再由1/6决定实际规格。云产品能力需查当时官方文档。
