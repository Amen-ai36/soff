# A 组候选部署与运行保障方案

状态：架构设计供稿，待成员 1、6 汇编及实际云环境复核

范围：华为云部署拓扑的组件职责、服务落点、数据流和运行保障
不在范围：创建云资源、填写真实账号/域名/IP/密钥、证明系统已上线

## 1. 从需求倒推部署边界

统一 SRS 的主链路是“公开来源/模拟数据 → 采集 → 清洗、去重和作者消歧 → 数据库与检索索引 → 检索、门户、认领、统计 → Web 前端与管理后台”。因此部署图不能只画一个 Web 服务和一个数据库；它至少要表达七类服务、原始数据和处理结果的落点，以及谁能访问受控认领材料。

| 需求能力 | 必须落到的运行位置 | 运行保障关注点 |
| --- | --- | --- |
| 数据采集 | 采集 Worker / 定时任务 | 限速、可停止、失败原因、批次与来源记录 |
| 清洗、去重、消歧、ETL | 处理 Worker / 异步任务 | 可重试但不重复计数；低置信度不自动合并 |
| 检索、筛选、排序 | 检索服务 + CSS | 索引版本、过滤权限、故障不能伪装为空结果 |
| 门户、认领、审核 | 业务服务 + RDS | 受控证明、原子授权、管理员不得自审 |
| 统计 | 统计服务 + RDS/CSS 的已确认数据 | 展示统计口径、批次/版本，避免读到半处理数据 |
| 认证和授权 | 认证服务 + RDS | 最小权限、会话失效、审计而不泄露证明正文 |
| 管理后台 | 管理端接口 + 管理前端 | 管理员权限隔离、任务停止/恢复与审核留痕 |

## 2. 供 CodeArts Modeling 复画的部署拓扑

正式图应由实际操作者在 CodeArts Modeling 绘制。下表是图上的节点、箭头和箭头含义，避免汇编时把“服务”与“云产品”混在同一层。

### 2.1 节点与职责

| 区域 | 图中节点 | 建议职责 | 不应声称的事实 |
| --- | --- | --- | --- |
| 外部 | 公开许可数据源 / 已标注模拟数据 | 输入数据；记录许可、来源和采集时间 | 不把收费库、绕过认证的数据源画进来 |
| 接入区 | Web 前端、管理前端、API 入口 | 访客查询；登录用户认领；管理员治理 | 尚未确定 CDN/WAF/网关产品时不写成已配置 |
| 计算区 | CCE 或 ECS 承载的业务服务 | 认证、检索、门户与认领、统计、管理后台 | CCE/ECS 是课程给出的部署组件候选，实际形态待环境确认 |
| 异步计算区 | 采集 Worker、ETL Worker、任务调度器 | 采集、清洗、去重、消歧、索引更新、失败恢复 | 不假定已有消息队列或具体调度框架 |
| 数据区 | RDS | 账号、业务元数据、认领状态、治理记录、任务和审计元数据 | 不把检索索引或原始大文件都塞进关系库 |
| 数据区 | OBS | 原始批次、导入文件、可追溯处理产物、非公开附件的受控对象存储 | 不公开桶、不在路径或日志里暴露证明材料 |
| 数据区 | CSS | 面向公开检索的索引副本 | 不作为认领证明的权威存储；索引延迟需被处理 |
| 运维区 | CodeArts / 日志、监控与告警（实际产品待定） | 构建、测试、制品、部署记录、运行事件 | 不把尚未配置的流水线或告警说成已运行 |

### 2.2 正式图的连线顺序

1. 浏览器访问 Web 前端/管理前端；前端只调用 API 入口，不直接访问 RDS、OBS 或 CSS
2. API 入口将认证、检索、门户认领、统计、后台治理请求分发给对应业务服务
3. 采集 Worker 从获准来源或模拟数据读取，先把原始批次及来源元数据存至 OBS，再创建可追溯的处理任务
4. ETL Worker 读取原始批次，输出清洗/去重/消歧结果；权威业务状态写 RDS，公开检索副本更新 CSS
5. 检索服务从 CSS 查询候选结果，并按已确认的公开范围/授权状态过滤；详情页可回查 RDS 的来源和更新时间
6. 门户、认领、审核和管理服务以 RDS 为权威状态；受控证明只通过受权路径读取 OBS，绝不进入公开索引
7. 统计服务只消费已完成且版本明确的数据；结果页展示统计口径、数据版本或更新时间
8. CodeArts 只向受控环境部署通过门禁的制品；日志/监控收集运行状态，不能把敏感证明正文写入日志

## 3. 服务通信与一致性边界

| 服务间关系 | 建议通信方式 | 为什么 | 待 ADR 确认点 |
| --- | --- | --- |
| 前端 ↔ 认证/检索/业务 API | HTTPS 同步请求 | 用户操作需要直接得到鉴权、结果或错误 | API 网关、会话方案和错误码尚未冻结 |
| 采集任务 ↔ ETL | 异步任务/任务状态驱动 | 采集、清洗、重试时长不可预测，不能阻塞管理端 | 队列/任务框架和取消语义 |
| ETL ↔ RDS | 事务性写入权威元数据 | 审核、认领和治理需有确定的权威状态 | 具体表结构与迁移方案 |
| 已确认数据 ↔ CSS | 可重放的索引更新 | 检索可扩展，但索引不是唯一事实来源 | 事务外盒、事件或补偿重建策略 |
| 统计 ↔ 已确认数据 | 只读查询或异步汇总 | 统计不应干扰在线认领和写入 | 实时/离线口径和刷新频率 |

**关键约束：**RDS 与 CSS 不能用“两个库随手同时写”一句带过。若最终 ADR 选择事务外盒、事件队列、定时补偿或全量重建，部署图和运行手册必须一致地写出失败重试、幂等键、重放和索引延迟的处理。当前没有冻结实现，不虚构选型结论。

## 4. 环境划分和最小权限

| 环境 | 可放什么 | 必须隔离什么 | 进入下一环境的前提 |
| --- | --- | --- | --- |
| 开发 | 合成夹具、匿名化/许可样本、开发配置 | 不使用真实证明材料和生产密钥 | 本地构建、静态检查及相关单元测试通过 |
| 测试/演示 | 固定版本夹具、可追溯模拟数据、候选制品 | 与开发/生产数据库、索引、对象存储分离 | API/端到端/数据质量场景的结果可记录 |
| 生产或课程最终演示 | 经批准的数据和正式制品 | 账号、密钥、认领证明、管理接口最小权限隔离 | 负责人批准、回滚方式与监控/备份实际可用 |

密钥应由环境变量或课程云环境的密钥能力注入，仓库只保留变量名和示例模板；部署图、文档、截图和日志均不得包含密码、令牌、真实 IP 或个人证明内容。

## 5. 运行保障：不能等到答辩才补

| 风险 | 最小控制 | 可观察证据 |
| --- | --- | --- |
| 采集任务重复或恢复后重复计数 | 批次号、检查点、幂等键、任务状态 | 同一输入重跑后成果计数和处理记录符合预期 |
| 清洗/消歧误合并 | 低置信度隔离，人工修正优先 | 冲突样例不自动合并且能回查来源 |
| CSS 延迟或不可用 | 查询失败与空结果区分；可重放索引更新 | 故障时返回明确错误；恢复后索引可对账 |
| 认领越权/自审/半授权 | 授权校验、审核回避、事务/补偿与审计 | 竞争申请仅一项成功，失败不留半授权 |
| 原始数据或证明泄露 | OBS 受控访问、日志脱敏、前端不直连对象存储 | 权限测试和日志抽查不含受限正文 |
| 错误部署或版本回退困难 | 制品版本、环境审批、回滚记录 | 能指出当前版本、上一个稳定版本和回退步骤 |
| 缺乏健康判断 | 服务健康检查、任务积压/失败、RDS/CSS 可用性指标 | 演示时可查看状态，不靠“页面能打开”代替监控 |

## 6. 展示时的两分钟说法

“我们把在线查询和重任务分开：门户、检索、认领、统计通过 API 服务响应；采集和 ETL 是异步任务。RDS 保存权威业务状态，OBS 保存原始批次和受控对象，CSS 只承载面向公开检索的索引。这样既能把检索扩展出去，又不把认领证明或审计状态暴露进索引。部署图采用华为云的 CCE/ECS、RDS、OBS、CSS；实际云资源、流水线命令和一致性机制会在 ADR 和环境落地后补为可验证结果，而不是提前写成已经上线。”
