## 事实边界

1. 统一 SRS 目前明确核心范围和验收方向，但尚未冻结技术栈、构建命令、公共 OpenAPI、精确性能指标和云资源账号。因此本文只给出可评审的架构方案与验收条件，**不把候选方案写成已经部署/已经通过测试**。
2. 课程要求的正式逻辑架构图、部署架构拓扑图应使用 CodeArts Modeling 绘制并保留源文件。本目录提供的是用于复画和评审的组件清单、连线语义与文字说明，不能充当 CodeArts 建模源文件。
3. 搜索引擎选型、ETL 异步化和 RDS/CSS 一致性属于至少 3 条 ADR 的核心内容。本文只列出运行保障侧必须承接的后果；最终决策文本由成员 1、6 汇总并与成员 2、3、6、7、8 复核。

## 交接前的最小动作

1. 成员 1、6 把统一服务名、方案 A/B 差异和至少 3 条 ADR 的最终表述冻结后，更新本目录中标为“待 ADR 确认”的位置
2. 实际部署操作者在 CodeArts Modeling 画出正式部署图，导出清晰 PNG，并把源文件与导出图放入统一交付目录
3. A、B 两组实现负责人提供真实构建、测试、镜像/制品、环境变量与部署命令；成员 5、10 再据此把门禁从“设计”落成可执行流水线
4. 汇编负责人将本目录内容并入**一份**统一报告；不要将 A 组本目录和 B 组另行打包为两份正式作业
