# 成员 4 建模 PPT 交接内容

用途：交给成员 5/10，并入唯一一份需求调研/建模 PPT。建议占 2～3 页，不单独制作 A 组正式 PPT。

## 第 1 页：普通用户证据如何影响页面

标题：问卷证据驱动的检索与门户需求

建议内容：

- 问卷于 2026-09-22 实施，设置为不可重复填写；PDF 汇总样本 35 人，其中本科生 32 人、硕士生 3 人。
- 15/30 从关键词开始，23/30 使用主题关键词：关键词检索作为首页主入口。
- 23/30 使用领域筛选，16/30 使用成果类型，15/30 使用年份：三类条件优先。
- 20/30 有时或经常搜不到成果，19/30 有时或经常面对结果过多：空结果和筛选反馈必须可操作。
- 18/30 用领域、18/30 用代表成果区分同名学者：学者结果需要消歧信息。

页脚限制：样本以学生为主，不代表科研人员和管理员；各题分母不同。

## 第 2 页：方案 A 信息架构与关键流程

标题：从检索到门户认领的连续任务

建议展示：

```text
首页检索 -> 结果过滤 -> 成果详情/学者门户
                           |
                           `-> 登录 -> 提交认领 -> 查询状态 -> 审核通过后维护
```

讲解要点：

- 访客、登录用户、已认领学者和管理员按权限分开。
- 登录不等于认领，提交申请也不等于获得维护权。
- 业务空结果与依赖失败使用不同页面状态。
- 个人字段、成果关联和共享成果元数据使用不同维护入口。

## 第 3 页：可验证的 UI 要求

标题：页面状态与验收

建议内容：

- 17 个 Given/When/Then 场景覆盖检索、筛选、空结果、依赖失败、同名学者、门户、认领、冲突、隐私、键盘和窄屏。
- 低保真线框覆盖首页、检索结果、学者门户、认领申请和状态查询。
- 待共同冻结：高级搜索字段、筛选应用方式、认领扩展状态、移动端一期范围。
- 尚未执行真实原型测试，不写“可用性已验证”。

## 口头讲稿（约 60～75 秒）

我们把问卷作为普通用户探索性证据，而不是三类角色的完整验证。结果支持把关键词检索设为主入口，同时保留领域、成果类型和年份筛选。用户最明显的问题是搜不到以及结果过多，因此页面必须把业务空结果、筛选建议和系统故障区分开。学者场景中，领域和代表成果是主要消歧依据，门户优先展示研究方向和四类成果。认领流程则明确区分登录、提交申请、审核和获得维护权。当前线框与 17 个验收场景可供 SRS 和后续前端测试使用，但接口字段、扩展状态和移动端范围仍需共同确认。
