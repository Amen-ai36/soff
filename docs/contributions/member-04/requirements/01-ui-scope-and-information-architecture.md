# UI 范围、角色边界与信息架构

状态：成员 4 方案 A 贡献草案。`UI4-*` 是局部追踪编号，待成员 1/6 汇编后映射到统一 SRS。本文不定义 API 路径、数据库字段或正式状态枚举。

## 1. 角色边界

| 角色 | 可见能力 | UI 必须防止的误解 |
| --- | --- | --- |
| 访客 | 检索成果/学者、查看详情、门户和公开统计 | 浏览公开门户不代表拥有该门户 |
| 登录用户 | 继承访客能力，提交认领并查看本人申请 | 登录成功不代表认领成功或获得维护权 |
| 已认领学者 | 维护授权门户、提交成果补录或关联纠错 | 不能修改他人门户或直接删除共享成果本体 |
| 平台管理员 | 管理采集、审核认领、处理治理问题 | 不能自审；权限仍须由服务端校验 |

“普通用户”在调研材料中仅指公开检索和浏览场景。认领申请人、已认领学者和管理员按行为与权限分别建模，解决旧材料把研究人员及审核诉求混入普通用户的问题。

## 4. 导航要求

| 编号 | 要求 | 验证方式 |
| --- | --- | --- |
| UI4-FR-01 | 全局导航应提供成果、学者、统计和登录/个人入口；当前栏目可识别 | 页面走查 |
| UI4-FR-02 | 首页首要操作是关键词检索，并允许明确选择“成果”或“学者”对象 | 问卷证据、任务走查 |
| UI4-FR-03 | 领域浏览和高级检索作为可发现的次级入口，不遮挡简单检索 | 原型任务测试 |
| UI4-FR-12 | 页面应显示数据来源、更新时间或统计快照信息；缺失时显示“未提供”，不伪造值 | 字段和缺失状态检查 |

## 5. 全局页面状态

所有数据页面至少设计下列互斥或可组合状态：

| 状态 | 页面反馈 | 禁止行为 |
| --- | --- | --- |
| 初始 | 给出任务入口和必要示例 | 不把初始状态显示成“0 条结果” |
| 加载 | 保持页面框架稳定，标识正在处理 | 不允许同一提交被连续触发 |
| 成功 | 显示结果、条件和数据版本 | 不隐藏当前筛选条件 |
| 业务空结果 | 明确无匹配，提供改词和清筛选操作 | 不写成服务异常 |
| 依赖失败 | 显示可识别错误、重试入口和追踪标识（如公共契约提供） | 不伪装成 `total=0` |
| 无权限 | 说明需要登录或无访问权 | 不泄露受限记录和材料是否存在 |
| 部分数据缺失 | 用“未提供/未知”表达 | 不用 `0` 代替未知 |
| 内容已下线 | 使用统一不可访问反馈 | 不继续展示缓存敏感信息 |

## 6. 不在本阶段冻结的内容

- API URL、字段名、分页格式和错误码。
- PENDING/APPROVED/REJECTED 之外是否增加“需补充”“撤回”等状态。
- 高保真视觉风格、品牌颜色、字体和最终组件库。
- 移动端是否纳入一期正式验收；本包只要求布局具备基本响应能力。
- 创新功能最终选择；相关成果推荐和合作网络均仅为候选。
