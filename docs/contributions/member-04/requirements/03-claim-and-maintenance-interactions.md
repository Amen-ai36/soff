## 2. 认领申请流程

```text
公开门户
  -> 选择申请认领
  -> 未登录时完成登录
  -> 阅读流程与隐私说明
  -> 填写关系说明并引用/上传允许的证明材料
  -> 提交前复核
  -> 服务端校验材料、重复申请和门户占用
  -> 创建待审核申请
  -> 显示申请编号和状态查询入口
```

候选表单内容：目标门户摘要、申请人与目标关系说明、证明材料、联系方式、授权与隐私确认。材料类型、大小、保留期限和上传方式必须等待公共规则确认，线框稿只保留占位区域。

## 3. 状态展示

当前跨岗位材料中可共同识别的最小提案为：

| 业务状态提案 | 用户显示 | 可用操作 |
| --- | --- | --- |
| PENDING | 待审核 | 查看申请；是否允许撤回待确认 |
| APPROVED | 已通过 | 进入授权门户维护 |
| REJECTED | 已驳回 | 查看理由；修正后是否新建申请按公共规则 |

旧成员 4 材料中的“需要补充材料”可以作为 UI 展示需求候选，但不是已冻结公共状态。若成员 1/6、3/8 决定采用扩展状态，必须同步 SRS、状态图、SPEC、接口、页面和验收场景；否则通过“有理由驳回后新建申请”表达。

## 4. 重复、占用和并发反馈

| 场景 | 用户反馈 | UI 后续动作 |
| --- | --- | --- |
| 本人已有待审申请 | 告知已有申请及编号 | 打开既有申请，不重复创建 |
| 门户已被认领或不可申请 | 使用不泄露他人私密信息的冲突提示 | 返回门户或提交纠错 |
| 材料不完整 | 标出缺少或不合法的字段 | 保留其他已填内容 |
| 重复提交同一请求 | 展示权威申请结果 | 不显示两个成功申请 |
| 审核期间被他人先处理 | 告知记录已更新 | 刷新最新状态，不覆盖 |
| 持久化失败 | 明确提交未确认成功 | 允许查询权威状态后再决定是否重试 |

## 5. 审核工作台 UI 边界

管理员界面由成员 4 提供交互层，业务规则由成员 3/8 负责。至少需要：

- 申请列表按状态、时间和必要条件筛选。
- 申请详情显示目标门户、申请人公开上下文、受控证明材料入口和历史决定。
- 当前管理员是申请人或无权审核时，操作不可用且服务端仍须拒绝。
- “通过”和“驳回”使用不同确认文本；驳回理由为业务必填提案。
- 提交决定期间禁用重复操作；冲突时刷新权威状态。
- 通知失败不应让页面把已经提交的审核决定显示为未提交。

## 6. 门户维护

| 内容类型 | UI 处理 | 权限边界 |
| --- | --- | --- |
| 个人公开字段 | 编辑、校验、保存并显示更新时间 | 只针对授权门户 |
| 成果展示关联 | 提交新增、纠错或移除本人展示关联 | 不等于删除成果本体 |
| 共享成果元数据 | 提交纠错或治理请求 | 不允许单个学者直接覆盖所有作者共享内容 |
| 外部采集值冲突 | 显示冲突和来源 | 不静默覆盖人工修正 |

编辑页面必须显示当前版本或更新时间。若保存时版本已变化，应保留用户输入、提示冲突，并提供重新加载/比较入口；具体并发字段由公共接口确定。

## 7. 问题反馈

反馈入口至少携带目标对象，允许选择错误、重复、来源失效、信息不完整或不当公开等类型。提交后显示反馈编号或可查询入口（以最终后端能力为准）。涉及隐私或撤下请求时，不在公开页面展示提交人的联系方式和证据。
