# 用户与页面交互分析

状态：成员 4 第 7～8 周供稿。本文从前端边界补充关键用例交互，不替代成员 2/7 的数据流程时序图或成员 3/8 的检索、认领业务时序图。

## 1. 分析目标与参与者

交互分析关注“用户看见什么、可以做什么、页面如何响应、失败后如何恢复”，不规定后端接口路径或数据表。参与者沿用统一 SRS：访客、登录用户、已授权学者、管理员；外部系统只按检索、认证和认领等分析级职责出现。

| 参与者 | 进入页面 | 主要目标 | 必须阻止的误解 |
| --- | --- | --- | --- |
| 访客 | 首页、检索结果、成果详情、学者门户、公开统计 | 查找并判断成果或学者信息 | 公开门户不等于本人已认领 |
| 登录用户 | 访客页面、认领申请、我的申请 | 提交本人门户认领并查询结果 | 登录成功不等于认领成功 |
| 已授权学者 | 门户维护、成果关联纠错 | 维护授权范围内的个人展示 | 移除展示关联不等于删除公共成果 |
| 管理员 | 认领审核工作台、采集任务概览 | 在职责内处理申请和数据治理 | 管理员不能自审，页面可见不等于服务端授权 |

## 2. 页面边界与导航关系

| 当前页面 | 用户动作 | 前置条件 | 页面迁移/结果 | 关键异常出口 |
| --- | --- | --- | --- | --- |
| 首页 `UI4-P01` | 选择成果/学者并提交关键词 | 无 | 检索结果 `P02`，保留对象和关键词 | 非法输入停留首页；服务失败进入可重试失败态 |
| 检索结果 `P02` | 改词、筛选、排序、翻页 | 检索版本有效 | 原页面更新；选择条目进入 `P03/P04` | 空集、版本失效、依赖失败分别反馈 |
| 成果详情 `P03` | 打开作者门户、来源或反馈入口 | 记录仍可公开 | 学者门户 `P04`、可信外链或反馈 `P10` | 下线、来源失效、字段缺失 |
| 学者门户 `P04` | 选择四类成果、申请认领、进入维护 | 入口随会话和授权变化 | 列表更新、登录 `P06`、申请 `P07` 或维护 `P09` | 门户被占用、无权限、内容下线 |
| 登录 `P06` | 完成认证 | 原任务上下文可安全恢复 | 返回原门户/申请入口 | 凭据错误、会话服务失败、上下文不可恢复 |
| 认领申请 `P07` | 填写、复核、提交 | 登录且目标可申请 | 成功进入申请详情 `P08` | 字段错误、重复申请、门户占用、提交结果未知 |
| 我的申请 `P08` | 查看状态、理由和后续动作 | 申请属于当前用户 | 展示权威 `PENDING/APPROVED/REJECTED` | 无权限时不泄露记录是否存在 |
| 门户维护 `P09` | 编辑个人字段、调整展示关联、提交纠错 | 当前授权有效 | 保存成功、待同步、治理请求或冲突 | 会话失效、字段越权、版本冲突、保存失败 |
| 认领审核 `P11` | 查看证据、通过/驳回 | 管理员且非申请人 | 权威结果与审计状态 | 自审、过期版本、门户已被占用、通知失败 |

## 3. 关键交互一：检索与查看

图源：[检索与查看交互时序图](diagrams/01-search-and-view-sequence.puml)。图中的操作名是分析语言，不是公共 API。

### 3.1 正常路径

1. 用户选择“成果”或“学者”，输入关键词并可选设置条件。
2. 页面先完成本地格式校验，再进入加载态；旧请求结果不得覆盖新请求。
3. 检索服务在公开数据范围内返回结果、总数语义、排序、分页和数据版本。
4. 页面显示当前条件与版本，用户打开成果详情或学者门户。
5. 详情页展示来源和更新时间；缺失值用“未提供/未知”，不伪造为 0。

### 3.2 分支与边界

| 分支 | 页面判定 | 反馈与恢复 |
| --- | --- | --- |
| 输入非法 | 提交前或服务端确认字段不合法 | 定位到字段，保留其他条件，焦点移到首个错误 |
| 业务空结果 | 请求成功且 `total=0` | 保留关键词和筛选，提供改词和清筛选操作 |
| 依赖失败 | 无法完成可靠查询 | 不渲染为 0 条；提供重试和追踪信息（若契约提供） |
| 数据版本失效 | 翻页/返回时原版本不可继续 | 使用原条件重新查询，不把新旧页混合 |
| 内容已下线 | 打开条目时已不允许公开 | 清除受限缓存，显示统一不可访问反馈 |
| 同名学者 | 相同显示名对应不同实体 ID | 保留多条结果，并展示机构、领域、代表成果等区分信息 |

### 3.3 页面职责划分

- 首页只负责建立查询意图，不提前声称命中数量。
- 结果页负责呈现条件、排序、分页和版本，不自行更改排序口径。
- 详情/门户页负责可解释展示，不用前端拼接私有字段补齐公开数据。
- 浏览器历史返回应恢复用户可理解的条件；若版本不可继续，明确提示刷新。

## 4. 关键交互二：门户认领

图源：[门户认领交互时序图](diagrams/02-claim-sequence.puml)。业务状态和并发语义引用 `SPEC-M3-CLAIM` 与 `SPEC-M8-CLAIM` 的共同部分，仍待公共确认。

### 4.1 正常路径

1. 访客在可申请门户选择“申请认领”。
2. 未登录时进入登录页；认证成功后只恢复目标门户与允许的非敏感上下文。
3. 登录用户阅读材料用途和隐私说明，填写关系说明并引用/上传允许的证明材料。
4. 用户在提交前复核目标门户和材料摘要；页面进入提交中并阻止重复操作。
5. 服务端创建 `PENDING` 申请后，页面显示申请编号、提交时间和查询入口；维护入口仍不可用。
6. 后续查询以权威状态为准：`APPROVED` 才显示维护入口，`REJECTED` 显示允许公开给申请人的理由及重新申请路径。

### 4.2 特殊路径

| 场景 | 页面响应 | 不得发生 |
| --- | --- | --- |
| 本人已有待审申请 | 打开既有申请并显示权威编号 | 再显示第二个“提交成功” |
| 同一提交结果未知 | 先查询权威状态，再允许重试 | 仅因超时就创建新申请 |
| 门户已被认领/不可申请 | 显示不泄露他人信息的冲突反馈 | 暴露认领人材料或联系方式 |
| 审核冲突 | 刷新最新状态，要求管理员重新判断 | 用旧页面覆盖已提交决定 |
| 通知失败 | 审核页仍显示已保存决定，另示通知待处理 | 把通知失败显示为审核未提交 |
| 会话过期 | 保存允许保留的非敏感表单内容并引导登录 | 在 URL、本地日志或公开缓存中保存证明内容 |

## 5. 关键交互三：门户维护与纠错

| 用户意图 | 页面操作 | 服务端结果类别 | 页面反馈 |
| --- | --- | --- | --- |
| 修改个人公开字段 | 编辑白名单字段并带当前版本保存 | 已保存 / 版本冲突 / 无权限 | 成功显示新版本；冲突保留草稿并提供比较/重载 |
| 新增或移除个人展示关联 | 选择成果并说明关系 | 已接受 / 进入治理 / 冲突 | 区分“展示关联变更”与“公共成果删除” |
| 纠正共享成果字段 | 提交纠错依据 | 创建治理请求 | 显示请求编号，不写成成果已修改 |
| 采集值与人工值冲突 | 查看来源与差异 | 待治理 | 并列展示可公开差异，不静默覆盖人工修正 |
| 保存成功但索引未同步 | 查询权威记录 | 已保存、待同步 | 区分“已保存”和“公开检索尚未更新” |

## 6. 交互一致性规则

1. 页面主操作在请求处理中保持稳定位置，并禁用重复触发。
2. 成功提示只在权威写入确认后出现；网络超时使用“结果待确认”，不直接写“提交失败”。
3. 返回和刷新不得丢失已生效筛选、权威申请状态或允许保留的非敏感草稿。
4. 登录、申请通过、保存、发布/同步使用不同文案，避免把身份、授权和展示混为一体。
5. 对象已下线或权限撤销时，前端立即清除受限内容并重新读取权限；不能依赖旧按钮状态继续写入。
6. 每个异步结果绑定请求标识或等价机制；晚到的旧响应不得覆盖当前页面。
