# 前端状态变化分析

状态：成员 4 第 7～8 周供稿。本文描述用户可观察的前端状态，不新增后端业务枚举。

## 1. 状态分层

前端页面不能只用一个 `loading` 布尔值表达全部情况。建议每个关键页面按以下正交维度组合状态：

| 维度 | 候选值 | 说明 |
| --- | --- | --- |
| 路由/对象 | 未定位、已定位、对象失效 | 当前页面和目标对象是否仍可访问 |
| 会话/权限 | 匿名、已登录、已授权、无权限、会话过期 | 仅影响可见操作，不能替代服务端校验 |
| 请求 | 空闲、校验中、加载中、提交中、重试中 | 同一主操作只允许一个有效请求 |
| 数据 | 未加载、成功有数据、成功空数据、部分缺失、过期、失败 | 空数据与失败必须分开 |
| 表单 | 原始、编辑中、校验失败、未保存、保存中、冲突 | 离开页面前只对真实未保存修改提示 |
| 同步 | 已保存已同步、已保存待同步、同步失败 | 维护场景区分权威保存与检索展示 |

可编辑总图见 [前端视图状态图](diagrams/03-frontend-view-state.puml)。图分为检索、认领和门户维护三个复合状态。

## 2. 检索页状态机

| 当前状态 | 事件 | 守卫/判定 | 下一状态 | 页面副作用 |
| --- | --- | --- | --- | --- |
| `INITIAL` | 提交查询 | 本地格式合法 | `LOADING` | 保存当前条件快照，禁用重复提交 |
| `INITIAL` | 提交查询 | 本地格式非法 | `INVALID` | 字段报错并聚焦首个错误 |
| `INVALID` | 修改字段 | 字段重新合法 | `INITIAL` | 清除对应错误，不清除其他条件 |
| `LOADING` | 新查询提交 | 新请求有效 | `LOADING` | 取消或作废旧请求，更新条件快照 |
| `LOADING` | 成功且有数据 | `total>0` | `RESULTS` | 原子替换结果、总数、排序、版本 |
| `LOADING` | 成功且为空 | `total=0` | `EMPTY` | 保留条件，显示改词/清筛选操作 |
| `LOADING` | 依赖/网络失败 | 无可靠结果 | `ERROR` | 保留条件，不沿用旧总数冒充本次结果 |
| `RESULTS/EMPTY` | 改筛选/排序 | 条件合法 | `LOADING` | 排序或筛选变化回到第一页 |
| `RESULTS` | 翻页 | 数据版本有效 | `LOADING` | 继续使用同一查询版本或快照 |
| `RESULTS` | 版本失效 | 无法稳定继续 | `STALE` | 保留条件，停止混合新旧页 |
| `STALE` | 重新查询 | 用户确认或自动策略获批 | `LOADING` | 从第一页建立新版本 |
| `ERROR` | 重试 | 条件仍有效 | `LOADING` | 使用同一条件发起新请求 |

### 2.1 竞态约束

- 每次查询生成单调递增请求序号或取消令牌；只有当前请求可提交结果。
- 新筛选触发后，旧列表可保留为视觉占位，但必须标识加载且不可被误认为新条件结果。
- 详情返回结果页时，先恢复条件，再验证版本；不能先展示混合页后静默修正。
- 重试不得重置用户输入，也不得把缓存结果当成本次成功响应。

## 3. 认领页面状态机

### 3.1 前端视图状态与业务状态映射

| 前端视图状态 | 含义 | 对应业务状态 | 可用主操作 |
| --- | --- | --- | --- |
| `LOGIN_REQUIRED` | 用户尚未建立有效会话 | 无 | 登录并返回 |
| `EDITING` | 正在填写或复核材料 | 尚未创建 | 保存允许的本地草稿、提交 |
| `INVALID` | 页面或服务端字段校验未通过 | 尚未创建 | 修正字段 |
| `SUBMITTING` | 创建请求进行中 | 未知 | 等待；禁用重复提交 |
| `OUTCOME_UNKNOWN` | 请求超时/断网，无法判断是否已创建 | 可能无，也可能 `PENDING` | 查询权威状态 |
| `PENDING_VIEW` | 已确认存在待审申请 | `PENDING` | 查看申请；撤回是否可用待确认 |
| `APPROVED_VIEW` | 已确认审核通过 | `APPROVED` | 进入授权门户维护 |
| `REJECTED_VIEW` | 已确认审核驳回 | `REJECTED` | 查看理由；按公共规则新建申请 |
| `CONFLICT` | 重复申请、门户占用或版本冲突 | 读取后确定 | 打开既有申请或刷新门户 |
| `FORBIDDEN` | 当前主体无权读取或操作 | 不公开 | 登录/返回，不泄露私有对象 |

`EDITING/SUBMITTING/OUTCOME_UNKNOWN/CONFLICT` 都是前端状态，不能写进认领申请表的正式业务枚举。

### 3.2 迁移规则

| 当前状态 | 事件 | 下一状态 | 关键处理 |
| --- | --- | --- | --- |
| `LOGIN_REQUIRED` | 登录成功 | `EDITING` | 只恢复安全的目标 ID 和非敏感上下文 |
| `EDITING` | 提交且本地合法 | `SUBMITTING` | 冻结当前提交快照，防双击 |
| `EDITING` | 提交且本地非法 | `INVALID` | 定位字段并保留非敏感输入 |
| `SUBMITTING` | 创建成功 | `PENDING_VIEW` | 显示权威申请编号，不开放维护 |
| `SUBMITTING` | 已有待审申请 | `CONFLICT` | 提供打开既有申请入口 |
| `SUBMITTING` | 门户被占用 | `CONFLICT` | 返回门户或提交纠错，不泄露占用者私密信息 |
| `SUBMITTING` | 超时/断网 | `OUTCOME_UNKNOWN` | 不直接允许再次创建；先查询权威状态 |
| `OUTCOME_UNKNOWN` | 查到申请 | `PENDING_VIEW` | 绑定权威编号 |
| `OUTCOME_UNKNOWN` | 确认未创建 | `EDITING` | 恢复可保留内容后允许重试 |
| `PENDING_VIEW` | 权威状态更新 | `APPROVED_VIEW/REJECTED_VIEW` | 状态、时间、理由一起更新 |
| 任意受限状态 | 会话过期/授权撤销 | `LOGIN_REQUIRED/FORBIDDEN` | 清除证明材料显示与受限缓存 |

## 4. 门户维护状态机

| 当前状态 | 事件 | 下一状态 | 页面行为 |
| --- | --- | --- | --- |
| `CLEAN` | 修改允许字段 | `DIRTY` | 标记未保存，不立即声称已更新 |
| `DIRTY` | 本地校验失败 | `INVALID` | 字段级反馈，保留草稿 |
| `DIRTY` | 保存 | `SAVING` | 带当前版本提交，禁用重复保存 |
| `SAVING` | 权威保存成功且已同步 | `SAVED` | 显示新版本和更新时间 |
| `SAVING` | 保存成功但索引待同步 | `SYNC_PENDING` | 明确“已保存，公开检索稍后更新” |
| `SAVING` | 版本冲突 | `CONFLICT` | 保留草稿，加载权威版本供比较 |
| `SAVING` | 无权限/授权撤销 | `FORBIDDEN` | 停止保存并清除受限内容 |
| `SAVING` | 依赖失败且结果未知 | `OUTCOME_UNKNOWN` | 查询权威版本后决定是否重试 |
| `SYNC_PENDING` | 同步完成 | `SAVED` | 更新公开可见状态 |
| `SYNC_PENDING` | 同步失败 | `SYNC_FAILED` | 保留权威保存成功事实，提供状态查询 |
| `CONFLICT` | 放弃草稿并重载 | `CLEAN` | 使用权威版本 |
| `CONFLICT` | 人工合并后再保存 | `SAVING` | 使用新预期版本，不自动覆盖 |

## 5. 全局状态规则

1. 页面状态必须从权威响应和本地事件共同推导，不能仅从 HTTP 成功与否推导业务成功。
2. 业务空态、部分字段缺失、依赖失败、无权限和内容下线是不同状态，使用不同文案与操作。
3. 页面刷新后，公开查询条件可从 URL 或安全状态恢复；证明材料、私有联系方式和内部审核信息不得进入 URL。
4. 会话过期后只恢复允许的非敏感输入；敏感附件是否保留由安全和上传设计决定。
5. 浏览器前进/后退、重复点击、响应乱序、断网恢复和多标签页并发均应进入后续前端测试。

## 6. 待决项

- 查询版本由页码快照、游标还是其他机制表达，属于公共接口设计。
- “需补充材料”若获批准，应同时更新业务状态模型、接口、页面和验收，不通过前端标签私自增加。
- 保存成功后的检索同步状态是否对用户展示，需成员 3/8 根据实现能力确认。
