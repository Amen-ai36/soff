# 核心页面设计说明

状态：承接已有低保真线框的可实现结构；图片原型仍是示意，未通过真实用户测试。

## 1. 首页和检索结果（P01/P02）

首页首屏只有一个主检索任务：对象切换（成果/学者）、关键词输入、提交和可发现的高级条件。结果页固定显示检索对象、关键词、已应用条件、排序、total 语义、数据版本和结果列表。筛选在桌面侧栏、窄屏折叠面板呈现。

结果卡片按“题名/姓名 -> 年份、类型、机构/领域 -> 来源、更新时间、状态”分层。字段未知使用“未提供/未知”，真实为 0 使用明确的 0；业务空结果和依赖失败使用不同 `StatusPanel`。

## 2. 成果详情和学者门户（P03/P04）

详情页展示公开元数据、作者/机构关联、来源链接、更新时间和数据状态；外链失效时只提示状态，不自动跳转到未经校验地址。门户首屏优先姓名、机构、研究方向/简介和四类成果入口，再展示公开统计、认领状态及候选创新入口。

门户不得把“已认领”写成全部成果真实性背书；未认领门户仍可公开浏览，但不能出现私有申请或证明信息。

## 3. 登录、认领和申请状态（P06/P07/P08）

认领表单先展示流程、用途和隐私说明，再填写关系说明、允许的证明材料占位、联系方式和确认项。材料类型、大小、访问者和保留期等待公共规则确认，原型不写死。提交成功只显示申请编号、时间和 `PENDING` 等公共状态，维护入口保持不可用。

申请详情按当前用户权限显示状态、时间、公开理由和可用操作。`OUTCOME_UNKNOWN` 时先查权威申请，不直接生成第二个申请；私有申请对无权主体使用中性的无权限反馈。

## 4. 门户维护和管理工作台（P09～P12）

维护页把个人公开字段、成果展示关联、共享成果纠错分成三个区域，并显示当前版本/更新时间。保存成功但索引未同步时显示“已保存，公开检索稍后更新”；版本冲突保留草稿并提供比较/重载。

审核工作台采用“列表 -> 详情 -> 明确决定”的路径。通过和驳回使用不同确认文案；决定提交中禁用重复操作，冲突时刷新权威状态。采集任务页只展示任务、尝试、批次和运行反馈，不在 UI 重新定义成员 2/7 的任务状态。
