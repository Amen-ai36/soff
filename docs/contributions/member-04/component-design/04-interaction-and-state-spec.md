# 关键交互与状态设计

状态：成员 4 UI 构件候选；业务终态沿用成员 3/8 公共规范。

## 1. 检索交互

1. 提交时保存条件快照并生成本地请求序号；提交中禁用同一主操作。
2. 结果、total、排序、版本一次性替换；旧响应序号低于当前值时丢弃。
3. `total=0` 只有在服务端确认查询成功且公开集合为空时才进入业务空态。
4. 依赖失败保留条件并显示重试；版本失效停止混合分页，提供重新查询。
5. 从详情返回时恢复条件，不能把浏览器缓存当成当前版本成功结果。

## 2. 认领交互

| 前端视图 | 触发 | 结果/动作 |
| --- | --- | --- |
| `LOGIN_REQUIRED` | 未登录点击认领 | 登录并恢复安全上下文 |
| `EDITING` | 填写或修改 | 本地草稿只保留非敏感内容 |
| `INVALID` | 字段校验失败 | 聚焦首个错误，保留其他输入 |
| `SUBMITTING` | 合法提交 | 锁定快照，禁用重复提交 |
| `OUTCOME_UNKNOWN` | 超时/断网 | 查询权威状态，不直接重试创建 |
| `PENDING_VIEW` | 申请已确认 | 查看申请，维护入口不可用 |
| `APPROVED_VIEW` | 通过 | 进入授权门户维护 |
| `REJECTED_VIEW` | 驳回 | 查看可公开理由，按规则重新申请 |
| `CONFLICT/FORBIDDEN` | 重复/占用/无权 | 打开既有申请、返回门户或中性反馈 |

## 3. 维护和同步

维护编辑使用 `CLEAN -> DIRTY -> SAVING`；服务端返回版本冲突进入 `CONFLICT`，保存成功但投影未更新进入 `SYNC_PENDING`。页面绝不把投影延迟写成权威保存失败，也不在冲突时静默覆盖新版本。

## 4. 异常反馈模板

每个关键异常包含“发生了什么、当前结果、可以做什么、保留了什么”四部分。字段错误贴近控件；空结果和依赖失败占据主内容区；高风险决定用确认对话框；关键反馈不能只用 toast。错误正文不含堆栈、数据库键、令牌、证明材料或私有联系方式。

## 5. 实现验收输入

本设计直接映射已有 `UI4-AC-01～17`：快速检索竞态、空态/故障态、未知值、未登录认领、重复申请、审核冲突、维护版本冲突、键盘、窄屏和隐私隔离。它们是测试设计输入，不表示测试已经执行。
