# 信息架构与导航设计

状态：A 组 UI 构件候选；具体 URL 和权限以公共契约为准。

## 1. 导航分区

```text
PublicShell
├─ 首页/全局检索（P01）
├─ 成果结果/详情（P02/P03）
├─ 学者结果/门户（P04）
└─ 公开统计（P05）

AccountShell
├─ 登录（P06）
├─ 认领申请/我的申请（P07/P08）
├─ 门户维护（P09）
└─ 纠错与反馈（P10）

AdminShell
├─ 认领审核（P11）
└─ 采集任务（P12）
```

公开区不要求登录；登录用户可返回原公开目标；管理员入口不在公开导航中暴露业务细节。导航显示是体验优化，真正授权由服务端执行。

## 2. 页面骨架

每个页面采用稳定的 `Header -> Breadcrumb/Context -> Main -> StatusRegion -> Footer` 骨架。主操作位于主区，状态区使用程序化可感知区域；加载时保留骨架尺寸，避免控件位移。详情返回结果页时恢复查询条件并校验版本。

## 3. 权限可见性

| 角色 | 可见入口 | 必须隐藏/拒绝 |
| --- | --- | --- |
| 访客 | 检索、详情、门户、统计、登录 | 申请材料、内部审核备注、维护操作 |
| 登录用户 | 本人申请、申请认领、公开页面 | 他人申请、证明材料和审核内部信息 |
| 已认领学者 | 自己授权门户的维护入口 | 他人门户、共享成果本体删除 |
| 管理员 | 审核和任务工作台 | 自审操作、非职责范围的证明材料 |

## 4. 响应式和返回路径

- 桌面基准 1366×768，窄屏基准 360×800。
- 结果筛选在窄屏转为可展开面板，当前条件以可移除标签显示；不能依赖横向滚动访问主操作。
- 管理页在窄屏转为“列表 -> 详情”；审核决定固定在详情底部但不遮挡理由输入。
- 登录恢复只携带公开目标和非敏感条件；不把证明材料或私有联系方式写入 URL。
- 浏览器后退回到上一个用户任务状态，不把过期结果重新当作当前结果。
