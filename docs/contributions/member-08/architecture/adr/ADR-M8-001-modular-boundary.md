# ADR-M8-001：业务模块与异步工作进程边界

状态：Proposed；2026-11-11；供成员1/6主编的全组ADR目录选用。关联七类服务与M8-AUTH/CLAIM。

背景：课程要求采集、ETL、检索、门户认领、统计、认证和管理后台；服务职责必须明确，但当前没有获批技术栈、运行负载或独立团队运维证据。

候选决策：逻辑上保留七类服务，一期B方案以模块化业务应用承接认证和认领等交互，采集/ETL/索引工作进程异步运行。同步业务仅通过模块接口访问权威数据，不跨模块随意改表。外部请求统一做身份、权限、参数、版本和幂等检查。

替代：全部混在一个进程会增加阻塞耦合；直接拆成七个独立微服务会增加认证传播、事务和运维负担。当前没有数据证明后者收益高于代价。

后果：有利于先保证本地审核事务和课程链路；业务应用仍有共同故障域，须通过超时、资源配额及模块测试约束。后续若测得独立扩容/发布需要，再按契约拆分，不将本决策解释为永不采用微服务。

接受条件：成员3/8核对事务边界，2/7核对异步链路，5/10核对部署约束，1/6共同确认。当前未执行性能比较、云部署或代码实现。技术范围由[架构比较](../01-backend-architecture.md)给出。
