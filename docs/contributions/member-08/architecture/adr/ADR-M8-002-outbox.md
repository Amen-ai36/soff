# ADR-M8-002：数据库与索引同步采用事务Outbox候选

状态：Proposed；2026-11-11。关联M8-NFR-06及AN-Q08/09。

背景：业务数据库和ES顺序双写存在一边成功、一边失败的窗口；通知失败不能撤销已提交的认领决定。

候选决策：业务、最小审计、Outbox在一个数据库事务中保存；工作进程重试读取，按聚合ID及单调版本写公开投影。ES逐项确认后记录已处理，按至少一次重试设计，保留幂等、防倒退和受限墓碑。先不强制引入独立队列。

依据：官方Outbox模式将业务和事件意图同事务保存，并要求考虑重复与顺序；本稿据此推导B实现，不把它称为端到端恰好一次。[技术依据](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)

替代：直接双写改动少但恢复不可靠；CDC可减少轮询侵入，但需要日志、连接器及运维支持，留待1/6、5/10对照选型。

后果：可恢复与可追溯性提高，同时增加Outbox清理、积压、租约和失败项运维。权威保存成功不等于公开已发布，ES可见性另由ADR-003保护。

接受条件：核对SQL字段及幂等租约，验证逐项失败、宕机重放、重复/乱序和旧事件防复活。无系统执行证据；状态未接受。详见[一致性说明](../02-consistency-and-failure.md)。
