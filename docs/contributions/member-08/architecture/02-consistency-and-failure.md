# 数据库、ES与公开读取一致性方案

B组候选，2026-11-11。保证目标是业务事务原子、事件可重试、公开全集与total合法；不是数据库和ES分布式原子提交或已验证的实时延迟保证。

## 1 写入、Outbox和消费

数据库事务一并保存权威业务变化、最小审计和Outbox事件。审核通过还要原子更新申请、有效决定和唯一维护授权；失败整笔回滚。Outbox解决业务数据与待发送事件的双写窗口，消息仍可能重复，消费者必须幂等；这是官方模式的基本边界，[事务Outbox资料](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html)。本候选先轮询Outbox，不强制增加消息中间件；今后加队列仍保留相同消费约束。

事件使用候选字段 `event_id、aggregate_type、aggregate_id、aggregate_version、event_type、destination、payload、created_at、published_at、attempts、next_attempt_at、last_error`。destination区分索引、通知等目的地，多个目的地各自有待确认事件；payload只放公共投影或ID/版本，不带证明。工作进程按聚合ID分区/序列化处理，读取权威版本形成完整投影；逐事件租约只防重复领取，不自动保证同聚合顺序。租约字段lease_owner/lease_until/lease_token与数据稿一致，确认必须匹配当前token。已被更高完整投影版本覆盖的旧索引事件，核验后记录已覆盖结果，避免无限重试；通知事件不可直接按索引覆盖规则跳过。逐项检查ES批量结果，成功后才标记published_at，不能仅看HTTP成功。此字段只表示同步端确认，不表示该投影已公开；公开发布另看publication_generation。崩溃重放同事件不重复增加统计。

ES文档按规范ID写入，采用持久化、单调聚合版本。外部版本条件拒绝旧写入，和ES自身 `_seq_no/_primary_term` 不是同一编号体系；相同版本重试冲突须核对实际版本及内容摘要后才视作已完成。限定/撤下用带版本的受限墓碑或持续版本台账防旧事件复活，不依赖已物理删除文档的短期历史。[ES写入版本接口](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-index)、[ES并发控制](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/optimistic-concurrency-control)

## 2 公开版本栅栏：保守安全候选

候选数据库记录公开栅栏 `epoch、READY/BLOCKED、active_generation_id`，发布代保存具体不可变索引、data_version、policy_epoch和状态。撤下、改私有或其他公开资格收缩，与权威业务更新同一事务令epoch递增并BLOCKED。普通新增和非收缩元数据更新可以继续返回旧已发布代，明确其版本和时间；不能把候选保存成功说成已公开发布。

公开查询、详情和统计先读栅栏；BLOCKED、无法读取权威策略、代不存在或版本不兼容时明确失败。成功查询绑定一个具体索引代，结果、total及聚合一次取自完整合法集合，不能只删除当前页中不合法项。响应授权线性化点在最终栅栏校验：该校验与收缩事务通过同一行共享/排他锁或等价串行机制互斥，共享栅栏锁须持有到本次响应内容物化和授权决策结束，验证epoch和代仍匹配后才允许响应；不在索引构建期间持锁。已在收缩之前完成授权的在途响应无法撤销已发出的字节；收缩提交后的新授权不得使用旧代。

这是项目设计推导，不是ES自动提供的保证。代价是公开资格收缩期间**全局公开查询暂不可用**。若不能接受，需另评审完整集合级权限过滤/分区策略并重新证明total、统计和缓存边界；不能在实现中悄悄退回只过滤一页。

## 3 发布、重建与分页

1. 构建输入绑定关系数据库一致性快照，或具有边界水位的不可变导出；不能逐条读取变化中的latest并混称同版本。长快照的资源和清理影响需实测。在候选代构建白名单投影，逐项处理失败；不变索引代完成后禁止后台继续写入。
2. 对照同一权威版本的合法ID集合，核对缺失、额外、重复、受限ID、分类计数和内容摘要；只对总数相等不能证明集合相等。
3. 若发生收缩，生成已清理的新代。确认没有新epoch变化后，数据库事务更新active_generation并READY；发布失败保持BLOCKED。业务代记录中的具体索引是读取依据，不能先信别名后假称数据库同步成功。
4. ES别名可用单请求批量移除/新增切换，但须验证存在性与逐动作结果，避免部分成功；其原子能力不扩展到数据库。[别名文档](https://www.elastic.co/docs/manage-data/data-store/aliases)
5. 旧代在无合法引用后再清理，回退只允许仍符合当前公开epoch的代。旧公开权限代永不作为撤下故障时的兜底。

查询上下文候选绑定数据版本、条件摘要、排序、当前策略epoch及有效期。每次翻页重新检查当前栅栏：旧epoch或过期上下文返回409语义，当前发布不可用返回503语义；字段和错误码尚待公共批准。浅页可保留既有页码接口；深页推荐服务端游标加search_after/PIT。ES默认from/size有结果窗口限制，PIT用于稳定索引视图，不能固定当前访问权限；不能仅提高窗口就承诺百万深分页。[分页官方说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results)

## 4 故障矩阵与验收准备

| 故障点 | 权威结果及恢复 | 后续应执行的测试 |
| --- | --- | --- |
| DB事务失败 | 业务、授权、审计、Outbox均回滚 | 各写步骤故障注入，无部分授权 |
| DB提交后消费者宕机 | Outbox留存，租约到期重新领取 | 重启后无丢事件，无重复业务写 |
| ES批量部分失败 | 仅确认成功项，失败项退避/告警/人工重放 | 注入单项拒绝，不错标全批完成 |
| 重复或乱序事件 | ID+版本防倒退，重放对账 | 新版后到旧版不能复活受限记录 |
| 撤下后ES不可用 | 栅栏BLOCKED，公开读取关闭，权威编辑状态保留 | 新查询、total、统计、缓存均不泄漏 |
| 新代发布时再次撤下 | epoch变化令本次发布失效，重新清理 | 竞争发布不覆盖新栅栏 |
| PIT/上下文失效 | 保留用户条件，提示从首屏重查 | 不拼接不同数据代、不假报空集 |
| 通知或缓存失败 | 不回滚成功审核；可追溯重试/绕过缓存 | 本人查询仍读取权威终态 |

退避、最大尝试、延迟SLO、公开阻断时长和保留期需由1/6、3/8、5/10共同确定。以上是验收设计，尚未运行服务、故障注入、百万规模或性能测试。
