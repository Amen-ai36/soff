# 成员8 · 接口设计说明（第10周评审稿）

2026-11-11，版本0.1。适用B组数据库、检索与后端供稿，进入唯一构件设计报告。全部URI、字段和HTTP映射为本次设计候选；不改写已归档SRS、旧SPEC或其他成员材料。百万规范公开成果是10月27日统一分析采用的规划目标；旧一万记录属于待同步历史，不宣称数据或性能已达标。

## 1 操作边界与输入输出

| 操作组 | 输入与职责 | 输出与边界 |
| --- | --- | --- |
| 会话 | 匿名/当前会话查询，登录，退出 | 当前主体、角色、CSRF令牌；会话凭据只在HttpOnly cookie，不在正文/URL/日志回显 |
| 公开发现 | 成果/学者检索、详情、门户及四类分页 | 仅公开规范ID、来源、模拟标记、合法total及数据版本；同名不合并 |
| 认领 | `scholar_id`、本人有效材料引用、幂等键；管理员决定和预期版本 | 私有申请ID/三态/版本；只有本人或职责内管理员可读材料 |
| 维护治理 | 当前门户授权、字段白名单、预期版本 | 个人字段或展示选择的权威保存结果；共享成果字段另建治理请求 |
| 统计 | 类型/年/机构/领域范围及分析维度 | 类型分布、机构排名、领域分布、专家合作、年度热点；口径、分母、未知数、版本 |
| 采集协同 | 已批准来源配置ID、类型、版本及STOP/RETRY意图 | `202`受理及Location状态查询；任务生命周期与B组新任务策略交成员7确认 |

具体路径与Schema见[openapi.json](openapi.json)；完整操作列表与权限、错误、旧AC关联见[映射表](api-acceptance-map.csv)。公开对象不嵌入账号、申请人、证明正文、私有联系方式或证明引用。私有Claim/Evidence类型只供受控端点使用。

对象字段采用`additionalProperties:false`；未知查询参数也须由服务端拒绝。ID是不透明非空字符串，不按姓名或数字猜测身份；年与未知值区分，时间带时区。数组多选同维度OR、跨维度AND。起年大于止年、非法类型、页码和排序拒绝。`biography/interests`和纠错字段至少一项由Schema及业务校验共同约束，不允许空更新。

## 2 候选会话与资源授权

本稿评估服务端会话+HttpOnly/Secure cookie，便于即时撤销与集中核验；不是已批准JWT/OAuth选择。`GET /auth/session`在匿名时返回`authenticated=false`并建立CSRF上下文；登录前也核验Origin和绑定的`X-CSRF-Token`，登录成功轮换会话标识。写操作同样进行Origin、CSRF令牌和服务端授权校验。HttpOnly仅限制脚本访问cookie，不能独立承担CSRF防护；SameSite为补充候选策略，期限数值未冻结。退出须服务端撤销，不能只删浏览器cookie。私有/会话响应`Cache-Control:no-store`。

匿名CSRF上下文采用独立短期签名挑战cookie及服务器密钥校验，按经批准有效期配置验证，登录时销毁并轮换；不插入`app_session`。登录会话才关联非空account_id，其CSRF摘要按会话绑定。签名密钥不入仓库，具体算法、轮换和期限需认证专项确认。

写入顺序为“会话有效→操作资格→对象授权→白名单/版本→事务提交”；角色、申请人和owner均从权威数据取得。客户端伪造`role/applicant_id`等字段拒绝；管理员审核还须职责范围及非本人。无会话401，操作拒绝403；私有对象存在但无读取资格与不存在同为404，避免泄露存在性。公开端点不要求登录。

`POST /private/evidence`为候选multipart上传入口，返回202及Location；轮询受控元数据，只有valid=true才可引用。处理状态字符串尚未冻结；类型、字节数、归属与内容安全须由后台校验，不能相信客户端Content-Type。格式/大小、保留期来自经批准配置，本稿不编造阈值。私有临时对象与DB登记的部分失败须可追溯清理，幂等摘要包含文件内容。此入口是设计稿，不宣称已运行；最小充分身份证明仍待1/6及教师确认。证明内容由`/private/evidence/...`受控下载，读取时重查资格、有效性并默认附件，不返回公开OBS链接。

## 3 查询、合法全集与跨页版本

沿用SPEC-M8-SEARCH：NFKC及空白/拉丁大小写规范化；多词AND，中文连续子串；完全相等题名优先，再按不同token的题名×5、关键词×3、摘要×1；同分年降序、空年末尾、规范ID字典序。学者使用姓名精确优先及命中数/ID顺序。不能把ES默认BM25分数当同一业务语义。

本次候选细化要求原始及归一化后q/name均≤200字符；NFKC可能扩张，超限400。这使数据稿`title_exact`只保存归一化后≤200字符仍不遗漏合法完整q的完全相等匹配；该细化不是既有公共批准。学者来自同代不可变DB只读导出，不假设成果ES mapping已包含学者姓名。

首请求省略`query_context`以建立不透明上下文，它绑定数据版本/索引代、规范条件、排序及当前公开策略epoch。后续页必须携带上下文；缺失400，条件不一致、过期或旧epoch409 `QUERY_CONTEXT_EXPIRED`，前端保留已提交条件并从首页重查。ES PIT只固定数据视图，不能证明仍有权公开。

按架构稿的DB公开gate，每次查询及翻页验证当前READY及epoch；公开资格收缩会使gate BLOCKED，不能安全核验则503 `PROJECTION_NOT_READY`或`DEPENDENCY_UNAVAILABLE`。完整不变投影代对账并原子发布后才恢复，不以每页删私有项维持错误total。返回前的共享栅栏校验是授权线性化点，撤下事务与之串行。策略失效不能静默回退旧缓存，也不能把旧数据代拼成新结果。

`total`是完整合法集合大小；空集200、items=[]且total=0，越界页仍保留total；故障是错误。门户四类均有首屏、total和上下文，四类子页的data_version必须与门户外层一致，不能拼接不同代；`/portal/works?category=...`分开翻页，禁止一次无界返回全部成果。合作网络边数按候选edge_limit分页，游标绑定同一上下文；单边支撑集合过大须明确资源限制或另议异步导出，不静默截断依据。规模和游标成本仍需真实实现基准。

与数据稿映射：biography对应scholar_portal.intro，interests对应其JSONB数组；Work.doi对应achievement.doi及公开ES的doi keyword，冲突进入治理而不全局静默覆盖；治理version对应governance_request.version。学者field_ids来自有依据的scholar_field同代导出，不从个人兴趣猜测。服务生成ID≤64字符以匹配候选DDL，源站原ID另存来源记录。

## 4 幂等、审核及保存结果

保留正文`request_key`，其键空间为当前账号+操作+键，服务端保存规范参数摘要与结果。同键同参且仍有读取资格时返回原结果，同键异参409。业务写入、唯一约束、审计和幂等结果同一原子边界；并发未完成请求应明确“处理中”冲突或等待既有结果，不能再创建一条。期限由公共设计确定，过期仍靠待审唯一、有效授权唯一和终态不可改保证安全。

申请创建PENDING不授予维护权；同账号同门户最多一个PENDING。审核提交重查版本、PENDING、职责回避与通过时门户空闲，原子写决定/状态/通过时授权/审计/幂等结果。两申请争门户落败者可仍待审，不自动伪造驳回；同申请并发失败不把他人成功终态回退。APPROVED/REJECTED对单申请为终态；驳回补充后以新ID关联本人同目标历史。补充、撤回、申诉仍属候选扩展。

门户允许字段或展示关联修改成功后返回`saved=true`及`projection_status`；投影等待发布不会撤销已保存业务结果。公共字段纠错只创建治理请求，不回报公共字段已更改；移除个人展示不删全局成果或改变合作计数。网络回包丢失属于结果未知，应同键重试或授权查询，不能生成新键盲目重做；通知失败也不回滚已成功决定。

## 5 异步任务及联合评审

采集创建、停止及重试用202和Location表达受理，客户端查询任务/命令进度；受理不等于已执行完成。只接收已审批来源配置ID，不收任意URL、源站凭据或客户端提升权限字段。STOP/RETRY是意图，`state/command_state`为未冻结数据侧字符串；不把A/B生命周期强行改成同一枚举。重试生成新任务、停止确认点、失败摘要和发布水位交成员7共同细化。

共用错误结构为code/message/trace_id及可选field_errors；400参数、401会话、403操作/CSRF、404不可访问、409冲突/版本、429限流、503依赖/发布不可用。追踪标识须真实关联服务端记录，不能虚构。HTTP状态表示请求处理结果，业务三态、前端加载和投影状态分别表达。
