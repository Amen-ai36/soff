# 4 检索处理与分页一致性

用例UC08-01；对应M8-SEARCH-01/02、M8-NFR-03/04；验收AC08-01～06、20。输入是已提交条件、排序、分页及可选版本；输出为公开结果、合法全集total、版本与更新时间。姓名检索保持同名实体各自ID。

| 阶段 | 分析职责及异常 |
| --- | --- |
| 输入校验 | 关键词做NFKC、去首尾及合并空白、拉丁不区分大小写；参数与排序白名单、起止年和页码校验；非法输入返回可定位错误。 |
| 候选范围 | 先取得可核验公开范围与版本，再对规范记录过滤；不同维度AND、同维度OR；时间过滤排除未知年份。 |
| 排序分页 | 完全相等题名优先，其后不同token命中题名×5+关键词×3+摘要×1；同分年份降序、空年末尾、ID字典序。先过滤再排序最后分页。 |
| 合法总数 | total须来自完整合法集合；不能查出一页后删掉私有项却保留原total。权限无法核验时明确失败。 |
| 结果反馈 | 真实空集返回total=0；越界页items为空但total不变；依赖失败不当空集；同一固定版本内分页不重不漏。 |
| 更新与恢复 | 公开策略变化或旧版本不可复现时，反馈版本失效并保留已提交条件，重新从首屏查询；跨版本协议待设计。 |

规则走查：原合成夹具q=graph应返回W01、W02、W03，total=3；尽管加权分W02=8大于W01=5，完全相等优先使W01第一。W05非公开排除，W04不匹配。该手算用于模型解释，不能证明后端检索或规模达标。

与页面衔接：成员9在请求处提供已生效条件，响应处接收成功空集/错误/版本变化。即时筛选或显式应用均不得让旧响应覆盖新条件；筛选触发方式由成员1/6与4/9确定。

# 5 提交、审核与不确定结果恢复

| 环节 | 正常路径 | 失败/冲突与恢复 |
| --- | --- | --- |
| 提交前置 | 有效会话；本人有效材料；目标存在且未占用。 | 申请人取自服务端会话；他人材料、伪造身份和不合法输入拒绝。 |
| 幂等与创建 | 同主体同操作同键同参数返回保存结果；新请求原子写PENDING及审计。 | 同键参数不同冲突；幂等结果与申请不能一成一败；重放仍验证当前读取资格。 |
| 审核前置 | 有审核职责、非本人；理由、预期版本有效。 | 会话/角色失效、自审、旧版本、已终态新操作拒绝；不改变已有权威结果。 |
| 审核通过 | 再次核验材料、PENDING、版本与门户空闲；决定、授权及审计原子提交。 | 两申请争门户只一个授权；落败请求不自动驳回。并发同申请时不覆盖已提交终态。 |
| 审核驳回 | 写REJECTED及理由、决定和审计，不授权。 | 理由缺失拒绝；补充重提创建新ID，原申请历史不回退。 |
| 返回与通知 | 返回权威保存状态；通知在成功提交后执行。 | 回包丢失时同键重试或授权查询恢复；通知失败不回滚决定。可靠通知恢复留待架构设计。 |

用例映射：提交UC08-03、审核UC08-04，关联AC08-07～13、21、25。图采用分析控制对象表达协调职责；没有确定事务数据库、JWT、队列或公共URL。

原子失败的范围是“本次操作没有部分写入”，不代表把全局状态重置为PENDING。另一个请求已成功时应读取其权威终态。管理员仅能在职责范围访问证明；未知目标与无权目标采用不泄露存在性的读取反馈。

# 6 授权维护、统计与数据侧衔接

| 路径 | 分析规则 | 对应验收 |
| --- | --- | --- |
| 门户读取 | 可直接按规范学者/成果ID读取公开投影；四类栏目保留，缺失为空或未知；无权/非公开不泄露私有信息。 | AC08-21、26 |
| 允许字段维护 | 有效会话→当前门户授权→字段白名单→版本校验→原子保存及审计。版本冲突保留输入，不静默覆盖。 | AC08-07/08/22/23/25 |
| 共享元数据纠错 | DOI、题名、成果归属等公共字段进入治理请求，不假报公共字段已修改；来源更新冲突保留人工修改。 | AC08-22/23 |
| 个人展示关联 | 调整或隐藏本人展示只影响门户选择；不删全局成果、来源和合作网络依据。 | AC08-22/24 |
| 统计查询 | 同一公开快照按规范成果ID去重，披露分母、未知数、口径、时间和版本；故障不能伪装全零。 | AC08-14～19、24 |

统计解释：机构来自成果发生时依据，同机构内每成果计1；不同机构分别计数，跨机构合计可超过总量。领域可交叉，占比之和可超过100%。合作边基于同一成果不同学者ID的无序对，权重为共享不同成果数；未知作者不编造关系。年度热点按当年公开成果为分母，空分母比例为null。

数据侧交接：成员2/7的处理时序在“规范成果、来源映射、参与/机构/领域关系、发布版本”处连接本包；未发布或隔离来源不计公开总量。成员2/7仍需提供实际清洗/入库/更新图、停止恢复与权威版本形成机制。

规模边界：现有公共SRS和B组规范为不少于10,000条，A组成员1分析提出1,000,000条新目标。本包设计计数语义可复用，但不替团队选择新验收门槛，也不声称已有数据规模或延迟实测。
