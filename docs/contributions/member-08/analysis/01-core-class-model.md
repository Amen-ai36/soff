# 1 业务边界与对象职责

分析回答“哪些对象承担业务事实、谁有资格改变状态、结果如何一致”，不在本阶段决定数据库表、ES映射、认证框架或部署服务。图中的英文别名与属性只是分析标识，不发布公共接口字段。

| 对象 | 语义属性与方法职责 | 关键约束 |
| --- | --- | --- |
| Scholar 学者 | 规范标识、姓名与别名；提供公开档案。 | 姓名不唯一；可没有账号、门户或已确认成果。 |
| Achievement 成果 | 规范标识、类型、题名、年份、可见性和版本；提供公开投影。 | 论文/专利/项目/获奖四类；未知年份不补当前年。 |
| Participation 参与关系 | 参与角色、顺序、依据；关联一个学者与一个成果。 | 不把项目参与者统称论文作者；来源不足保持未知。 |
| Institution / WorkInstitution | 机构身份与成果发生时机构依据；解释归属。 | 机构按ID归一；不能由学者现任机构倒推历史成果机构。 |
| Field / SourceRecord | 领域分类体系；来源键、版本和依据；追溯规范映射。 | 多领域可交叉；来源记录数不等于成果数。 |
| ScholarPortal / DisplayLink | 门户公开配置、四类展示及个人选择。 | 隐藏个人展示不删除公共成果或改变合作统计。 |

四类成果采用类型判别表达共同业务职责；类型专属属性在后续细化。继承、组合或独立存储由设计阶段评估，不能仅凭本图推导四张表。

WorkInstitution、Participation、PortalDisplayLink 为分析关联对象，不是已批准新增实体。任职时间、角色、顺序等只有在来源可证实时填写；保留未知与不适用的区别。

# 2 关系、多重性与公开范围

| 关系 | 本包分析表达 | 理由与限制 |
| --- | --- | --- |
| 学者—参与关系—成果 | 每个参与关系各连一个学者、一个成果；两端可有0..*关系。 | 0允许来源尚未确认作者，不等于已证实无人参与。 |
| 成果—机构 / 领域 | 多对多；机构通过有依据的关联表达。 | 机构内按成果去重；跨机构/领域合计可能超过总成果。 |
| 来源—规范成果 | 每条单成果来源记录当前映射0..1成果；成果可对应多来源。 | 未映射、隔离来源不计公开成果；可公开成果至少一项有效来源依据。 |
| 学者—门户 | 当前候选为学者0..1门户，门户恰连一个学者。 | 沿用成员6结构；一学者多门户与即时生成策略须共同确认。 |
| 门户—展示选择—参与关系 | 门户与参与关系各可有多条选择；每条选择连接各一个。 | 同一门户/参与关系同时至多一个当前有效选择；两端学者必须相同。默认展示可派生，不要求全部落库。 |

- 可见性不变量 V1：公开结果、total和统计全集都受当前权威策略约束；撤下记录不能因旧索引继续暴露。
- 计数不变量 V2：一个规范成果ID只计一次，来源增加、参与人增加和展示选择变化不增加成果总量。
- 数据边界 V3：私有证明、账号凭据及私有联系方式不进入公开门户、检索投影、统计或审计正文。
- 版本不变量 V4：同一响应的数据范围、结果、计数和口径对应同一可核验版本；失败和真实空结果分开。

来源记录到规范成果的0..1关系以“来源已拆分为单成果记录”为前提；复合原始载荷拆分和历史观察由成员2/7确认。本包不将来源历史覆盖成一条最新记录。

# 3 认领模型与状态授权不变量

| 对象 | 职责 | 关系与约束 |
| --- | --- | --- |
| Account | 当前会话主体与操作资格。 | 账号≠学者；管理员是资格，不强制账号继承层级。 |
| ClaimRequest | 申请人、目标、状态、版本、前序引用。 | 同账号同门户最多一条PENDING；不同账号可申请同一空闲门户。 |
| EvidenceReference | 私有材料归属及有效引用。 | 提交时至少一个本人可用引用；材料格式、大小与保留期尚未批准。 |
| ReviewDecision | 有效业务决定、理由及版本依据。 | 每申请最多一次有效决定；审核人不能是申请人。 |
| PortalGrant | 维护权限与有效性、授权来源。 | 同门户同时最多一个有效授权；历史多条不表示允许多人代管。 |
| AuditRecord | 操作者、对象、动作、结果、版本和时间。 | 成功创建/审核/维护有可追溯轨迹；失败尝试不冒充有效决定。 |

| 业务状态 | 维护权 | 允许的后续 |
| --- | --- | --- |
| PENDING 待审 | 不授予维护权。 | 有资格管理员通过或有理由驳回；冲突不擅自生成新终态。 |
| APPROVED 已通过 | 通过时创建相应授权。 | 同申请为终态；幂等重放返回原结果，不能再次改判。 |
| REJECTED 已驳回 | 不新增授权。 | 补充后创建新申请ID并关联历史，旧申请仍REJECTED。 |

不变量 C1：审核决定、申请终态、通过时授权、幂等结果和最小审计共同成功或共同失败。C2：一申请最多一次有效决定；一门户同时最多一有效授权。C3：复核权限、版本和占用须在提交边界成立，前端预检查不能替代。

“需补充材料”“已撤回”仍为候选扩展，不加入本包三态枚举。加载、超时、上传失败是前端状态，也不是申请业务状态。
