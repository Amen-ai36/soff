# SPEC-M8-CLAIM：门户、认领审核与维护 v0.1

关联 M8-PORTAL-01/02、M8-CLAIM-01/02、M8-MAINT-01；用例 UC08-02～05。状态：待确认提案。

## 目标、输入与输出

公开门户按学者 ID 展示基本信息及四类成果；申请输入 scholar_id、evidence_refs、request_key；审核输入决定、原因、预期版本；输出申请编号、状态与版本。申请者身份和审核者身份来自服务端会话。不会实现外部身份证明服务、申诉转让或资料抓取。

## 正常流程及规则

1. 创建前验证用户会话、材料归属、非空引用、目标存在且未被认领。同一 user_id+scholar_id 最多一个 PENDING 申请；不同用户可排队申请同一未认领门户，审批时争用同一所有权约束。
2. 创建后 PENDING，只授予查本人申请权。材料无法验证或缺失时拒绝创建；审核中证据不足则有理由 REJECTED，不把姓名匹配当身份验证。
3. 审核仅管理员、禁止自审，expected_version 必须与当前一致。通过/驳回均写理由，驳回理由不得为空。
4. 通过时再次核验门户无所有者，以门户唯一 owner 约束与版本条件，在一个原子提交中写 APPROVED、授权关系、审核审计。任何一步失败均不留下部分成功。
5. 两个申请并发通过只能一个成功；另一个返回冲突并保持 PENDING，管理员依据已占用事实另行有理由驳回。不得自动伪造审核决定。两个管理员处理同一申请也只能一个终态提交；失败者返回冲突并读取最新状态，不得把另一请求已提交的终态改回 PENDING。
6. APPROVED/REJECTED 为当前申请终态，不能再审批。幂等重放相同操作返回已保存结果；不同操作或不同参数返回冲突。
7. REJECTED 后重提创建新 ID 并关联前序申请，保留历史，不从 REJECTED 直接回 PENDING。
8. 门户四类列表都存在；未认领仍可公开浏览。个人说明可在授权内编辑；公共成果元数据变更进入治理申请，删除个人展示关联不得全局删除成果或抹去来源。

## 异常、边界和数据保护

无权查询申请统一不透露存在性；他人 evidence_ref 拒绝；会话过期拒绝；材料链接失效由管理员记录理由后驳回或保留待审，不能默认通过。数据写入失败回滚，消息通知失败仅标记通知失败，申请状态仍以查询为准。证明正文、账号凭据及私有联系方式不出现在公开门户和审计正文中。

审核证据标准建议“机构邮箱/公开官方主页/可交叉核验成果关系”的组合，具体哪种足够由组长与教师确认；不宣称已完成防冒领效果验证。

## 验收

AC08-07～13、AC08-21～23、AC08-25；活动图和状态图必须与本规范一致。授权后的成果编辑应验证本人/他人、共享字段、版本冲突与采集覆盖四类边界。人工核验标准未冻结前只能做模拟审核测试，不得称真实身份核验通过。
