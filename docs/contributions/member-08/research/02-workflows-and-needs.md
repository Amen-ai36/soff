# 核心业务流程与科研人员、管理员诉求

依据：任务书正文第 1、3～4 页；统一范围 R01、R06～R10、R14。下述“诉求”是角色分析形成的待验证假设，没有虚构受访人数、满意度或引语。

## 1. 角色与目标

| 角色 | 典型任务与困扰假设 | 需要的系统能力 | 验证问题 |
| --- | --- | --- | --- |
| 科研人员（未认领） | 找到自己的档案，排除同名者，了解申请进度 | 姓名+机构+领域上下文，材料提交与状态查询 | 常见同名误归属有哪些？可提供何种非敏感证明？ |
| 科研人员（已认领） | 四类成果集中展示，修正错误关联，知道更新是否生效 | 分类型成果列表、维护授权、来源与更新追踪 | 哪些字段允许自改？合作成果变更应由谁确认？ |
| 审核管理员 | 快速定位证据与冲突，说明通过/驳回原因 | 审核队列、材料受控访问、冲突提示、审计 | 哪种证据足够？同名、重名机构、异议如何处理？ |
| 数据管理员 | 发现重复/缺失、判断更新对检索和排名的影响 | 数据质量状态、来源、更新批次与异常追踪 | 当前怎样发现错误？哪些修复需交给 ETL 岗位？ |
| 普通用户（交接范围） | 找成果、专家及领域信息 | 无登录公开检索与详情，统计口径说明 | 检索字段、过滤习惯由成员 4、9 补充验证 |

管理员两种工作视角暂不等于新增两种正式角色；是否细分权限由组长确认。

## 2. 流程 F01：检索—详情—门户

用户选择成果或学者 → 输入关键词与过滤条件 → 系统校验条件 → 在可公开的数据范围检索 → 稳定排序和分页 → 用户查看成果详情、来源及作者 → 进入学者门户并按四类成果浏览。

分支：空结果返回空列表并保留条件；非法区间或分页参数提示纠正；学者同名展示机构和领域，不自动合并；来源失效仍显示已获授权的元数据和状态；检索服务不可用明确报错，不能伪装为空结果。

价值：从一个查询可追溯到成果和作者，跨页面 ID 一致。风险：索引滞后，因此更新状态需可见，失效/撤下记录不能继续公开泄露。

## 3. 流程 F02：申请—核验—审核—授权

已登录用户选定未认领学者 → 阅读材料用途 → 提交证明引用 → 系统检查完整性、账号状态、重复申请和门户占用 → 申请进入待审核 → 管理员查看证据 → 通过或填写理由驳回 → 用户查看结果。

通过时再次检查门户是否已被他人占有，在同一原子操作中写入审核结论与账号—学者授权；冲突或持久化失败不允许出现“已通过但无权限”。驳回后可补充材料重新提交新申请，历史申请保留。自审应禁止；若只有一个管理员则该申请等待另一名合格审核者，不能自动放行。

防冒领：姓名匹配只能定位候选；机构邮箱、官方主页或成果关联证据可供组合核验，但不能单凭自填资料通过。团队尚需确定认可的材料类型和申诉流程。

## 4. 流程 F03：已认领门户的成果维护

已授权学者打开自己的门户 → 新增/补充本人成果或提交关联纠错 → 校验所有权、版本、必填字段和重复候选 → 保存可直接编辑的本人字段，或形成公共元数据变更请求 → 记录操作者和来源 → 更新检索/统计可见版本。

建议允许本人编辑个人介绍、展示设置与提交成果补录；题名、作者列表等共享元数据修改建议交管理员审查。删除本人的展示关联不等于删除成果本体。外部采集更新与人工修改冲突应可见并保留历史，不静默覆盖。

## 5. 流程 F04：统计与分析

用户选时间、机构、领域、类型 → 系统校验并绑定一个数据快照 → 按去重后的成果集合计算 → 返回机构排名、类型/领域分布、基础合作关系、热点 → 展示分母、未知类、计数方式和更新时间。

多机构成果采用机构内去重、机构间各计一次的建议口径，因此机构计数之和可能大于总成果量；多领域也需说明不能简单相加。热点先做频次时序，不把基础趋势标成预测创新。

## 6. 交接与范围

成员 7：入库成果 ID、归一化作者/机构、重复候选和批次追溯；成员 9：检索条件、认领表单、状态反馈、错误提示；成员 10：权限、并发审核、统计去重和异常用例；成员 3：共同校对字段和流程；成员 1、6：冻结规则和验收。

本阶段不确定数据库产品、ES 映射、部署拓扑、缓存或完整 OpenAPI。这些属于后续设计阶段。接口需求先明确语义，不抢先冻结公共契约。
