# 模型 B："AI 生成 → 修正"案例（B 组）

方案第 6 节要求至少 3 个"AI 生成 → 人工修正"案例，两组均需贡献。以下 6 个案例来自 B-M9-001，**均为 AI 在执行测试或检查截图后自行发现并修正**，不是人工修正。如实标注来源，成员 9 人工审查后可补充真正由人发现的问题。

## B-M9-C01 问卷数据造假（前期阶段遗留，影响最大）

- **发现方式**：AI 在架构阶段核对材料时，发现成员 9 的需求建模、分析文档引用 37 个证据编号 `B-E01`～`B-E37` 和"50 份问卷"，但问卷分析文件中没有定义任何证据编号；问卷 PDF 实际为 35/30/23 人，且与"50 份"中的身份构成不符。
- **原因**：前期阶段 AI 在无法读清问卷图片时生成了数字，未标明是推测。
- **修正**：新增 `docs/contributions/member-09/CORRECTION-questionnaire-data.md`，在受影响文件顶部加更正提示；架构、构件设计、实现阶段只引用真实问卷 `06-questionnaire-results.md`；首页设计由"三入口并列"改为"检索为主"。
- **教训**：AI 生成的统计数字必须能追溯到原始文件；读不清原始材料时应停下来请使用者提供，而不是生成。
- 说明：此案例属于文档而非核心代码，列在这里是因为它直接改变了前端设计依据。

## B-M9-C02 测试中的文件路径在 Vitest 下无法解析

- **生成内容**：`architecture.test.ts`、`misc.test.ts`、`search.test.ts` 用 `new URL('..', import.meta.url)` 定位文件。
- **问题**：`npm test` 报 `TypeError: The URL must be of scheme file`（Vitest 转换后的 `import.meta.url` 不是 `file:` 协议）。
- **修正**：改为 `resolve(process.cwd(), 'src/...')`，并注明测试由 npm 脚本在 `frontend/` 下运行。

## B-M9-C03 测试预期数字写错

- **生成内容**：门户页测试断言 `科研项目（2）`。
- **问题**：合成数据中学者 A03 只有 1 个科研项目（W03）；测试失败。是测试写错，不是实现错。
- **修正**：断言改为 `全部（3）` 与 `科研项目（1）`。没有通过放宽断言让测试通过。

## B-M9-C04 窄屏截图与布局问题

- **发现方式**：检查 390px 截图。
- **问题 1**：Edge 无头模式最小窗口 504px，传入 390 时页面按 504 渲染后被裁切，截图看起来像布局溢出。改用 DevTools 协议设置设备视口后重截。
- **问题 2**：复选框被全局 `input { min-height: 40px }` 拉高，与文字错位；窄屏下筛选面板过长，结果被推到屏幕外。
- **修正**：复选框单独设定尺寸并与文字同行；窄屏时筛选项横排。曾考虑用 CSS `order` 把结果调到筛选前，但这会让视觉顺序与键盘顺序不一致（违反 UI9-NFR-09），因此放弃。

## B-M9-C05 统计页占比条与同名学者

- **发现方式**：检查统计页截图。
- **问题**：占比条所在列宽度由内容决定，几乎看不见；合作关系表出现"示例学者甲—示例学者甲"，同名学者无法区分。
- **修正**：图示列固定宽度；统计页与合作路径页的学者名后附学者编号（IA9-RULE-08）。

## B-M9-C06 类型检查与提示文案

- `WorkSearchView.test.ts` 访问 `element.form` 不通过 `vue-tsc`，改为 `closest('form')`。
- 审核成功提示拼成"已已通过"，改为"审核结果：已通过"。
- `AdminReviewView.vue` 模板中循环变量名 `ref` 与 Vue 的 `ref` 属性名易混淆，改为 `evidence`。
