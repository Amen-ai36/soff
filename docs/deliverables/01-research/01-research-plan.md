# 学术成果分享平台统一需求调研方案

版本：0.1。适用阶段：第2～6周。依据：课程任务书、仓库分工、成员1和成员6贡献包。状态：计划文本已汇编，实际调研与人工复核待执行。

## 1. 背景与目的

平台面向科研从业人员，以论文、专利、科研项目、获奖等成果为核心，支持领域分类、成果与人员检索、学者门户、认领审核、成果维护和统计分析。调研要把背景需求转换为有依据的业务边界，验证数据路线，识别可行性风险，并为后续 SRS 和设计提供输入。

## 2. 目标与判定依据

| 编号 | 目标 | 需要形成的结果 |
| --- | --- | --- |
| G1 | 确认普通用户、科研人员、管理员场景 | 各角色的任务、困难、需求、证据与局限 |
| G2 | 调查四类成果的数据获取路线 | 四类来源调查表、样例或失败记录、许可出处和备用路线 |
| G3 | 明确业务规则 | 认领防冒领、成果编辑、去重消歧、更新与异常处理问题清单 |
| G4 | 比较领域分类方案 | 候选体系、跨源映射示例、多标签和未知类别处理建议 |
| G5 | 分析同类平台 | 使用统一维度的操作证据、比较结果和借鉴意见 |
| G6 | 明确范围与优先级 | 对应课程要求的范围表、创新候选、后期业务和未决问题 |

## 3. 对象与方法

| 对象/主题 | 方法与问题 | 输出责任 |
| --- | --- | --- |
| 普通用户 | 最近一次检索任务、筛选习惯、结果判断、同名区分和详情需求 | 成员4、9主责，成员3、8补充 |
| 科研人员 | 查找本人门户、认领证明、错误关联、多人成果编辑和审核反馈 | 成员3、8主责，成员4、9协作 |
| 管理员 | 采集管理、失败重试、停止、审核依据、质量检查与追溯 | 成员3、8主责，成员2、7协作 |
| 数据源与分类 | 官方资料调查、小样本获取、字段映射、质量和更新机制核查 | 成员2、7主责，成员3、8协作 |
| 同类平台 | 对可访问平台进行相同任务的操作比较，保留日期及观察证据 | 成员3、8 |

访谈建议先接触三类角色各1～2名对象，用于探索场景，不作统计代表性推断；人数并非课程硬性指标。无法接触真实角色时记录对象的实际身份或改为资料分析。提纲、匿名原始记录和分析分开保存，不将模拟回答作为真实访谈。

数据源调查记录来源名称、官方链接、日期、成果类型、许可出处、访问方式、鉴权/限流、字段样例、标识符、作者机构关系、更新方式、质量问题、验证结果和备用方案。四类成果逐类覆盖。OpenAlex、DBLP 在此仅为任务书提出的候选来源，其当前可用性尚待相关岗位实测。

竞品建议选取2～3个可访问平台，比较检索过滤、门户、成果类型、认领维护、统计和来源追溯。不可观察的能力标注“未验证”，不凭宣传判断实际效果。

## 4. 执行与证据规则

先研读任务书并建立需求映射，再并行开展数据、用户与竞品调查，最后比较范围和优先级。方案A补充来源追溯与主链路验证思路，方案B补充角色探索和分类可行性检查，两者采用同一证据标准。

每条证据使用 `RS-主题-序号`，记录采集人、日期、来源、方法、原始观察、结论、关联目标和局限。区分“课程要求”“已验证事实”“证据推断”“待验证假设”。调研计划、模板和文案不计为已执行活动；本阶段不记录非核心代码 AI 日志。
