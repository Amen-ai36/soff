# 统一构件设计目录与收件矩阵

| 交付物 | 必须回答 | 负责人 | 成员6收件检查 |
| --- | --- | --- | --- |
| 数据库设计说明书/模型 | E-R、核心表、约束、迁移、事务边界 | 3/8 | 与对象语义、审核/审计、版本发布一致 |
| 接口设计/OpenAPI | REST、分页、错误、鉴权、异步任务接口 | 3/8 | 与 SRS/SPEC、权限和版本规则一致 |
| 采集与增量算法 | 来源适配、限速、检查点、重试、去重消歧 | 2/7 | 合规、幂等、可追溯，不能虚构指标 |
| 检索排序与统计 | 字段映射、排序、公开过滤、统计分母 | 3/8 | full-set过滤、total与聚合不泄漏 |
| UI/前后端构件 | 页面组件、状态、错误反馈、接口映射 | 4/9 | 无权、空数据、冲突、超时可解释 |
| 部署/测试/证据 | 组件部署、配置、安全、恢复、实测 | 5/10 | 必须有真实环境与命令证据 |
| 统一构件设计稿 | 目录、版本、差异、未决项、引用 | 1/6 | 只保留一套正式交付物，附 A/B 差异 |

## 建议正式目录

1. 范围、术语和约束；2. 构件分解与依赖；3. 数据库与索引；4. API/OpenAPI；5. 采集、清洗、消歧与增量；6. 检索排序与统计；7. UI组件和交互状态；8. 部署、安全、可观测与恢复；9. 设计取舍与 A/B 差异；10. 验收追踪、未决项和变更记录。

## 收件规则

每份稿件须附作者、日期、基线 commit/模型版本、输入 SPEC、未决项和验证证据。成员6只记录“已收到/待复核/退回修改”，不把提交行为写成通过结论。
